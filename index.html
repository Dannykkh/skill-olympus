하네스와 루프 엔지니어링

Act → Observe → Verify

에이전트는 프롬프트 한 번으로 안 끝납니다 — 실행하고, 관찰하고, 검증하는 루프로 동작합니다. Skill Olympus는 처음부터 그렇게 설계됐습니다.

기반

하네스Harness

제우스가 기반입니다. 하나의 비대화형 요청을 살려두고, 분해하고, 구현하고, 점검하고, 배포하고, 테스트하고, 보고까지 — 사용자에게 "다음 단계"를 되돌려주지 않습니다.

운영 모델

루프Loop

크로노스가 그 위의 운영 모델입니다. 실제 테스트를 돌리는 검증 게이트(크로노스), 통과할 때까지 고치는 미노스, AC를 대조하는 아르고스, GO/NO-GO를 내리는 클리오 — v4.7.0부터 이 루프들은 네이티브 /goal stop gate 위에서 동작합니다.

하나의 파이프라인

Interview → Build → Audit → Ship
01 — 설계
젭마인이 묻습니다

이해관계자 인터뷰와 도메인 분석으로 섹션 단위 구현 계획을 만듭니다. 코드보다 질문이 먼저입니다.

02 — 구현
포세이돈이 팀을 부립니다

섹션 의존성을 분석해 웨이브로 묶고, 에이전트 팀이 병렬로 구현합니다.

03 — 감리
아르고스가 대조합니다

spec, API 명세, QA 시나리오, 흐름도 — 설계 산출물 대비 구현을 항목별로 검증합니다.

04 — QA
미노스가 심판합니다

QA 시나리오에서 Playwright 테스트를 생성하고, 통과할 때까지 수정 루프를 돕니다.

05 — 마감
클리오가 기록합니다

GO/NO-GO 최종 점검과 함께 PRD, 기술 문서, 매뉴얼을 일괄 생성합니다.

또는, 전부 한 번에

다섯 단계를 하나씩 실행할 수도 있고, 제우스에게 한 줄만 설명하면 질문 없이 순서대로 완주합니다.
