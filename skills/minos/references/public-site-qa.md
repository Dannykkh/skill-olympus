# 공개 사이트 QA — 방문 행동과 실제 결과

공개 사이트의 페이지·CTA·문의/예약·브랜드/검색 화면을 검사할 때만 적용합니다. 기존 Step 1의
시나리오와 Step 4~7의 실행·수리·보고를 사용합니다. CI 감사 모드에는 적용하지 않습니다.

## 입력과 검증 범위

- spec·섹션 AC·QA와 최신 Experience Contract의 `Public Site Delivery`·CTA·상태·콘텐츠 보존
  조건을 읽습니다. 계약이 없으면 현재 요청·소스·실제 인터랙션에서 검증 가능한 기대 동작만 정하고
  사업 사실·가격·검색 수요·필수 동의 요건을 만들어내지 않습니다.
- 대상 버전·URL/환경·뷰포트·테마·확인 시각을 결과에 연결합니다. 같은 버전·조건의 유효한 기존
  증거는 재사용하며 변경·실패·미해결 의심이 있는 범위만 다시 확인합니다.
- `--ui-only`, `--api-only`, 읽기 전용, 수정 파일·Healer 상한은 유지합니다. 운영 문의 발송·예약·
  결제 같은 외부 효과는 허용된 테스트 환경·sandbox·mock으로 검증하고 그 범위를 명시합니다.
  실제 수신·처리를 관찰하지 못했으면 `NOT RUN`/`UNVERIFIED`로 남기며 성공을 추정하지 않습니다.

## 기존 시나리오에 보충할 사례

| 대상 | 실제로 확인할 결과 |
|---|---|
| 페이지·CTA | 계약의 페이지/앵커/다운로드/외부 URL/전화/메일 대상과 일치하고 모바일·키보드에서도 실행 가능 |
| 폼·주요 전환 | 유효 입력의 결과, 필수/잘못된 입력의 거부, 중복 제출·실패·재시도와 피드백. 약속한 접수·저장·외부 처리 각각의 증거 |
| 오류와 부수 효과 | 거부/실패 시 성공 표시가 없고 데이터·중복 요청·외부 효과가 계약을 지킴. 접근 가능한 API는 기존 직접 호출 검증과 연결 |
| 콘텐츠·신뢰 | 실제 렌더의 가격/조건·주요 문구·근거·소개와 승인된 사실의 일치. 샘플·미검증 후기/수치가 운영 사실로 노출되지 않음 |
| 링크·반응형 | 공개 페이지·내비·중요 외부 링크·방침 링크의 목적지/응답, 모바일 가림·넘침·클릭/포커스 방해와 상태 표시 |
| 접근성·모션 | 입력 레이블·오류 연결·포커스·키보드, reduced-motion에서 핵심 정보·행동 보존 |
| 성능 | 요청된 예산에 대해 실제 로드 자산·폰트·페이지를 가용 도구로 측정. 측정 불가·환경 차이는 명시 |
| 검색·개인정보 UI | 요청 범위의 실제 title/헤딩/alt/공개 링크, 정의된 동의·설정·철회 흐름과 방침 노출. 전문 감사의 결론과 실행 검증을 구분 |

모든 링크를 무제한 크롤링하지 않고 요청·계약의 페이지와 주요 목적지를 대상으로 합니다.
전화/메일 링크 형식 확인을 통화·메일 전달 성공으로, mock 접수를 운영 시스템 접수로,
성공 토스트를 저장 완료로 세지 않습니다. 소개/후기/블로그·쿠키 배너가 없는 것 자체를 실패로
판정하지 않고 확인된 요구와 실제 개인정보 처리·전문 검토 결과에 따릅니다.

## 결과와 인계

기존 QA ID·AC별로 실행 경로·관측값·저장/상태/부수 효과·증거 위치와 미실행 이유를 남깁니다.
원인·심각도·관측 빈도와 Healer 상태는 기존 계약을 따릅니다. 요구된 필수 검증의 미완료를
"출시 때 확인"으로 넘겨 PASS로 만들지 않습니다. 요청 밖의 외부 서비스 검증은 제외 범위를
명시하고 실제 수행한 QA만 판정합니다.

미노스 PASS는 이 실행의 QA 범위에 대한 판정입니다. 검색 노출·개인정보 법률 검토·DNS/HTTPS·
호스팅·출시 승인까지 통과한 것으로 보고하지 않습니다. 아프로디테에는 시각/경험 차이,
구현 담당에는 기능 결함, SEO·테미스에는 전문 검토 입력, 클리오에는 대상과 유효한 실행 증거·
미해결/미실행을 전달합니다. 보고만 요청한 경우 파일 대신 응답으로 제공합니다.
