# 같은 업무 규칙을 경로별로 대조하는 기준

먼저 각 경로에서 **누가 어떤 동작을 어떤 상태에서 수행하는지** 확인한다. 요구사항·기존 테스트·공개 계약에서 두 경로가 같은 결정을 약속하는지 확인하고, 실제 호출부에서 판정식이나 공통 구현까지 따라간다. 함수명이 다르거나 한쪽이 쿼리 필터로 작성된 경우도 포함한다.

| 판정 | 보고할 근거 |
|---|---|
| 동작 불일치 | 같은 계약에서 결과가 갈리는 구체적 입력·상태, 양쪽 결과와 사용자 영향을 제시한다. 어느 쪽이 계약을 어겼는지 근거가 있으면 함께 밝힌다. |
| 규칙 중복 | 현재 결과가 같아도 한 정책을 바꿀 때 두 구현을 따로 고쳐야 하는 근거를 제시한다. 이미 재사용할 판정 함수·정책이 있으면 위치를 짚는다. |
| 의도된 차이 | 기록 조회와 재개 자격처럼 목적·권한·계약이 다르면 차이를 설명할 근거를 제시한다. 화면의 사전 검사와 서버의 최종 검증은 각 경계에 유지하고, 두 경로가 공통으로 약속한 조건만 대조한다. |
| 확인 필요 | 기대 동작이나 실제 연결을 확인할 근거가 부족하면 관찰한 차이와 판단에 필요한 근거를 적는다. |

발견의 근거에는 비교한 두 위치의 `file:line`을 남긴다. 단순한 구문 유사성이나 동일한 함수 호출만으로 규칙 중복을 추정하지 않는다.
