# Role Mapping

## 기본 역할

| 역할 | 목적 | 코드 수정 |
|---|---|---|
| `default` | 리드/조율/최종 통합 | 필요 시 가능 |
| `explorer` | 코드베이스 탐색, 리스크 분석 | 금지 |
| `worker` | 구현, 리팩토링, 테스트 | 허용 |

## 태스크 분해 규칙

1. 태스크당 소유 파일은 1~5개로 제한.
2. 동일 파일을 2개 worker에 동시에 배정하지 않음.
3. 공통 파일이 필요하면 별도 single-owner 태스크 생성.
4. 의존성이 있으면 다음 Wave로 이동.

## Wave 설계 가이드

- Wave 1: 독립 태스크(병렬 최대화)
- Wave 2+: 이전 Wave 산출물 의존 태스크
- 권장 동시 worker 수: 2~5

## 실패 처리

1. 실패 명령·출력과 실제 변경으로 원인을 확인한다. 명확한 구현 결함은 직접 수정하고 환경 문제는 복구 또는 차단 조건을 남긴다.
2. 문맥·지시·작업 분할·도구 순서가 원인이라는 근거가 있으면 SKILL.md의 resolver로 `orchestrator_root`를 정하고 `references/execution-adjustment.md`를 읽는다. 프롬프트 보강·범위 축소·작업자 교체는 비교할 후보이며 횟수만으로 자동 선택하지 않는다.
3. 같은 실패는 초회 포함 최대 3회이며 호출자의 더 작은 상한이 우선한다. 비교 실행도 이 상한에 포함한다. 소진하면 미완료와 근거를 보고하고, 작업자 교체·재분할로 다시 시작하지 않는다.
4. Lead는 과제 복구와 실행 방식 개선 판정을 따로 기록한다. 기준점과 조건이 다르면 성공해도 방식의 효과는 `unverified`다. 명시적인 비교를 하지 않은 일반 결함 수정에는 이 기록을 추가하지 않는다.
