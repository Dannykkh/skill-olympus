# 공개 사이트 출시 준비 판정

공개 사이트의 출시 점검을 요청했거나 승인된 spec·AC·Experience Contract가 출시 조건을
요구할 때만 적용합니다. 디자인 시안·국소 UI 수정·일반 문서 생성에 운영 검증을 강제하지 않습니다.
기존 Phase 1 CHECKLIST와 FINAL-REPORT에 결과를 추가하며 별도 완료 장부를 만들지 않습니다.

## 결과 수집

요청된 출시 범위·대상 URL/환경과 항목의 요구 출처를 먼저 확인합니다. `Public Site Delivery`가
있으면 페이지·전환·콘텐츠·검색/개인정보·구현 소유권·출시 점검 입력을 읽고, 없으면 현재
요청과 spec·AC에서 확인한 조건만 사용합니다. 없는 사실·법적 의무·도메인을 만들어내지 않습니다.

| 항목 | 수집·확인할 근거 |
|---|---|
| 디자인·콘텐츠 | 아프로디테의 실제 렌더·주 과업 검증, 승인 카피/가격/조건·신뢰 근거와 남은 차이 |
| 구현·QA | 아르고스 결과와 minos의 실제 Playwright/탐색 QA. CTA·폼·실패/복구·모바일·링크의 검증 범위와 실제 접수/저장 여부 |
| 검색 | 요청된 페이지별 title/description/헤딩/alt·공개 의도와 seo-audit 결과. 정적 검사와 운영 관찰 구분 |
| 개인정보 | 테미스의 실제 처리 감사·방침 초안·빈칸/검토 상태, 확정된 요구에 해당하는 방침 링크·동의/설정 기능의 QA |
| 운영 환경 | 요청한 운영 도메인·HTTPS·호스팅/설정·폼 처리 대상의 실제 관찰. preview와 운영의 차이·접근 불가 항목 |
| 출시 행동 | 요청된 경우 첫 공유/홍보의 대상·채널·자료·담당·시점, 운영 모니터링/롤백 준비 결과 |

검사 결과마다 대상 버전·URL/환경·확인 시각·명령/관측·증거 경로·미실행 범위를 유지합니다.
현재 대상과 다른 버전·환경의 결과는 보조 근거로만 쓰고 유효한 완료 증거로 합산하지 않습니다.
같은 조건의 유효한 결과는 재사용하며 새로운 변경·실패·미해결 의심에 해당하는 범위만 재검증합니다.
요청이 점검이면 허용된 읽기·검사만 수행하고, 동작 확인에 외부 발송·결제·운영 변경이 필요하면
그 권한·환경이 없는 항목을 `NOT RUN`으로 남깁니다.

`mode: ci-audit`는 minos QA 결과가 아닙니다. 감사의 COMPLETE/PARTIAL, 테스트 파일의 존재,
디자인 완료·성공 토스트·mock 처리·테미스 초안·SEO 점수만으로 출시 준비를 통과시키지 않습니다.
방침 링크가 열린다는 사실과 내용/실제 처리의 정합성·필요한 검토 완료를 각각 구분합니다.

## 판정

CHECKLIST에 `항목/AC | 요구 출처·필수 여부 | 담당 | 대상·증거 | 상태 | 남은 조치`를 추가합니다.
상태는 `PASS`·`FAIL`·`NOT RUN`·`UNVERIFIED`·`NOT APPLICABLE`로 기록합니다. 비해당은 근거가
있어야 하며, 담당자 미지정·접근 불가·자료 없음은 비해당 사유가 아닙니다. 필수 여부를 판단할
입력 자체가 없으면 해당 결정을 미확인으로 보고하고 출시 GO를 선언하지 않습니다.

- **GO**: 요청된 필수 출시 조건을 현재 대상에서 증명했고 기존 Phase 1 GO 조건도 충족.
- **CONDITIONAL GO**: 필수 조건은 증명했으며 비필수 후속·경고만 남음. 기존 Phase 1의 경고도 유지.
- **NO-GO**: 필수 조건에 FAIL/NOT RUN/UNVERIFIED가 남거나 요구·필수 여부가 미확정, 또는
  기존 Phase 1이 NO-GO. 누락을 안내·수동 확인 항목으로 바꿔 등급을 올리지 않습니다.

기존 구현 점검과 출시 준비 판정을 따로 표시하고, 출시 점검이 요청된 전체 판정은 더 엄격한
결과를 따릅니다. 출시 점검이 요청되지 않았으면 `출시 준비: NOT REQUESTED`이며 일반 Phase 1
판정에 추가 실패를 만들지 않습니다. GO는 수행한 범위의 준비 상태이며 배포·DNS 변경·
홍보/메일 발송이나 법률 검토를 자동 승인하는 효과가 없습니다.

미해결 항목마다 담당·필요 입력·다음 검증 방법을 적습니다. 출시 실행이나 전문 감사가 별도로
요청됐을 때 해당 담당으로 연결하고, 체크리스트의 이름만 보고 다른 스킬·외부 작업을 실행하지 않습니다.
