# 대화 레코드 저장 계약

Claude, Codex, Grok, Antigravity, Devin 어댑터는 Node.js의 공통
`hooks/mnemo-record-store.js`를 사용한다. 이벤트 해석·턴 식별·원본 조회는 각 어댑터가,
완전한 내용의 대기 저장·잠금·본문 쓰기·완료 확인은 공통 저장기가 담당한다.
설치본에는 같은 파일을 각 CLI 훅 디렉터리에 배치한다. Node.js가 필수다.

- 비어 있지 않은 입력·응답은 길이와 관계없이 저장한다. 셸의 `echo -e`를 거치지 않아
  역슬래시·코드 블록·한국어를 그대로 보존한다.
- `<private>`를 제외한 전체 레코드를 `conversations/.mnemo-pending/*.json`에 먼저 쓴다.
  프로젝트 잠금 아래 Markdown을 쓰고 fsync한 뒤 본문 끝에 있는 완료 표식을 확인한다.
  쓰기 실패는 원래 크기로 되돌리고 대기 파일을 보존한다.
- 다음 저장 이벤트가 모든 CLI의 대기 레코드를 다시 처리한다. 성공한 본문을 확인한 뒤에만
  대기 파일을 지운다. Claude UUID 색인 실패도 대기 파일을 남기며 다른 CLI 색인과 알 수 없는 키를 보존한다.
- 대기 파일은 복구 원본이다. `.mnemo-pending`, `.claude-events.json`, `.grok-events.json`,
  `.devin-events.json`, `.mnemo-index.json`을 일반 청소 대상으로 지우지 않는다.
- 이전 어댑터의 선두 표식만으로는 완료라고 판단하지 않는다. 역할별 전체 본문이 맞아야
  기존 기록을 재사용한다. 새 표식은 본문 뒤에 있으며 같은 이벤트 재전달을 구분한다.
- 기록을 읽는 UI·검색은 기존 `conversations/YYYY-MM-DD-{cli}.md`를 그대로 사용한다.

훅이 실행되기 전에 CLI가 종료되거나 대기 파일 자체를 만들 수 없으면 이 저장기로 복구할
내용을 확보하지 못한다. 이 경우 프로젝트·세션 범위를 좁힌 제공자 원본 복구가 필요하다.
유한한 재시도가 끝난 대기 레코드는 다음 이벤트가 올 때까지 남는다.
이 계약은 제공자 원본 세션과 UI의 저장·표시 동작까지 변경하지 않는다.
