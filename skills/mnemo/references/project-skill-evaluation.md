# Mnemo 프로젝트 스킬 비교 검증

Mnemo의 project-skill-improvement가 evaluate 단계에서 읽는다. 예시 점수나 형식 준수는 실제 개선의 증거가 아니다.

## 실험 입력

상위 하네스가 지정한 정확한 대상 파일, 가설 하나, 평가 기준, 사례, 결과 디렉터리,
수정 권한과 실행 상한을 받는다. 지정한 프로젝트 전용 스킬만 다룬다. 대상 미지정 시 실험을 시작하지 않고 보류한다.
전역 스킬이나 프로젝트의 배포용 정본을 자동으로 선택하지 않는다.

실행 전에 다음을 고정한다.
- 개발 사례: 실패 재현과 후보 수정에 사용할 입력.
- 별도 평가 사례: 수정 과정에서 정답 맞춤에 쓰지 않을 입력과 평가 기준.
- 회귀 검사: 기존 정상 동작과 필수 제약을 검증할 명령 또는 관찰.
- 상한: 최대 라운드와 시간 또는 토큰 예산. 기본 최대 20라운드, 상위의 더 작은 상한 우선.

사례가 부족하면 일반화 검증 부족으로 보류한다. 별도 평가 결과를 보고 후보를 다시 수정했다면
그 사례는 개발 사례가 된 것으로 기록하고 새 평가 사례를 확보한다.

## 실행

기준점과 후보를 같은 환경·동일 사례로 실제 실행한다. 파일이 쓰였는지, 테스트 종료 코드,
타입·스키마 등 기계적 검사는 코드로 확인한다. 의미 판단은 현재 LLM이 기준별
`pass | fail | uncertain`과 근거 한 줄로 답한다. uncertain과 NOT RUN은 통과에 합산하지 않는다.
Jev·다른 공급자·다른 CLI를 필수 의존성으로 요구하지 않는다.

백업은 지정한 대상 파일에 한정한다. 프로젝트 전체 git stash/reset이나 사용자 변경 덮어쓰기를 하지 않는다.
가능하면 후보 사본에서 실험한다. 실제 대상을 수정할 때는 적용 직전 원본 해시를 확인하고,
동시 변경을 발견하면 덮어쓰지 않고 보류한다. 복구도 이번 실험의 변경만 대상으로 한다.

## 채택

- accepted: 별도 평가에서 기준점 대비 개선이 있고 필수 회귀 검사를 모두 통과했다.
- 동점: 무조건 채택하지 않는다. 품질 회귀 없이 길이·시간·토큰 중 명시한 비용 지표가
  개선된 경우에만 채택할 수 있다. 관측 변동 이내이면 보류한다.
- rejected: 실제 회귀 또는 유효한 개선 없음. 이전 채택본을 유지한다.
- deferred/not-run: 증거 부족, 실행 불가, 상한 소진을 구분해 기록한다.

필수 실패를 평균 점수로 상쇄하지 않는다. 단일 모델의 순차 재채점은 독립 검증이 아니다.
다른 모델의 채점이 가능해도 실제 테스트나 별도 평가를 대신하지 않는다.
같은 입력의 연속 고득점은 안정성 보조 신호이며 최종 채택 게이트가 아니다.

## 반환

기준점·후보의 해시, 입력과 결과 산출물, 실제 실행 명령/결과, 채점자와 격리 여부,
측정 비용 또는 unknown, 상태, 이유, 재시도 조건을 상위 하네스에 반환한다.
계산 가능한 비율은 실제 분자/분모로 계산한다(3/5 = 60%). 새 프롬프트의 결과는 실제 실행한다.
과거 결과를 읽은 것을 새 후보 실행이나 Dream-RSI 재생 검증으로 보고하지 않는다.
