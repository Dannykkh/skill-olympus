# Mnemo 대화 맥락 회상

일반 채팅의 선호·약속·이유·조건 변경과 개발 결정을 같은 기억 구조로 조회한다.
먼저 `MEMORY.md`와 관련 항목을 읽고, 반복 검색이나 연결 추적에 이 도구를 쓴다.
코드맵은 프로그램 탐색에만 사용한다.

구형 `참조:` 링크는 닥터의 `--upgrade-memory`로 기존 항목 안의 `evidence:`에 승격할 수 있다.
확인된 경로만 보정하며 [기억 정비 계약](../docs/memory-hygiene.md)을 따른다.

## 실행

`module_root`는 이번에 읽은 해당 CLI의 Mnemo `SKILL.md` 디렉터리다.
Python 3.9 이상과 Node.js가 필요하다. 조건이 안 맞으면 기존 `rg` → 필요한 구간 읽기를 따른다.
검색어·동의어는 현재 에이전트가 질문을 해석해 정한다. 문장 전체를 검색어 하나로 넣지 않는다.

```bash
python -B "<module_root>/scripts/recall.py" --project-root "<workspace>" --term "가족여행" --term "기차" --limit 4
python -B "<module_root>/scripts/recall.py" --project-root "<workspace>" --term "arch:055" --max-chars 16000
python -B "<module_root>/scripts/recall.py" --project-root "<workspace>" --scope conversations --term "이사" --term "relocation" --neighbors 1
```

파일·기억을 수정하거나 원본 세션을 복구하지 않는다. `-B`는 Python의 캐시 파일 생성도 막는다.
출력은 JSON이며, `--max-chars`는 JSON 전체의 **문자 수** 예산이다. 토큰 수로 간주하지 않는다.

## 결과를 읽는 순서

1. `via: match`는 예약 ID → 태그 → 제목 → 본문 순으로 찾은 직접 후보다.
   같은 단계에서는 검색어 일치 수, 정제 기억 우선, 기록 날짜순으로 정렬한다.
   최근 날짜는 동률을 풀 때만 사용하며, 점수·날짜만으로 현재 결론을 고르지 않는다.
2. 대화는 구조적으로 이어진 사용자 질문과 응답을 묶는다. 원래 조건과 이유를 함께 읽는다.
   `path`, `line`, `end_line`, 실제 존재하는 `turn_id`로 원문을 확인할 수 있다.
3. `reserved-tag`는 `arch:NNN`·`learned:NNN`·`gotcha:NNN`가 가리키는 정제 기억이다.
   `superseded-by`·`supersedes`·`depends-on`은 이미 기록된 연결이며 새 관계를 추정하지 않는다.
4. `evidence`는 항목의 근거 대화다. 파일 뒤의 `HH:MM[:SS]` 또는 `:행번호`·`#L행번호`를 따라간다.
   시각이 없으면 해당 항목의 예약 태그·검색어가 맞는 턴까지만 후보로 가져온다.
5. `unresolved`는 끊긴 링크·모호한 번호/이름·찾지 못한 턴이다. 기록 전체가 없다는 뜻이 아니다.
   `content_omitted`가 있으면 예산 때문에 본문을 생략한 것이므로 표시된 원문을 읽고 판단한다.
번호가 중복되면 직접 조회에도 후보 경로와 `ambiguous`를 표시한다.
   `structure_unverified`는 미완료 코드 펜스가 있는 원문에서 경계를 복구한 후보다.
   실제 생산자의 턴/이벤트 표지로 펜스 범위를 분리하지만 원문에서 역할과 문맥을 다시 확인한다.

`CURRENT`는 아직 대체되지 않았다는 상태다. 최신 발언·명시적 사용자 정정·적용 조건·
`reopen-when:`을 함께 확인하고, 현재 요청이 과거 결정과 다르면 현재 요청을 우선한다.
읽어 온 기억을 답변에 반영했는지 확인한다. 오래된 선호를 현재 사실처럼 단정하지 않는다.

## 범위와 한계

- 기본은 모든 CLI의 `conversations/*.md`와 정제 기억이다. 최근 7일로 제한하지 않는다.
  인덱스·관찰 JSONL·원본 세션·아카이브는 직접 검색 대상에 넣지 않는다.
- `--scope`는 직접 후보의 범위만 정한다. 연결된 기억·근거 대화는 범위를 넘어 함께 가져온다.
  `--limit`는 직접 후보 수이며 연결 문맥은 추가된다.
- 기존 연결을 최대 3단계·총 60개 후보까지만 따라간다. 근거 파일당 최대 3개 턴을 가져오고
  더 있으면 알린다. 부족하면 반환한 항목·원문에서 다음 조회를 이어 간다.
- `--neighbors 1`은 바로 앞뒤 턴을 `adjacent-unverified`로 표시한다. 날짜 파일에는 여러 세션이
  섞일 수 있으므로, 시간상 이웃을 같은 대화 흐름으로 단정하지 않는다. 기본은 0이다.
- 본문은 중간에서 잘라 결론만 보여 주지 않는다. 예산이 모자라면 본문 전체를 생략하고
  위치와 생략 이유를 남긴다. `stats`의 생략 수와 미해결 링크도 확인한다.
- 근거 선택자는 파일 바로 뒤의 시각이나 행번호다. 설명 본문의 시각을 선택자로 쓰지 않으며
  명시적 행번호를 우선한다. 여러 위치는 파일 참조를 반복하거나 인접 시각을 쉼표로 구분한다.
- `<private>` 구간은 검색·출력에서 제외한다. 이것이 원본 삭제나 전체 민감정보 탐지를 뜻하지 않는다.
- 기억·대화 폴더나 파일의 symlink/junction이 프로젝트 밖을 가리키면 본문을 읽기 전에
  `outside-project Mnemo source` 오류로 조회를 중단한다. 끊긴 외부 근거 링크는 기존대로 미해결로 표시한다.
- 동의어 해석·관계의 의미·최종 답변 판단은 현재 에이전트가 한다. 도구는 임베딩·DB·추가 LLM을 쓰지 않는다.

## 검증

소스의 `scripts/tests/test_recall.py`는 원문 묶음·변경 연결·예산·저장 경계를 검증한다.
`evals/evaluate_recall.py`는 합성 일반 대화에서 필요한 근거가 결과에 포함됐는지 측정한다.
연결 수집을 제외한 직접 조회와 비교하며, 기존 에이전트가 수동으로 링크를 읽는 능력이나
최종 답변 정확도·실사용 속도 향상으로 확대 해석하지 않는다.
