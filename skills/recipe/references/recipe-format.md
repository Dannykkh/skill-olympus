# Recipe Format — recipe.md 양식과 견본 규칙

레시피 한 건 = `<라이브러리>/<kind>/<id>/` 폴더 하나.

```
<kind>/<id>/
  recipe.md     ← 필수. 아래 양식
  sample/       ← 필수. 원래 프로젝트 없이 혼자 실행되는 견본
  source/       ← 선택. 원래 프레임워크로 쓴 구현 (견본과 다를 때만)
```

`kind`는 `ui` · `backend` · `mcp` · `infra` 중 하나이고, 폴더 이름은 `kind`·`id`와 같아야 합니다.
`recipe-lib.js check`가 이 문서의 필수 항목을 검사합니다.

## recipe.md 양식

```markdown
---
id: upload-with-presigned-url
kind: backend
title: 미리 서명된 URL로 파일 올리기
tags: upload, s3, presigned-url, validation
version: 1
updated: 2026-10-05
source: shop-admin @ 3f2a9c1 — src/upload/presign.ts, src/upload/confirm.ts
reuse: personal
when: 브라우저가 큰 파일을 서버를 거치지 않고 저장소로 바로 올려야 할 때
---

# 미리 서명된 URL로 파일 올리기

## 언제 쓰나
## 쓰지 않을 때
## 계약
## 구조
## 값
## 상태와 흐름
## 결정과 이유
## 함정
## 옮길 때
## 견본
## 변경 이력
```

### 머리 필드

| 필드 | 값 |
|------|----|
| `id` | 소문자·숫자·하이픈. 폴더 이름과 같음 |
| `kind` | `ui` · `backend` · `mcp` · `infra` |
| `title` | 한 줄 이름 |
| `tags` | 쉼표로 구분한 검색어 (기술·도메인·한국어 동의어) |
| `version` | 정수. 다시 수확할 때마다 1 올림 |
| `updated` | `YYYY-MM-DD` |
| `source` | 출처 프로젝트 @ 커밋 — 파일 경로. 공개하면 안 되는 이름이면 별칭으로 |
| `reuse` | `personal`(내 프로젝트에서만) · `company-internal`(같은 회사 프로젝트에서만) · `public`(어디서나). 수확 때 사용자에게 확인한 값 |
| `when` | 언제 쓰는지 한 문장 — `index.md` 목록에 그대로 나옴 |

### 본문 섹션

해당 내용이 없으면 섹션을 지우지 말고 `해당 없음 — <이유>`라고 씁니다. 그래야 빠뜨린 것과 없는 것이 구분됩니다.

| 섹션 | 쓰는 것 |
|------|---------|
| `## 언제 쓰나` | 이 레시피가 맞는 상황 2~4개 |
| `## 쓰지 않을 때` | 비슷해 보이지만 맞지 않는 상황과 대신 쓸 것 |
| `## 계약` | 입력·출력·이벤트·에러. ui는 props·이벤트·슬롯, backend·mcp는 요청·응답·에러 코드, infra는 입력 변수·산출물. 견본 언어별 형태만이 아니라 다른 언어로 옮겨도 지킬 형태(무엇을 돌려주나, 시간 제한)를 먼저 적음 |
| `## 구조` | 구성 부분과 역할 (파일·컴포넌트·함수 단위) |
| `## 값` | ui는 색·간격·반경·그림자·모션 토큰과 기본값, backend·infra는 설정값과 기본값. 원래 프로젝트 값은 "출처 값"으로 따로 |
| `## 상태와 흐름` | 상태 목록과 전환 조건, 또는 요청 흐름 |
| `## 결정과 이유` | 왜 이렇게 했고 무엇을 버렸는지. 근거(기억 항목·커밋·이슈)를 함께. 근거가 없으면 "기록 없음" |
| `## 함정` | 원래 프로젝트에서 실제로 겪은 문제와 증상·원인·대응 |
| `## 옮길 때` | 다른 프레임워크·언어·OS로 옮길 때 바뀌는 것과 지켜야 하는 것 |
| `## 견본` | 실행 방법(명령 한 줄)과 `검증: <명령> → <결과> (YYYY-MM-DD)` 줄. 재현 검사를 했으면 그 결과 한 줄 |
| `## 변경 이력` | `vN (YYYY-MM-DD): 무엇을 왜` — 버전마다 한 줄 |

## 종류별 견본 규칙

| kind | 필수 견본 | 검증 |
|------|-----------|------|
| `ui` | `sample/preview.html` — 파일 하나로 열림. 모든 상태(기본·열림·로딩·빈 화면·에러 등)를 페이지 안 토글로 볼 수 있음. 토큰은 CSS 변수 | 브라우저 렌더, 콘솔 에러 0, 키보드 조작, 다크 모드, 모바일 폭(360px), `prefers-reduced-motion` |
| `backend` | 최소 실행 코드 + 테스트 파일(이름에 `test`나 `spec`). 외부 서비스는 가짜 구현이나 fixture | 테스트 한 명령으로 통과 |
| `mcp` | 최소 MCP 서버나 도구 래퍼 + 테스트 파일 | 테스트 통과, 가능하면 `tools/list` 출력 |
| `infra` | 설정 파일·스크립트 + 실행 명령 | dry-run, lint, 또는 가짜 환경에서 실행 |

공통:
- 원래 프로젝트 없이 실행됩니다. 필요한 의존성과 설치 명령은 `## 견본`에 적습니다.
- 외부 네트워크가 필요하면(CDN 폰트, 실제 API) 그 사실을 `## 견본`에 적고, 가능하면 끌 수 있게 합니다.
- 견본은 설명서의 계약을 보여 주는 기준입니다. 원래 프로젝트의 전체 기능을 옮기지 않습니다.
- 테스트는 시험하려는 상황이 실제로 일어났는지도 확인합니다(가짜 구현이 정말 불렸는지, 실패 경로를 정말 지났는지). 그러지 않으면 아무것도 확인하지 않고 통과합니다.

## 떼어내기

수확할 때 하나씩 확인합니다.

- [ ] 브랜드 색·폰트·문구 → 토큰·변수·`{{placeholder}}`
- [ ] 실제 API 주소·DB 연결 → 인터페이스와 가짜 구현, 연결값은 환경 변수 이름만
- [ ] 비밀값(키·토큰·비밀번호) → 없음. 견본에 필요하면 `<YOUR_KEY>`처럼 명백한 자리 표시
- [ ] 실데이터·개인정보(이름·이메일·전화) → `example.com` 같은 가짜 데이터
- [ ] 회사·고객 이름, 내부 도메인, 사내 시스템 이름 → 일반 명칭이나 별칭
- [ ] 내 PC 경로(`C:\Users\…`, `/Users/…`, `/home/…`) → 상대 경로
- [ ] 원래 프로젝트에만 있는 유틸·전역 상태 의존 → 견본 안에 최소 구현으로 넣거나 계약으로 바꿈

`recipe-lib.js check`는 개인 키·클라우드 키 형태를 오류로, 로컬 경로·실제 같은 이메일·비밀번호 같은 할당을 경고로 알립니다.
도구가 못 찾는 것(회사 이름, 사내 도메인)은 위 체크리스트로 직접 확인합니다.
