# Argos GS 평가 감리 절차

GS에서 scope·criteria·TC·execution·문서 검토 결과를 전달받았을 때만 적용한다.
등급과 기관 기준이 없는 일반 Argos 요청에 자동 적용하지 않는다. 전체 Phase를 무조건 재실행하지 않는다.

| 단계 | 감리 행동 | 실패/누락 처리 |
|---|---|---|
| A1 평가 요구 | 기관·등급·제품 유형·판본, 평가 목적/범위, 기준 원문과 criteria.md 전체 행 대조 | 누락 조항·임의 제외·미확정 판본은 INCOMPLETE |
| A2 평가 설계 | CR별 측정 단위·부하·환경·기준치·기대값, 정상/오류/경계값 및 문서 시험 대조 | 단순 HTTP 성공이나 자체 점수를 공식 측정치로 인정하지 않음 |
| A3 실행 증거 | plan 해시, 명령, 시각, 실제 하네스 리포트와 빌드/환경 대조; assertion 코드 확인 | exit 0만 있고 의미 있는 assertion/측정값 없으면 UNVERIFIED |
| A4 결과 검증 | 실패 사례 재현, API 응답+저장/부수 효과, 성능 원시값, 장비/복구 증거 확인 | 위반은 NEEDS_WORK, 관찰 불가/장비 부재는 NOT RUN |
| A5 문서 감리 | Clio의 문서 검토표와 실제 문서, 기능·버전·지원 범위 일치 확인 | 미확인 주장을 보완 대상으로 반환 |
| A6 결함/종결 | OPEN 결함, 수정 빌드, 실패 TC 재시험과 정상 회귀를 연결; 2등급 업무적합성 별도 확인 | 증거 없는 CLOSED/다른 빌드 결과 승계 금지 |

출력은 GS run_dir의 audit.md: `CR-ID | 설계 적절성 | 실행 증거 | 문서 일치 | 결함/회귀 |
판정 | 근거 위치 | 남은 행동`. 미검증·NOT RUN·N/A의 이유도 남긴다.
메인이 evidence-contract.md의 최종 게이트를 적용한다. 이 감리의 내부 READY와 기관 인증 여부는 구분한다.
25023 측정, 25051 제품/문서·시험, 25041 평가 관점을 연결하되 보유하지 않은 전문의 세부 조항을 인용하지 않는다.
