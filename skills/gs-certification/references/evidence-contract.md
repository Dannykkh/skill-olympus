# 증거·산출물·준비도 계약

## 출력 경계

제품 프로젝트의 `docs/gs-certification/grade-{1|2}/{run-id}/` 아래에 작성한다.
run-id는 시각과 빌드 식별자를 이용한 고유 이름으로 정하고 기존 실행을 덮어쓰지 않는다.
읽기 전용 요청에서는 같은 양식을 응답으로만 제공한다. 인증기관 제출이나 운영 변경을 자동 수행하지 않는다.

## 증거 게이트

- PASS는 해당 기준에 대한 실제 실행/문서 대조 근거가 있어야 한다. 코드 읽기를 런타임 시험으로 표시하지 않는다.
- 문서 요구는 문서 위치·검토 결과, 런타임 요구는 명령·입력·출력·빌드/환경·시각을 기록한다.
- N/A에는 선택 등급/기관 기준에 근거한 제외 사유가 필요하다. 장비·계정·시간 부족은 NOT RUN이다.
- 정상 대조군 없는 일괄 403/404, 거부 후 저장/부수 효과 미확인은 API 방어 PASS의 근거가 아니다.
- 증거의 토큰·쿠키·개인정보는 마스킹한다. 원시 로그 전체를 무조건 수집하지 않는다.
- 다른 빌드·환경·등급 결과는 자동 승계하지 않는다. 유효성을 설명한 재매핑 또는 재시험이 필요하다.
- 미확인 측정치·배점·조항은 UNVERIFIED다. 임의 0점/만점으로 채우지 않는다.

## 최종 판정 순서

1. 재현된 필수 결함 또는 미해소 중대한 보안/데이터 무결성 결함이 있으면 NEEDS_WORK.
2. 등급/기관/기준/필수 문서 범위가 미확정, 필수 시험 NOT RUN/UNVERIFIED, 근거 없는 N/A,
   버전 불일치·증거 누락이 있으면 INCOMPLETE. 2등급은 품질과 업무적합성 두 그룹 모두 확인한다.
3. 위 문제가 없고 적용 필수 항목 전부 증거로 충족됐을 때 READY(사전점검 준비 완료).

시험 수의 비율은 커버리지로만 표시한다. 공식 GS 점수·인증 합격으로 표시하지 않는다.
하위 모듈의 PASS/GO는 해당 범위의 증거일 뿐이고, 메인이 위 게이트로 최종 판정한다.

## 자동 실행 결과 결합

plan.json과 execution.json의 필드는 execution-protocol.md를 따른다. 실행기의 EVIDENCE_COMPLETE는
기계적으로 수집한 증거 상태다. 자동 결과와 Clio 문서 검토·Argos audit.md를 함께 읽은 뒤 최종 READY를 결정한다.
수동 시험은 원본 증거·검토자를 별도로 기록하며 실행기 NOT RUN을 임의 PASS로 고치지 않는다.
