# Clio GS 문서 작성·검토 절차

GS에서 문서 작업을 전달받았을 때만 적용한다. 일반 Clio 3종 문서 절차에 상시 추가하지 않는다.
입력: scope.md, criteria.md, 기능 목록, 현재 제품 문서, 빌드, 실행/결함 증거.
출력: 동일 GS run_dir의 product-description.md, user-manual.md, document-review.md.
읽기 전용에서는 파일 작성 대신 검토 결과를 응답한다. 이미 충족된 문서를 새로 만들지 않고 정본을 참조한다.

## D1 제품설명서 대조

아래는 작성 슬롯이며 기관의 실제 문서 요구 조항으로 매핑한 뒤 적용한다.
제품명·판본·공급자 식별, 사용 목적·대상 사용자, 기능 목록·입출력, 지원 HW/OS/브라우저와 의존성,
설치/운영 조건, 용량·성능 조건, 보안/계정 역할, 알려진 제한, 지원·유지관리 조건을 확인한다.
각 주장에 문서 위치→기능/설정→시험 증거를 연결한다. 미확인 용량·성능·지원 OS는 확인 필요로 남긴다.

## D2 사용자취급설명서 재현

설치→설정→최초 실행→역할별 주요 업무→잘못된 입력/오류 회복→백업/복원→업데이트/삭제 중
해당 기능을 문서 순서대로 시험 환경에서 실행한다. 설명서의 예제 입력과 실제 결과를 비교한다.
UI 없는 제품은 CLI/API 입력·출력·오류·권한·연계 예제로 대체한다. 모바일/임베디드는 해당 환경에서 확인한다.
문서 밖의 암묵적 준비 단계가 필요하거나 화면/옵션/오류 메시지가 다르면 결함으로 남긴다.

## D3 문서 일치와 검토표

제품명/버전, 기능명, 용어, 지원 환경, 제한, 설정 기본값이 제품·제품설명서·사용자취급설명서 간
일치하는지 확인한다. document-review.md에 `DOC-ID | 기준 조항 | 문서/위치 | 주장 | 실행 TC/증거 |
PASS/FAIL/UNVERIFIED/N/A | 보완 사항`을 기록한다. 기관 서식의 모든 요구 항목에 행이 있어야 한다.
누락 문서를 기존 PRD/TECHNICAL.md 이름만 바꿔 충족했다고 판정하지 않는다.

## D4 완료 기준

필수 누락·모순·미재현 절차는 미해소 결함/미검증으로 GS에 반환한다. 수정했다면 해당 절차 재현과
문서 간 일치 재검토를 수행한다. 실행하지 않은 시험·존재하지 않는 기능을 작성하지 않는다.
공인 시험결과서·인증서 대신 내부 사전점검 자료임을 표시한다. 제출은 별도 명시 요청 범위다.
