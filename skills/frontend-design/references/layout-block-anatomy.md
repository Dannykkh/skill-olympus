# Layout Block Anatomy — 블록 해부 카탈로그 (와이어프레임-퍼스트)

> 페이지는 즉흥 산문이 아니라 **블록의 시퀀스**입니다. 이 카탈로그는 30개 표준 블록의
> 구조 계약(anatomy contract)을 정의합니다 — 각 블록에 어떤 요소가, 어떤 순서와 위계로,
> 어떤 강조 규칙으로 들어가야 하는지. 스타일(색·폰트·모션)은 DESIGN.md 토큰의 몫이고,
> 이 파일은 **스타일을 입히기 전의 그레이스케일 구조**만 다룹니다.
>
> Credits: 블록 분류와 와이어프레임 스키마는 [anelkabag/bag-ui](https://github.com/anelkabag/bag-ui) (MIT)의
> 블록 카탈로그(Marketing 16 / App 8 / Ecommerce 6종 SVG 와이어프레임)에서 구조만 번역.
> 문구·코드·에셋은 복제하지 않음.

## 왜 와이어프레임-퍼스트인가

구조와 스타일을 분리하면 실패 원인도 분리됩니다. "구려 보인다"의 절반은 색·폰트가 아니라
**요소 누락이나 위계 붕괴**(가격보다 큰 라벨, CTA 3개가 전부 솔리드, 강조 카드 0개 또는 3개)입니다.
그레이스케일 청사진 단계에서 구조가 성립하면, 스타일은 그 위에 얹는 변주가 됩니다.

**검증 기준**: 색을 전부 빼고 잉크 농도 3단계만 남겨도 "무엇을 먼저 읽어야 하는지"가 보이면 통과.

## 공통 문법 (모든 블록에 우선 적용)

| # | 규칙 | 내용 |
|---|------|------|
| 1 | **잉크 위계 3단계** | 핵심(헤드라인·가격·KPI 값) = near-black / 보조(라벨·설명) = mid-gray / 배경 요소(placeholder·구분선) = light-gray. 와이어프레임 단계에서 이미 위계가 성립해야 함 |
| 2 | **강조는 블록당 정확히 1개** | 추천 pricing 카드 1, navbar 솔리드 CTA 1, 활성 내비 1, 현재 스텝 1, 선택 썸네일 1. 전부 강조 = 아무것도 강조 안 됨 |
| 3 | **CTA 문법** | primary solid 1개 + secondary outline 0~1개. 카드/폼 내부 CTA는 풀폭. 같은 위계의 솔리드 버튼 2개 금지 |
| 4 | **2분할 비율** | 폼+요약(체크아웃·카트·컨택트)은 60:40 또는 2/3:1/3. 50:50 균등 분할은 위계 없음의 신호 |
| 5 | **반복 요소는 내부 구조 동일** | 카드 그리드/행 리스트는 내부 anatomy를 통일하고 개수는 3~6. 내용 길이 차이로 카드 높이가 들쭉날쭉하면 클램프 |
| 6 | **상태를 하나 보여주기** | FAQ는 1개 열림, 투두는 일부 완료, 테이블은 지브라 — 정적 렌더에도 "동작하는 모습"이 보이게 |
| 7 | **지속 비대칭 + 강조 이탈** | 히어로에서 세운 그리드 비율을 최소 1개 후속 섹션에서 재사용. 반복 블록 3개+는 정확히 1개를 근거 있는 이유로 이탈(크기/배경/타이포). 균등 그리드로 전부 복귀하면 "한 번 쓰고 포기한 비대칭"으로 읽힘 — `technique-recipes.md` §11 |

> **anti-slop과의 관계**: 이 카탈로그는 "요소 체크리스트"(무엇이 있어야 하는가)이지 배치 강제가
> 아닙니다. `ai-slop-blacklist.md` #10(쿠키커터 섹션 리듬 금지)은 그대로 유효 — VARIANCE가 높으면
> 같은 요소를 비대칭·오프셋으로 배치하고 섹션 높이/밀도를 변주하되, **요소를 빼먹는 방식으로
> 변주하지 마세요**.

## Marketing 블록 (16종)

### Hero
- **구조**: eyebrow 배지(선택) → 헤드라인 최대 2줄 → 서브텍스트 1~2줄(헤드라인보다 좁은 폭) → CTA 쌍(primary solid + secondary outline) → 하단 미디어 또는 소셜프루프 스트립
- **위계**: 헤드라인이 페이지 전체에서 가장 강한 잉크. 서브텍스트는 mid-gray로 명확히 후퇴
- **흔한 실수**: CTA 2개 모두 솔리드 / 서브텍스트가 헤드라인과 같은 폭(스캔 리듬 붕괴) / VARIANCE>4인데 센터 정렬 고수
- **스캐폴드**: [`scaffolds/hero.html`](scaffolds/hero.html) — 렌더 검증된 시작 코드

### Feature
- **구조**: 섹션 타이틀(중앙 또는 좌) + 서브 → 카드 그리드 3×2 또는 2×2. 카드 내부: 아이콘 → 카드 타이틀 → 설명 2줄
- **흔한 실수**: 카드마다 설명 길이 제각각 / 아이콘만 크고 타이틀이 약함. 3열 반복이 세 섹션 이상 이어지면 지그재그/비대칭으로 리듬 전환

### Pricing
- **구조**: 타이틀+서브 → 플랜 카드 3열 → 카드 내부: 플랜명 → 짧은 설명 → 가격(블록 내 최대 잉크) + 단위 라벨 → 기능 리스트 4~7 → CTA 풀폭
- **강조**: 추천 플랜 카드 **정확히 1개**를 반전(inverted: 다크 배경/밝은 텍스트) 또는 보더/스케일로 구분. CTA도 강조 카드만 반전
- **흔한 실수**: 강조 카드 0개 또는 2개+ / 가격보다 플랜명이 큼 / 기능 리스트 개수가 카드마다 2배 이상 차이
- **스캐폴드**: [`scaffolds/pricing.html`](scaffolds/pricing.html) — 렌더 검증된 시작 코드

### Testimonial
- **구조**: 타이틀 → 카드 3열: 따옴표 글리프 → 인용문 3~4줄 → 아바타 + 이름/직함 → 별점(선택)
- **흔한 실수**: 제네릭 이름("John Doe") / 인용문이 전부 같은 길이(진짜 인용처럼 안 보임)

### CTA (밴드)
- **구조**: 풀폭 밴드 카드: 좌 헤드라인 + 서브 1줄, 우 CTA 버튼 1개. 변형: 다크 반전 / 아웃라인 / 배경 강조색
- **흔한 실수**: 히어로급 높이(밴드는 얇게) / CTA 좌측 배치(시선 흐름 종점은 우측)

### FAQ
- **구조**: 타이틀 중앙 → 아코디언 리스트 4~6행(질문 + 우측 토글 아이콘), **1개는 열림 상태**로 답변 노출
- **흔한 실수**: 전부 닫힘(동작이 안 보임) / 질문 길이가 모두 동일

### Navbar
- **구조**: 좌 로고 → 중앙(또는 로고 옆) 링크 3~5개 → 우측 보조 액션(로그인 등 텍스트) + 솔리드 CTA 1개. 스크롤 시 배경/blur 전환, 모바일은 햄버거
- **흔한 실수**: 솔리드 버튼 2개 / 링크 7개+ (과밀)
- **스캐폴드**: [`scaffolds/navbar.html`](scaffolds/navbar.html) — 렌더 검증된 시작 코드

### Footer
- **구조**: 다크 반전 흔함. 좌 브랜드 칼럼(로고 + 설명 2~3줄) + 링크 칼럼 3개(칼럼 타이틀 + 링크 4개) → 하단 divider → 저작권 + 소셜
- **흔한 실수**: 링크 칼럼과 브랜드 칼럼의 시각 무게 동일(브랜드 칼럼이 넓어야 함)
- **스캐폴드**: [`scaffolds/footer.html`](scaffolds/footer.html) — 렌더 검증된 시작 코드

### Blog
- **구조**: 타이틀 → 카드 3열: 커버 이미지(카드 상단 ~45%) → 카테고리 라벨(작게) → 포스트 타이틀 → 요약 2줄 → 메타(날짜 + 저자 아바타)

### Team
- **구조**: 타이틀 → 카드 4열: 원형 아바타(카드 상단 중앙) → 이름 → 직함(mid-gray) → 소개 2~3줄

### Stats
- **구조**: KPI 카드 4열: 라벨(작게, 위) → 값(블록 내 최대 잉크) → 보조 라벨 → 스파크라인(선택)
- **흔한 실수**: 값과 라벨의 잉크 위계 역전 / 카운트업 애니메이션 남용(기능형이면 예산 0)

### Contact
- **구조**: 2분할(좌 폼 카드 45% : 우 미디어/지도 55% 또는 반대) — 폼: 타이틀 → 설명 1~2줄 → 필드 3개(라벨 + 인풋) → 제출 풀폭

### Gallery
- **구조**: 타이틀 → 이미지 그리드 3×2 (균일 or 매소닉). 캡션은 선택

### Logos
- **구조**: 신뢰 문구(작게, mid-gray, 중앙) → 로고 행 4~6개(그레이스케일 통일), 많으면 2행 또는 마퀴

### Banner (공지 스트립)
- **구조**: 얇은 풀폭 스트립: 좌 메시지 1줄 + 우 CTA/닫기. 변형: 다크 / 경고색 배경 / 아웃라인

### SignUp / Login
- **구조**: 중앙 단일 카드(고정 폭): 타이틀 → 서브 1줄 → 필드(라벨 + 인풋) 2~3개 → 제출 풀폭 → 보조 링크(가입/비번 찾기) → 소셜 로그인(선택, divider로 구분)

## App 블록 (8종)

> 기능형 화면은 먼저 `coder-interface-pattern-playbook.md`의 Interface Mode·효과 예산을
> 고정한 뒤, 아래 anatomy를 pane 구성의 체크리스트로 사용하세요.

### Dashboard
- **구조**: 좌 사이드바(고정) + 메인: 페이지 타이틀 → KPI 카드 행 4개(라벨 → 값) → 메인 차트 카드(2/3) + 사이드 리스트 카드(1/3) → (선택) 하단 Data Table
- **위계**: KPI 값 > 페이지 타이틀 > 카드 타이틀. 활성 내비 1개만 강조
- **흔한 실수**: KPI 카드에 그림자·그라데이션(효과 예산 0) / 차트와 리스트가 50:50

### Sidebar
- **구조**: 로고/워크스페이스 → 내비 아이템 5~7(아이콘 + 라벨), **활성 1개** 배경 강조 → 하단 유저/설정 고정. 접힘 상태(아이콘만) 고려

### Data Table
- **구조**: 카드 컨테이너: (선택) 툴바(검색+필터) → 헤더 행(구분 배경, 4~6열) → 데이터 행 6~10(지브라 또는 divide-y), 행 높이 일정 → (선택) 페이지네이션
- **흔한 실수**: 열마다 정렬 불일치(숫자는 우측, 텍스트는 좌측) / 상태 셀에 색 3개+

### Chart Card
- **구조**: 2×2 그리드: 각 카드 라벨 → 큰 값 → 미니 차트(막대/라인). **현재 기간 1개만 강조색**, 나머지 막대는 뉴트럴

### Settings
- **구조**: 2분할 — 좌 세로 탭 4~6(활성 1 배경 강조) + 우 폼 패널: 섹션 타이틀 → 필드 그룹(라벨 + 인풋) 3~5 → 저장(패널 하단)

### User Profile
- **구조**: 커버 밴드(다크/이미지) → 아바타 원형(커버에 겹침, 보더 링) → 이름/핸들 + 우측 액션 버튼 1 → 통계 카드 3개(값 + 라벨)

### Onboarding
- **구조**: 중앙 단일 카드: 타이틀 → 서브 → 필드 1~2 → CTA 풀폭 → **스텝 도트(현재 1개 강조)**
- **흔한 실수**: 한 스텝에 필드 4개+ (스텝 분리 실패)

### Todo List
- **구조**: 카드: 타이틀 + 우측 추가 버튼 → 행 5~7(체크박스 + 텍스트), **완료 항목은 체크 + 흐린 텍스트**로 혼재

## Ecommerce 블록 (6종)

### Product List
- **구조**: (선택) 필터 바 → 카드 4열: 이미지(상단 ~55%) → 상품명 → 보조 정보(브랜드/옵션) → 가격(강한 잉크) → CTA 풀폭
- **흔한 실수**: 가격이 상품명보다 약함 / 이미지 비율 카드마다 상이

### Product Detail
- **구조**: 2분할 — 좌: 대형 이미지 + 썸네일 4(선택 1 보더 강조) / 우: 상품명 → 평점·리뷰 수 → 가격 → 옵션/특징 리스트 3~4 → primary CTA 풀폭 + secondary 아웃라인 풀폭

### Shopping Cart
- **구조**: 2분할(60:40) — 좌 아이템 리스트 2~4(썸네일 → 이름 → 옵션 → 가격, 수량 조절) / 우 주문 요약: 금액 행 3~4(라벨 + 값) → divider → **합계(최대 잉크)** → 체크아웃 CTA 풀폭

### Checkout
- **구조**: 2분할(60:40) — 좌 결제 폼(카드번호 / 만료+CVV(한 행 분할) / 이름, 각 라벨+인풋) / 우 주문 요약(아이템 2~3 + 합계 + 결제 CTA 풀폭)
- **흔한 실수**: 요약이 좌측(폼이 주 행동, 요약은 보조) / 결제 CTA가 폼 쪽에 있음

### Reviews
- **구조**: 카드: 타이틀(+평균 별점) → 리뷰 행 3~4: 아바타 → 이름/날짜 → 별점(**채워진 별과 빈 별 구분**) → 본문 1~2줄

### Product Card (단품)
- **구조**: 이미지 → 상품명 → 보조 정보 → 가격 → CTA 풀폭. 호버 시 이미지 스왑/퀵액션은 선택

## 페이지 유형 → 블록 시퀀스 템플릿

시퀀스는 시작점이지 강제가 아닙니다. 프로젝트 신호에 따라 블록을 빼고 더하되,
**Navbar와 Footer 사이의 서사**(문제 인지 → 신뢰 → 전환)가 끊기지 않게 하세요.

| 페이지 유형 | 기본 시퀀스 | 비고 |
|------------|------------|------|
| SaaS 랜딩 | Navbar → Hero → Logos → Feature → Stats → Testimonial → Pricing → FAQ → CTA → Footer | Stats/Logos는 근거 없으면 생략. 섹션 높이는 변주 |
| 제품 랜딩(단품) | Navbar → Hero → Feature → Testimonial → Pricing(단일) → FAQ → CTA → Footer | Pricing 1카드면 반전 강조 불필요 |
| 포트폴리오/에이전시 | Navbar → Hero → Gallery → Feature(서비스) → Team → Testimonial → Contact → Footer | Gallery가 주인공, Hero는 짧게 |
| 이커머스 홈 | Navbar(+Banner) → Hero(프로모) → Product List → Reviews → CTA → Footer | 필터가 주 행동이면 Faceted Directory 모드 우선 |
| 이커머스 상세 | Navbar → Product Detail → Reviews → Product Card 행(연관) → Footer | |
| 이커머스 구매 | Navbar(축소) → Shopping Cart 또는 Checkout → Footer(축소) | 구매 플로우에서 마케팅 블록 금지 |
| 앱 대시보드 | Sidebar + (타이틀 → Stats/KPI → Chart+리스트 → Data Table) | coder-interface playbook의 Data Instrument 계약 우선 |
| 앱 설정 | Sidebar + Settings | |

## 청사진(blueprint) 산출 절차

구현 전에 블록 시퀀스와 anatomy를 텍스트 청사진으로 고정합니다. 산출물은 표 + ASCII 스케치:

```
## Layout Blueprint — {페이지명}

| # | 블록 | anatomy 체크 | 변주 (VARIANCE 반영) |
|---|------|-------------|---------------------|
| 1 | Navbar | 로고/링크4/CTA1 | 스크롤 시 blur 전환 |
| 2 | Hero | eyebrow/헤드라인2줄/서브/CTA쌍/미디어 | 좌정렬 + 우측 미디어 오프셋 |
| 3 | Feature | 타이틀/카드6(아이콘+타이틀+2줄) | 2-4 비대칭 그리드 |
| ... | | | |

+----------------------------------+
| LOGO   nav nav nav nav    [CTA]  |   <- Navbar
+----------------------------------+
| badge                            |
| HEADLINE LINE 1                  |   <- Hero (좌정렬)
| HEADLINE LINE 2      [media]     |
| subtext              [media]     |
| [CTA] (cta2)                     |
+----------------------------------+
```

- 체크 열에는 이 카탈로그의 필수 요소를 축약 표기 — 누락이 바로 보이게
- 변주 열에는 DESIGN.md 프리셋(VARIANCE/DENSITY)에 따른 배치 변형을 명시
- 인터랙티브 세션이면 이 청사진을 사용자에게 확인받고, 자동 파이프라인(zeus 등)이면 산출만 하고 진행
- 저장 위치: `docs/design-refs/YYYY-MM-DD-layout-{slug}.md` (Phase 2 슈퍼프롬프트와 동일 디렉터리)
