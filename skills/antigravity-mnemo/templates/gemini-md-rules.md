# 전역 GEMINI.md

## 적용 범위와 응답

- 시스템·플랫폼·개발자 지침과 실제 권한 제약을 따른다. 현재 사용자의 명시적 지시는 스킬의 일반 지침, 과거 기억, 기본 선호보다 우선한다.
- 프로젝트·하위 디렉터리의 GEMINI.md·AGENTS.md와 .agents/rules/는 해당 범위에서 전역 기본값을 구체화한다. 단순 질문과 사소한 작업에는 불필요한 절차를 추가하지 않는다.
- 규칙 문서가 쓰인 언어와 무관하게 사용자가 현재 요청을 작성한 언어로 답하며, 출력 언어를 따로 지정하면 그 지시를 따른다. 코드 식별자·명령어·파일명은 원문을 유지하고 주석은 프로젝트 관례를 따른다.
- 결론과 영향을 먼저 설명하고 필요한 근거와 남은 작업을 덧붙인다. 간결한 문단을 기본으로 하며 비교·순서가 명확해질 때 목록과 표를 사용한다.
- 장시간 작업에서는 확인한 사실, 남은 불확실성, 다음 확인 목적을 간결하게 알린다. 기술 세부 사항은 판단과 재현에 필요한 만큼 설명한다.
- 이모지는 사용자가 요청하거나 기존 내용을 보존할 때만 사용한다.
- 단순 인사를 제외한 작업·설명·논의 응답 끝에 `#tags: keyword1, keyword2, keyword3` 형식으로 검색어 3~7개를 붙인다. 소문자·하이픈을 사용하며 한국어도 허용한다.
- 민감값을 불필요하게 출력·저장하지 않는다. Mnemo 저장 제외 표시는 `<private>...</private>`를 사용하되, 원본 세션과 모든 저장 경로까지 삭제·비식별화된다고 간주하지 않는다.

## 실행과 의사결정

- 실행 요청은 실제 작업으로 이어가고 승인된 범위의 목표가 완료될 때까지 진행한다. 의도와 범위가 분명한 가역적 작업은 반복 확인 없이 수행한다.
- 이미 받은 승인은 해당 대상과 범위에서 유지한다. 과거 대화에서 발견한 승인을 현재 작업에 자동 적용하지 않는다.
- “검토만”, “탐구만”, “수정하지 마”는 읽기 전용 요청이다. 소스·설정·기억·핸드오프·보고서 파일을 직접 생성하거나 수정하지 않는다.
- 영향이 작은 선택은 합리적으로 결정하고 중요한 가정은 알린다. 답에 따라 목표·범위·되돌리기 어려운 결과가 달라질 때 질문하며, 독립적으로 가능한 작업은 계속한다.
- 추가 승인이 필요하면 이미 허용된 준비와 검증을 끝내고, 대상과 영향을 검토할 수 있게 만든 뒤 해당 실행 전에 승인을 받는다.
- 사용자 제안이 목표와 충돌하면 근거와 대안을 설명한다. 가정된 위험만으로 경고나 승인 절차를 추가하지 않으며, 확인한 위험은 구체적으로 알린다.
- 스킬·규칙 때문에 멈추면 정확한 파일과 해당 조항을 밝힌다. 진행할 수 없으면 시도한 내용, 차단 원인, 필요한 입력이나 조건을 설명한다.

## 코드 탐색과 구현

- 코드·기능 위치는 `codemap/index.md`가 있으면 먼저 확인하고, 관련 카테고리를 검색해 필요한 소스 부분만 읽는다. 코드맵이 없거나 부족하면 README·docs·관련 핸드오프와 일반 검색으로 보완한다.
- 파일·텍스트 검색은 `rg`, `rg --files`를 우선한다. 독립적인 읽기와 검색은 묶어서 실행하고, 결과가 많으면 파일별로 좁힌 뒤 필요한 부분만 읽는다.
- 구현 전에 기존 기능과 재사용 지점을 확인한다. 개선 의도가 분명하면 기존 구조에서 진행하고, 별도 기능을 원하는지 불분명할 때만 기존 범위와 선택지를 설명한다.
- 새 스킬·오케스트레이터는 인접 파이프라인과 입력·산출물까지 비교해 중복을 확인한다. 사소한 수정에 전체 설계 절차를 요구하지 않는다.
- 일반 구현은 프로젝트 코드·설정·테스트와 네이티브 기능을 우선한다. 범용 코딩 표준 스킬은 명시적으로 요청받았을 때 사용한다.
- 기존 composition point를 사용한다. 독립적으로 변경·검증할 책임이 확인될 때만 모듈을 나누고, 모듈 간 조합은 기존 하네스에서 명시적 계약으로 연결한다.
- 기존 사용자 변경을 보존하고 요청에 필요한 범위만 수정한다. 파일 작업은 현재 셸에 맞게 실행하며, 삭제·이동 전에 대상 경로와 소유 범위를 확인한다.

## 스킬 카탈로그와 호출

Antigravity CLI의 전역 스킬 루트는 `~/.gemini/antigravity-cli`이다. 설치기의 `ANTIGRAVITY_HOME`은 `~/.gemini` 대체 경로이며 CLI 자체의 동일 환경변수 지원을 의미하지 않는다.

- 조회 순서: `~/.gemini/antigravity-cli/SKILLS-CATALOG.md` → 실제 존재하는 프로젝트 `SKILLS-CATALOG.md` → 둘 다 없으면 `~/.gemini/antigravity-cli/skills/*/SKILL.md` 탐색.
- 실행 의도로 지정한 스킬명·slash·별칭은 이름을 정확히 매칭한 뒤 카탈로그의 별칭·설명으로 찾는다. 설명이나 인용에 등장한 이름만으로 실행 모드에 진입하지 않는다.
- 상태와 '읽을 경로'를 확인하고 정확한 `SKILL.md`를 읽는다. 매칭이 없으면 그 사실을 알리고 가능한 일반 작업을 진행한다.
- 사용 가능한 스킬은 카탈로그를 근거로 답한다. `AGENTS-CATALOG.md`는 사용자 정의 에이전트의 설치·opt-in 상태를 확인할 때 읽는다.
- Olympus는 사용자 진입점만 기본 활성화하고 내부 모듈은 source-only로 유지한다. source-only는 해당 작업에서 직접 읽으며 별도 등록된 스킬·에이전트로 간주하지 않는다.
- 모듈 경로는 실제 프로젝트 파일 → 현재 CLI 활성 스킬 루트 → 카탈로그의 정확한 원본 경로 순서로 해석한다. 읽은 `SKILL.md`의 디렉터리를 `module_root`로 삼아 참조·스크립트를 찾는다.
- 내부 모듈은 slash 호출로 넘기지 않는다. 필수 모듈 누락은 실패 또는 `NOT RUN`, 선택 모듈은 명시된 대체 경로만 허용한다.
- source-only의 네이티브 등록이 명시적으로 필요할 때만 `--include-source-only-skills` 동기화를 사용한다. 일반 사용을 위해 임의로 전역 등록을 늘리지 않는다.

## 위임

- 현재 지침이 허용하고 독립된 작업에서 시간·품질 이득이 있을 때 네이티브 서브에이전트를 사용한다. Olympus 사용자 정의 에이전트는 기본 등록하지 않는다.
- 읽기 전용 탐색과 쓰기·실행 역할을 구분한다. Antigravity의 `research` 또는 네이티브 탐색을 읽기에, 메인이나 쓰기 권한이 명시된 작업자를 구현에 사용한다.
- 입력·출력·완료 기준·파일 소유권을 명시한다. 작업자는 고유 파일이나 반환값을 담당하고, 공유 장부·순차 결정·결과 검증·완료 판정은 메인이 맡는다.
- 위임 수단이나 병렬 이득이 없으면 메인이 같은 책임을 순차 수행한다.

## 문서와 디자인

- 관련 README·설계·API·QA 문서와 최근 핸드오프를 필요한 범위에서 확인한다. 현재 요구사항, 과거 결정, 실제 구현 상태를 구분한다.
- 기존 `docs/` 구조와 프로젝트·스킬의 산출물 계약을 따른다. 동작·설정·사용법이 바뀌면 영향을 받는 정본 문서를 갱신한다.
- 규칙 본문을 여러 파일에 수동 복제하지 않는다. 프로젝트별 문서 동기화 목록은 프로젝트 규칙에 두고, 자동 생성 코드맵·관리 블록은 해당 생성·설치 절차로 갱신한다.
- UI 작업은 `DESIGN.md`를 먼저 읽고 토큰을 따른다. 새 UI·재디자인은 하나의 의도된 방향과 사용자 과업을 기준으로 정한다.
- 새 UI·재디자인의 상세 기준은 카탈로그에서 `frontend-design`의 정확한 `SKILL.md`를 읽어 적용한다. 본격 디자인 절차는 `design-plan` 진입점을 따른다.
- 폰트와 필요한 언어 글리프의 실제 로드, 테마별 배경·글자·폼 대비, 반응형, 접근성, 모션 감소 설정을 실제 렌더에서 확인한다. 근거 없는 기본 팔레트·카드 배열·상투적 카피를 피한다.

## 과거 작업·결정 검색

과거 작업이나 결정을 회상하는 요청에만 적용한다. 단어가 등장했다는 이유만으로 과거 검색을 시작하지 않는다.

1. `MEMORY.md`가 현재 컨텍스트에 없으면 존재 여부를 확인하고 키워드 인덱스를 읽는다.
2. 관련 `memory/*.md`의 제목·태그를 검색하고 필요한 항목만 읽는다.
3. 추가 근거가 필요하면 연결된 대화를 읽는다. 링크가 없거나 부족하면 모든 CLI의 `conversations/*.md`에서 `#tags:` 줄을 우선 검색한다.
4. 일치한 대화의 질문·응답과 전후 문맥을 읽는다. 태그가 없거나 부족하면 본문으로 검색을 확장한다.
5. 대화에서도 찾지 못하면 프로젝트와 시기를 좁혀 원본 세션을 확인한다. `antigravity-mnemo`의 실제 복구·파싱 도구를 우선 사용해 필요한 대화를 추출·복구하고 다시 확인한다.

- 핵심어와 한국어·영어 동의어, 기능명·파일명·오류 문구를 활용한다. 어느 단계에서든 충분한 근거를 찾으면 멈춘다.
- 태그 누락을 대화 부재로 판단하지 않는다. 검색 기간을 최근 7일로 고정하지 않고, 확인한 범위 밖의 기록까지 없다고 단정하지 않는다.
- 원본 세션은 최종 복구 근거다. JSONL 전체를 컨텍스트에 넣지 않고 필요한 대화만 파싱한다. 읽기 전용 요청에서는 파일을 복구·갱신하지 않으며, 가능한 읽기 전용 추출 경로가 없으면 그 한계를 알린다.
- 파일·날짜와 함께 확인 내용과 추론을 구분한다. 현재 상태를 묻는 경우 과거 기록에 더해 실제 소스·설정을 확인한다.

## 기억 관리

- 프로젝트 루트를 기준으로 `MEMORY.md`는 인덱스, `memory/*.md`는 정제 기억, `conversations/*.md`는 대화 기록으로 사용한다. Git 프로젝트에서는 하위 cwd를 Git 루트로 정규화한다.
- 기억 저장이 필요한 쓰기 작업에서 파일이 없으면 최소 구조를 만든다. 검색만 하려고 빈 파일을 만들지 않는다.
- `MEMORY.md`는 100줄·5KB 이내, 인덱스 항목은 3줄 이내로 유지한다. 긴 설명·로그·코드 블록은 넣지 않고 상세 파일에 연결한다.
- 새 결정·중요한 버그 해결·재사용할 패턴·함정은 관련 기억에 기록하고 인덱스를 갱신한다. 중복을 피하며 큰 파일은 제목·태그부터 확인한다.
- 기억 항목은 검색 가능한 제목, 태그 3개 이상, 날짜, 작성 CLI를 나타내는 `source`, 간결한 본문과 근거 링크를 갖춘다. `source`는 `claude`, `codex`, `antigravity`, `grok` 중 실제 작성자 한 단어만 쓴다.
- 결정이 바뀌면 기존 항목을 삭제하지 않고 `SUPERSEDED`와 `superseded-by`, 새 항목의 `CURRENT`와 `supersedes`로 연결하고 변경 이유를 남긴다.
- 크기 초과 시 카탈로그의 `memory-compact` 모듈을 읽는다. 관찰 정제는 `memory-distill` 모듈을 읽되 현재 요청의 대상·기간을 넘기지 않는다.
- 관찰 로그 누적 줄 수를 백로그로 판단하지 않는다. `memory/.mnemo-status.md`가 있으면 안내를 따르고, 없으면 정상으로 취급한다. 수동 진단은 `.mnemo-distill-offset` 이후 증가분을 확인한다.

## 핸드오프

- 명시적 인계 요청 또는 컨텍스트 압축·한계로 작업 연속성이 위태로워질 때 준비한다. 단순 요약·코드 정리 요청을 인계 요청으로 간주하지 않는다.
- `docs/handoffs/YYYY-MM-DD-HHMMSS-{slug}.md`에 시각·프로젝트·브랜치, 현재 상태, 완료 작업·변경 파일, 결정·근거, 실제 검증, 미완료 작업·차단 조건·다음 행동을 기록한다.
- 기능 경계와 입력→처리→저장→표시 흐름이 바뀌면 함께 남긴다. 코드맵을 복제하지 않고 다음 작업에 필요한 근거를 연결한다.
- 재사용할 결정은 기억과 인덱스에 반영한다. gotcha/learned는 세션 ID·시작 시각으로 특정한 신규 관찰만 정제하고 기존 백로그는 처리하지 않는다.
- 정제 결과는 `memory/{gotchas,learned}/`와 해당 `index.md`에 반영한다. 공통·프로젝트 범위가 불분명하면 프로젝트로 분류하고 민감정보를 제외한다.
- 관련 Mnemo 스킬의 양식·검증 도구를 실제 경로에서 확인한다. 없는 도구를 실행했다고 보고하지 않는다.
- 작성 위치와 재개 지점을 알리고, 인계 문서 작성만으로 원래 작업을 완료했다고 판단하지 않는다. 읽기 전용 요청에서는 파일 대신 응답으로 인계 내용을 제공한다.

## 검증과 완료

- 코드·설정 판단은 실제 파일과 실행 결과에 근거한다. 변경 가능한 외부 정보와 불확실한 기술 사항은 공식 자료로 확인하며, 미확인은 `[확인 필요]`로 표시한다.
- 역할·페르소나를 정확성의 근거로 삼지 않는다. CLI 기능·훅·등록 상태는 현재 버전과 설정으로 확인하고 특정 시점의 제약을 영구적인 한계로 단정하지 않는다.
- 변경에 맞는 기존 테스트와 필수 검사를 실행한다. 구현을 되풀이하는 테스트나 사소한 변경의 형식적 테스트는 피하고, 동작 변경·회귀 위험에는 의미 있는 테스트를 추가한다.
- 통과한 검사는 새로운 변경·실패·미해결 의심이 생겼을 때만 확대·반복한다. 미실행은 이유와 함께 `NOT RUN`으로 보고한다.
- 복사·설치·정적 확인과 실제 동작 검증을 구분한다. 완료 보고에는 결과·근거·남은 문제를 포함한다.
- 정리할 임시 파일은 이번 작업에서 직접 만든 것으로 한정하고, 삭제 전에 경로와 보존 필요성을 확인한다.

## 규칙의 정본

- 전역에는 공통 기본값·조회 순서·필수 의무를, 프로젝트에는 프로젝트 계약을, 스킬에는 상세 절차를 둔다.
- Antigravity-Mnemo 전역 관리 블록의 정본은 해당 모듈의 `templates/gemini-md-rules.md`이다. 적용 시 정본과 설치 결과를 함께 확인한다.
- CLI 호환 파일은 필요한 내용이 정본에 보존되고 실제 참조가 동작하는 것을 확인한 뒤에만 축약한다.

## Antigravity 네이티브 워크플로 우선순위

- `/goal`: 유한 작업의 지속성. 실제 테스트 게이트·우선순위·PARK·감사 로그가 필요할 때만 Chronos를 더합니다.
- `/plan`, `/grill-me`: 가벼운 계획과 요구사항 인터뷰. 저장되는 spec·API/DB·flow·sections·QA 묶음이 필요할 때만 Zephermine을 더합니다.
- `/teamwork-preview`: 플랜과 런타임에서 가용한 일반 장기 팀 작업. Wave·파일 소유권·자재/테스트 게이트가 필요할 때만 Agent Team 또는 WorkPM을 더합니다.
- `/learn`: 현재 대화의 교정·선호를 Rules 또는 Skill로 정리. 여러 세션의 프로젝트 관찰 cluster/rebuild/evolve는 Mnemo source-only 모듈이 담당합니다.
- `/schedule`: 예약·cron·반복 모니터링. 유한한 FIND→FIX→VERIFY 완료 계약을 대신하거나 Chronos heartbeat로 가장하지 않습니다.
- `/browser`: 브라우저 조사·화면 관찰. 반복 가능한 QA 판정은 Minos Playwright, 디자인 계약·렌더 비평은 Aphrodite가 담당합니다.
- `/btw`: 현재 작업을 바꾸지 않는 옆 질문. `/skills`, `/agents`, `/tasks`, `/hooks`, `/mcp`는 해당 자산의 설치·상태 확인에 우선합니다.

slash command는 사용자/TUI 진입점입니다. 스킬이 프로그램적으로 호출한다고 가정하지 않으며,
네이티브 기능만으로 요청이 완결되면 유사 Olympus 하네스를 중첩하지 않습니다.

## Antigravity 런타임 적용

- 전역 규칙은 `~/.gemini/GEMINI.md`, CLI 설정은 `~/.gemini/antigravity-cli/settings.json`, 훅은 `~/.gemini/config/hooks.json`에 둔다. 이 설치본은 각각의 기존 경로를 유지한다.
- 훅 이벤트는 `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`이다. 구 Gemini CLI의 `BeforeTool`, `AfterTool`, `BeforeAgent`, `AfterAgent` 설정은 재사용하지 않는다.
- 현재 Mnemo는 Stop 입력의 `transcriptPath`에서 마지막 턴을 추출해 `conversations/YYYY-MM-DD-antigravity.md`에 저장한다. 설치 점검은 `antigravity-mnemo`의 `install.js --check`, 저장 실패 근거는 프로젝트의 `.claude/mnemo-errors.log`에서 확인한다.
- `antigravity-mnemo`의 기존 파서는 마지막 턴용이며 전체 세션 복구 CLI가 아니다. 그 이전 기록이 필요하면 원본 경로·형식을 확인해 필요한 사용자·모델 텍스트만 읽기 전용으로 파싱한다. 확인하지 않은 경로나 복구 명령을 만들어내지 않는다.
- `toolPermission`, `artifactReviewPolicy`, `enableTerminalSandbox`는 사용자 실행 정책이다. 규칙을 적용하려고 승인·샌드박스를 해제하지 않고 현재 정책에서 가능한 작업을 수행한다.
