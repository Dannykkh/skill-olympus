# 커피 앱 와이어프레임 판단 기록

## 범위와 근거

- 목적: 근처 카페의 커피를 찾아 장바구니에 담기.
- 사용자 제공 비교 이미지: `.termsnap/snapshots/clipboard_20260929_095506_062.png`. 비교 이미지의 와이어프레임에는 최종 시안의 주 행동인 `Order Now`가 나타나지 않았다.
- 이 문서와 화면은 아프로디테 절차 검증용 예시다. 카페 이름·메뉴·가격·배달 위치는 시연용 샘플이며 실제 서비스 사실을 뜻하지 않는다.
- 주문 확정과 결제는 이번 과업 범위 밖이다.

## 볼 수 있는 산출물

- [모바일 3단계 PNG](2026-09-29-wireframe-coffee-mobile.png): 홈 → 메뉴 → 장바구니.
- [데스크톱 홈 PNG](2026-09-29-wireframe-coffee-desktop.png): 동일한 우선순위의 넓은 화면 변환.
- [HTML 원본](2026-09-29-wireframe-coffee-demo.html): 메뉴 이동·상품 담기·품절 대체 링크를 확인하는 최소 상호작용.

회색 블록은 사진 자리만 나타낸다. 메시지·상품명·가격·행동에는 실제 샘플 문구를 사용했다. 요소별 그림 파일이나 브랜드 색은 사용하지 않았다.

## 정보 구조와 과업 흐름

| 순서 | 화면 | 사용자의 질문 | 다음 행동·피드백 |
|---|---|---|---|
| 1 | 홈 | 여기서 무엇을 할 수 있나? | 제목과 `메뉴 보기`, 검색, 종류별 보기, 빠르게 담기 |
| 2 | 메뉴 | 어떤 커피를 고를 수 있나? | 상품명·카페·가격을 보고 `담기`; 품절이면 `비슷한 메뉴`로 대체 상품 찾기 |
| 3 | 장바구니 | 제대로 담겼나? | 담긴 상품명·수량·가격과 상태 문구 확인; 메뉴로 돌아가기 또는 다음 주문 단계 인지 |

홈의 `담기`는 장바구니로 바로 이어지는 빠른 경로다. 홈의 `메뉴 보기`는 비교·탐색 경로다. 두 경로 모두 장바구니의 완료 상태로 합쳐진다.

## 다섯 기준의 판단

| 기준 | 렌더에서 확인한 근거 | 결정 |
|---|---|---|
| 위계 | 모바일 첫 화면에 과업 제목, 검색, `메뉴 보기`가 모두 보인다. 사진 자리는 그보다 약하다. | 주 행동을 회색 플레이스홀더에 숨기지 않는다. |
| 구조 | 홈에서 탐색·종류·빠르게 담기를 제공하고, 메뉴에서 상품을 비교한 뒤 장바구니에서 결과를 확인한다. | 프로모션·특가 블록은 이번 과업에 필요하지 않아 제외한다. |
| 흐름 | 홈→메뉴→장바구니 링크와 홈→장바구니 빠른 경로가 있다. 품절 상품은 `담기` 대신 대체 상품 링크를 제공한다. | 품절을 빈 버튼이나 막다른 길로 표현하지 않는다. |
| 일관성 | 모바일 세 화면의 하단 탐색이 같고, 상품의 `담기`는 같은 아웃라인 버튼으로 표시한다. | 장바구니에 없는 `주문` 탭을 넣지 않는다. |
| 명료성 | 상품명·카페·가격·품절 이유·담기 결과를 읽을 수 있다. 이미지만 자리 표시로 남겼다. | 의미 있는 문구를 무의미한 회색 막대로 바꾸지 않는다. |

## 데스크톱 변환

| 모바일 요소 | 데스크톱 처리 | 이유 |
|---|---|---|
| 하단 3항목 탐색 | 상단 메뉴와 장바구니 행동으로 이동 | 넓은 화면에서 현재 위치와 장바구니를 상단에서 찾기 쉽다. |
| 세로 홈 콘텐츠 | 종류별 보기와 빠르게 담기를 나란히 배치 | 홈의 주 행동과 상품 정보가 첫 화면에 남는다. |
| 헤더 아래 검색 | 콘텐츠 시작 부분의 검색으로 유지 | 탐색 진입점을 놓치지 않는다. |
| 히어로의 주 행동 | 같은 문구와 목적지 유지 | 화면 폭이 바뀌어도 과업은 같다. |

## 확인 결과와 한계

- Chrome에서 HTML을 렌더하고 모바일 3단계(1342×822)와 데스크톱(1320×720)을 실제 PNG로 캡처해 눈으로 확인했다. 주요 문구·행동·하단 탐색이 잘리지 않았다.
- Selenium에서 홈의 `아이스 라테 → 담기`를 실행해 장바구니의 상품명 `아이스 라테`, 가격 `₩4,800`, 목적지 `#cart-screen`을 확인했다. 품절 메뉴의 대체 링크는 `#iced-latte-option`으로 이동했다.
- 검색어 입력, 카테고리 필터, 주문 확정은 배치만 표시한 와이어프레임 단계이며 기능 검증 대상이 아니다. 장바구니 화면은 상품을 담은 뒤의 대표 상태로 그렸다.
- 다섯 기준은 화면과 클릭 경로를 근거로 자체 검토했다. 실제 사용자 테스트 결과로 해석하지 않는다.
