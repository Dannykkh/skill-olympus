# Olympus: 조사·권장안 우선 설계와 종료·재개 계약 보완

2026-10-28 · Codex

사용자는 도메인 지식을 다른 LLM에 조사시키는 기존 Olympus 방식에 맞춰, AI가 조사 근거와 권장 설계를 먼저 제시하고 꼭 필요한 사용자 결정만 묻도록 요청했다. 긴 인터뷰·새 승인 단계를 더하는 방향은 채택하지 않았다. 이전 Superpowers 개선에 이어 실제 계약 모순과 연결 누락을 보완했다.

## 변경

| 대상 | 변경과 목적 |
|---|---|
| Zephermine | Step 6·11·Soft Gate·재개가 같은 답변과 질문 예산을 이어받는다. 근거 → 권장안·이유 → 제약 → 남은 결정을 제시하며 요약마다 재승인을 묻지 않는다. 반복 5 Whys·없다고 답한 연동/기술 이슈의 재질문 지시를 제거했다. |
| 도메인 검토 | 전문가는 자료·사실·가정·추천·제약을 구별한다. 여러 모델의 합의를 회사 정책의 증거로 삼지 않는다. 사용자가 모르는 내부 사실은 미해결로 두고 독립 설계는 계속한다. |
| Daedalus 공통 command | 기존 코드·자료로 해소할 사실을 먼저 조사하고 권장안을 제시한다. 선행 결정, 기존 답변과 대기 질문을 활동 로그에서 재사용한다. 네이티브/MCP는 같은 정본을 따른다. |
| Zeus | Argos Phase 0~8·Minos Step 1~7을 현재 계약과 맞추고 최종 등급·탐색 QA·미실행·수리 이력을 함께 집계한다. 자동 테스트 100%가 Minos FAIL을 지우지 못하며, phase·worker·재개가 이슈 예산을 초기화하지 않는다. |
| Zeus 상태 | 프로젝트 루트의 정본을 먼저 찾고 확인된 구경로 원본을 보존해 복구한다. 진짜 상태 충돌은 두 파일을 보존하고 BLOCKED. 초기 실행 불가도 미실행 사유를 남긴 종결 보고를 허용한다. |
| Chronos | Complete는 전부 proved와 검증 PASS, Blocked는 주차로 인한 미완 종료, Exhausted는 상한 소진으로 구별한다. 실제 훅/notify에 비성공 종료를 연결하고 기계적 3회 반복·의무 모델 상향을 제거했다. 상한은 유지한다. |
| Zeus → Chronos | 진행 가능한 작업·원래 예산이 없으면 이번 Zeus가 만든 fallback만 비성공 신호로 종료한다. 사용자 기존 루프·native goal은 원래 정책을 따른다. |
| autoresearch·skill-evolve | 개선 위치를 검사/연결·탐색·판단으로 먼저 나눈다. 호출·참조 문제를 바꿀 때만 실제 카탈로그/상위 하네스에서 진입 시험을 한다. 본문 수행 시험을 실제 호출 성공으로 보고하지 않는다. |

기존 완료 기준 장부·로그·인터뷰 기록을 재사용했다. 새 스킬·전역 등록·프로토타입 의무·질문지·전면 TDD 절차는 추가하지 않았다. 이번 작업에서 Argos·Minos 자체는 앞선 개선을 유지했고 Zeus가 그 결과를 정확하게 소비하도록 바꿨다.

## 실제 검증

- 설치·라우팅·portable frontmatter·완료 기준·트립와이어·역할 정책: 기존 검사 **71/71 PASS**.
- Chronos: 소스 실행 경로 7개 × 6사례 **42/42 PASS**. Claude Bash/PowerShell 7/Windows PowerShell, Codex Bash/PowerShell 7/Windows PowerShell, Antigravity Node 경로를 실행했다.
- 설치 후 같은 7개 경로 **42/42 PASS**. 완료·주차·진행·단순 마커 언급·완료 promise·반복 상한을 확인했다. Codex는 `CHRONOS_DRY_RUN`으로 실제 재개 프롬프트 생성까지 검사하고 CLI 재실행은 하지 않았다.
- Claude Windows PowerShell transcript 읽기의 기본 인코딩 문제를 시험에서 발견해 `Get-Content -Encoding UTF8`로 수정했다.
- 6개 변경 스킬 `quick_validate.py` PASS, `git diff --check` PASS. 최종 설치 변경 파일 **48/48 해시 일치**, 6개 ZIP CRC PASS를 확인했다. 마지막 Zeus 수정 후 관련 계약도 **22/22 PASS**였다.

### 젭마인 비교

같은 두 입력을 수정 전/후 각각 새 문맥에서 수행했다. 실행자에게 평가 기준·기대 답변·다른 결과는 주지 않았고 메인이 실제 응답과 기록을 검토했다. 동일 기본 모델을 사용했지만 독립 채점자나 비공개 holdout은 아니므로 일반 성능 향상의 증거로 삼지 않는다.

| 사례 | 수정 전 | 수정 후 |
|---|---|---|
| 승인된 구매요청 설계 | 추가 질문 0, 기존 방향 유지 | 추가 질문 0, 기존 방향 유지, 제약을 응답에 명시 |
| 사용자도 모르는 계약별 정산 규칙 | 재질문 0, 가정/회사 정책 구분, 독립 설계 진행 | 재질문 0, 같은 경계 유지, 단계 간 누적 질문 3/3 보존 명시 |

두 사례 모두 핵심 안전·진행 경계가 유지되었다. 사용자 응답 길이는 각각 **557→722자**, **531→776자**로 늘었다. 따라서 질문 수·소요 시간 감소를 입증했다고 주장하지 않는다. 이번 채택 근거는 사용자 요구와 충돌하던 하위 인터뷰 지시를 정리한 것이며 자동 최적화의 승리로 기록하지 않는다.

### Zeus 격리 수행

제공된 실행 기록을 입력으로 최종 보고·상태 복구를 수행한다. 실제 제품 테스트를 재실행한 시험이 아니다. 초기 3사례는 자동 테스트 12/12와 Minos FAIL/예산 2/2, 구경로 단독 상태, 서로 다른 두 상태다.

구경로 복구 후 정본만 진행되면 다음 재개에서 옛 파일을 충돌로 오인하는 결함을 검토 중 발견했다. 기존 로그에 복구 경로·원본 해시·실행 식별 근거를 남기고, 일치하는 보존 원본만 제외하도록 보완했다. 초기 3사례와 추가 2사례 **5/5 PASS**: 실패/소진 보존, 구경로 원본 보존 복구, 실제 충돌 보존, 유효 복구 기록이 있는 재개, 구원본 해시 변경 시 BLOCKED를 확인했다. 추가 2사례의 복구 기록은 메인이 구성한 입력이며 비공개 holdout은 아니다. 최종 결과는 [실행 근거 JSON](2026-10-28-olympus-proposal-first-evidence.json)에 기록한다.

## 설치와 한계

정본은 `skills/`이며 Claude·Codex·Antigravity 관리 설치본에 반영했다. Grok은 Claude 공유 표면을 사용한다. source-only 등록 정책은 유지했다. 기존 사용자 ZIP 14개는 보존하고 이번 6개 패키지는 임시 근거 디렉터리의 `packages/`에 작성했다.

실제 네 CLI의 전체 제품 생성 파이프라인·브라우저 E2E·native goal 동작은 **NOT RUN**이다. 설치 파일 일치와 훅 실행을 그 인증으로 주장하지 않는다. Codex PowerShell stdin fallback의 기존 Unicode 선행 디코딩 한계는 이번에 변경하지 않았고 실제 notify의 payload 파일 인자 경로를 검증했다.

## 2026-10-29 릴리즈 전 보완

추가 감사에서 다중행 정규식이 진행 보고의 코드 예제·후속 소제목을 Blocked 종료로 오인하는 문제를 발견했다. 7개 실행 경로 × 2사례를 실제 실행해 수정 전 14/14 실패를 재현했고, 첫 비어 있지 않은 줄의 명시 헤더만 판정하도록 수정한 뒤 전체 56/56이 통과했다. 정상 종료는 선행 빈 줄·공백 줄·CRLF·한글 헤더도 처리한다.

이 검사는 앞선 42사례에 빠졌던 본문 예제의 회귀를 추가한 것이다. 기존 검증 이력은 그대로 남기며 최종 설치·릴리즈 검사 결과는 근거 JSON의 `release_followup`과 CHANGELOG에 기록한다. 공개 본문에서 불필요한 로컬 사용자 경로와 세션 식별자를 제거했으며 원시 근거는 로컬에 보존했다.
