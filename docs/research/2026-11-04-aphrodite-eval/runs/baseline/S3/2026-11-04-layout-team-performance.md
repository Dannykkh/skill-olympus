## Interface Mode (Phase 2-4)

- 선택: **Data Instrument** — 화면의 가치가 "숫자 변화와 비교"(playbook 1절 빠른 판별 1번). Faceted Directory(후보 축소)·Waiting State(기다림)가 아님
- playbook 정보 구조 대응: Utility header(좌측 내비 + 제목) → Primary query/action(기간 선택) → Compact KPI strip(3장) → Fast movers/anomalies(지금 기한 지난 할 일 카드 + 서랍) → Dense comparison table(프로젝트별 표) → Freshness + provenance(집계 시각·지표 정의, KPI 위로 올림)
- 효과 예산: 장식 효과 **0**, 상태 모션만(서랍 열기·정렬 전환·skeleton, 150~300ms), 숫자 카운트업 금지, 가장 무거운 구현 단계 A(CSS)
- DENSITY: medium(`DESIGN.md` "밀도는 중간"). 표 행 52px, 숫자는 우측 정렬·`tabular-nums`
- STATE MODEL: loading / empty(A) / early(B) / error(C) / stale / permission(D) / success — experience 초안 `States` 표

## 역할별 화면 처리 (Phase 2-5 결정, 4-1-1에서 변형표로 상세화)

spec 시스템 역할 표: `owner`·`member` 모두 `화면: 공용 권한차등`. 요소별 노출을 이 단계에서 정합니다(어휘는 `operation-scenarios.md`가 없어 SKILL.md 4-1-1의 `표시/숨김/비활성/읽기전용`을 가정으로 사용).

| 요소 | owner | member |
|---|---|---|
| 좌측 내비 `팀 성과` 항목 | 표시 | 숨김 |
| 팀 성과 화면 전체(KPI·차트·표·서랍) | 표시 | 숨김 — 주소 직접 접근은 진입 차단 안내(상태 시트 D) |

- 비활성이 아니라 숨김인 이유: member가 이 화면을 얻는 경로(권한 요청 흐름)가 없어서, 존재를 알려도 할 수 있는 행동이 없음
- 역할을 지웠을 때 비는 화면 확인: member가 주소로 들어오면 화면이 비지 않고 `홈으로 가기` 1개 행동이 남음(D에서 확인)
- owner가 전권 기준 화면이므로 별도 변형표 불필요

시각 시안에서 처음 생긴 주 행동이 없도록, 이 화면의 행동은 위 다섯 가지(기간 선택, 기한 지난 할 일 보기, 보드 열기, 다시 시도, 활성화 단계)로 고정합니다. Phase 3 후보가 이 중 하나를 바꾸거나 새 행동을 더하면 이 게이트로 되돌아옵니다.
