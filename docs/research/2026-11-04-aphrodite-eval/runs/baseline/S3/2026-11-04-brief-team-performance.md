# Design Brief — 팀 성과 탭

- 작성일: 2026-11-04
- 요청 원문: «/aphrodite --plan-only 관리자 웹의 설정 화면 옆에 '팀 성과' 탭을 추가해서 KPI 카드랑 추세 그래프로 디자인해줘.»
- 실행 범위: Phase 0~2 (저충실도 와이어프레임 판단 게이트까지). Phase 3 렌더 방향 탐색·시각 시스템, Phase 4 계약 확정·검증, 구현은 하지 않음
- 사용자 질문 불가 실행: 모호한 곳은 아래 `가정`으로 결정하고 `열린 질문`에 남김

## 범위 충돌 — 먼저 확인해야 할 사실

현재 요청은 이미 내려진 두 결정과 정면으로 부딪힙니다.

| 근거 | 원문 |
|---|---|
| `docs/plan/projectflow/interview.md` Soft Gate 3 | "MVP 범위: … 제외 — 팀 성과 KPI 대시보드, 시간 추적, 리포트 내보내기", "첫 경험 완성도 vs 관리자용 분석 기능 → 첫 경험을 선택" |
| `docs/athena/projectflow.md` | 결론 "CONDITIONAL GO", 조건 "관리자 분석 기능은 미룬다", 삭제 권고 "팀 성과 KPI 대시보드 — 프로젝트가 쌓이기 전에는 보여줄 데이터가 없고 초기 사용자 과업과 무관 — 복구 시점: 활성 팀 100개 이후" |

처리: 현재 사용자의 명시적 요청이므로 `--plan-only` 설계는 진행합니다. 다만 구현 착수 여부는 이 충돌을 사용자가 정리한 뒤로 미루고, 질문 1번으로 올립니다.
설계에 반영한 점: 아테나가 든 삭제 이유("보여줄 데이터가 없다")를 **이 화면의 기본 상태 조건**으로 받아들였습니다. 새 팀에서는 `기록 없음` 상태가 가장 흔하므로 빈 KPI·빈 차트를 그리지 않고, MVP 목표(첫 프로젝트·팀원 초대·할 일 배정)로 돌려보내는 화면으로 설계합니다. 이렇게 하면 이 탭이 첫 경험 목표와 경쟁하지 않고 그 목표를 돕습니다.

## 1. 무엇을 만드는가

관리 화면(좌측 내비)에서 `설정` 바로 위에 붙는 형제 항목 `팀 성과`. 팀이 최근 몇 주 동안 할 일을 얼마나 끝냈는지, 마감일을 지켰는지, 지금 밀린 일이 어디 있는지를 KPI 카드 3장 + 주별 추세 그래프 + 프로젝트별 비교 표로 보여 주는 읽기 위주 화면.

## 2. 누가 어떤 상황에서

- 사용자: `owner`(팀 소유자). 5~20명 소규모 팀의 리더. 요청의 "관리자"를 spec의 `owner`로 대응시킴(새 역할명을 만들지 않음)
- 상황: 주 1회 정도, 주간 회의 전이나 월요일 아침에 "요즘 우리 팀이 잘 돌아가나"를 확인. 대부분 데스크톱, 이동 중에는 휴대폰으로 밀린 일만 빠르게 확인
- `member`: 이 화면을 보지 않음(가정 3)

## 3. 최우선 과업과 완료 조건

| 과업 | 시작 | 완료 조건 |
|---|---|---|
| T1. 팀이 일을 제때 끝내고 있는지 판단 | `팀 성과` 진입 | 기간을 바꾸지 않고도 완료 수·기한 내 완료율과 그 변화 방향(이전 같은 기간 대비)을 5초 안에 읽음 |
| T2. 지금 밀린 일로 이동 | 같은 화면 | `기한 지난 할 일 보기` → 어떤 할 일이 누구 담당으로 며칠 밀렸는지 확인 → 해당 보드의 할 일을 엶 |
| T3. 어느 프로젝트가 문제인지 비교 | 같은 화면 | 프로젝트별 표에서 기한 지난 할 일이 많은 순으로 확인 → `보드 열기` |
| T0. (기록 없음 상태) 데이터가 쌓이게 만들기 | 새 팀이 진입 | 다음 활성화 단계 1개(예: `팀원 초대하기`)를 실행 |

## 4. 망설임·불신 지점

- "이 숫자는 무엇을 셌나?" — 기한 내 완료율의 분모(마감일 있는 할 일만), 이번 주 포함 여부가 불분명하면 숫자를 믿지 않음
- "언제 기준인가?" — 집계 시각이 없으면 회의에서 인용하지 못함
- "좋아진 건가?" — 비교 기준 없이 값만 있으면 판단 불가
- 표본이 작은데 퍼센트가 크게 보이는 문제(3건 중 2건 = 67%)
- 팀원 개인 순위처럼 보이면 감시 도구로 읽혀 팀 신뢰를 해침 → 팀·프로젝트 단위만 보여 줌(가정 5)

## 5. 제약

- 기술: React 18 + Vite SPA, REST API(spec "기존 환경"). 지표 집계 API·데이터 모델은 정의돼 있지 않음 → KPI 정의는 `hypothesis`
- 시각: `DESIGN.md` 정본. 이 단계에서는 색·폰트·그림자를 쓰지 않음(그레이스케일 잉크 3단계)
- 레이아웃: `DESIGN.md` "좌측 내비 + 본문 1열. 밀도는 중간", "버튼은 primary 1개만 강조"
- 접근성: 차트에 표 대안(`표로 보기`), 증감은 색이 아니라 부호·문장으로, 키보드로 서랍 열고 닫기
- 콘텐츠: 실제 고객 수치 없음. 와이어프레임 숫자는 전부 `prototype` 샘플

## 6. 관찰 가능한 성공 기준

- 처음 본 owner가 설명 없이 "최근 4주 47건 완료, 이전보다 9건 늘었고, 기한 내 86%, 지금 6건 밀림"을 말할 수 있음
- `기한 지난 할 일 보기`에서 2번 이내 조작으로 특정 할 일이 보드에서 열림
- 완료 0건인 새 팀이 이 화면에서 빈 차트 대신 다음 활성화 단계를 실행함
- member 계정의 내비에 `팀 성과`가 보이지 않음

## 가정 (질문할 수 없어 스스로 정함)

1. "관리자 웹" = 같은 SPA의 owner 관리 영역. 별도 백오피스 앱은 저장소에 없음
2. "설정 화면 옆에 탭" = 좌측 내비에서 `설정`과 나란한 **형제 항목**. 설정 화면 안의 세로 탭으로 넣지 않음 — 설정은 값을 바꾸는 화면, 팀 성과는 상태를 읽고 이동하는 화면이라 임무가 다름
3. 역할: `owner`만 표시, `member`는 내비 항목 `숨김` + 주소 직접 접근 시 진입 차단 안내. spec의 member 금지 행동에 "성과 열람"은 없지만 요청이 "관리자"를 명시. `operation-scenarios.md`가 없어 거부 동작 어휘는 이 문서의 가정
4. KPI 3개: 완료한 할 일(총량·변화) / 기한 내 완료율(비율) / 지금 기한 지난 할 일(이상치·행동). 기간 기본값 최근 4주(진행 중인 이번 주 제외), 대안 최근 12주
5. 팀원 개인별 성과·순위는 v1에서 제외(감시 인상, 소규모 팀 신뢰)
6. 기한 지난 할 일 목록은 새 경로가 아니라 같은 화면의 오른쪽 서랍

## 열린 질문

1. 아테나·인터뷰가 MVP에서 제외한 "팀 성과 KPI 대시보드"를 지금 범위에 다시 넣는 것이 맞습니까? (복구 조건 "활성 팀 100개 이후") 이번 산출물은 설계안일 뿐이며 구현 전에 결정이 필요합니다.
2. "설정 화면 옆"은 좌측 내비의 형제 항목(이 설계)입니까, 설정 화면 안의 탭입니까?
3. member도 팀 단위 성과를 볼 수 있어야 합니까? (현재: owner만)
4. KPI로 원하는 지표가 따로 있습니까? (예: 평균 처리 기간, 팀원별 완료 수)
5. 집계 주기(실시간·매시·매일)와 주 시작 요일(월요일 가정)은 무엇입니까?
