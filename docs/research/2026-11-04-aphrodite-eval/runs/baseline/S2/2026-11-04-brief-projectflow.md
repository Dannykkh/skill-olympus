## 1. 무엇을 만드는가

5~20명 소규모 팀용 프로젝트 관리 웹앱(React 18 + Vite SPA, REST API, 이메일 링크 인증)의 **가입 직후 첫 실행 경험**.
지금의 빈 홈을 "첫 프로젝트 만들기 → 팀원 초대 → 첫 할 일 배정 → 보드"로 이어지는 진입점으로 바꾼다.

MVP 범위(interview Soft Gate 3, athena Reduce 결과 그대로):

- 포함: 프로젝트 생성 마법사, 팀원 초대, 할 일 보드
- 제외: 팀 성과 KPI 대시보드(athena: "프로젝트가 쌓이기 전에는 보여줄 데이터가 없고 초기 사용자 과업과 무관", 복구 시점 활성 팀 100개 이후), 시간 추적, 리포트 내보내기, Slack 알림(spec 에코시스템 맵 `제외`)

→ 홈은 **KPI 대시보드가 아니다.** layout-block-anatomy의 "앱 대시보드 = Stats/KPI → Chart" 기본 시퀀스를 쓰지 않는다.

## 2. 누가 어떤 상황에서 사용하는가

| 사람 (spec 이해관계자 → 역할 ID) | 상황 | 처음 오는 이유와 마음 | 알고 싶은 것 (답이 보일 화면) |
|---|---|---|---|
| 팀 리더 → `owner` (**핵심 사람**) | 방금 이메일 링크로 가입. 데스크톱 브라우저. 팀에 쓸 도구를 고르는 중 | 막막함 + 시험 삼아 써보는 가벼운 마음. 시간을 많이 쓸 생각이 없음 | 지금 뭘 하면 되나? (홈 첫 화면) / 얼마나 걸리나? (마법사 단계 표시) / 팀원에게 어떤 메일이 가나? (초대 단계 미리보기) / 다 하고 나면 뭐가 남나? (완료 보드) |
| 팀원 → `member` | 팀 리더가 보낸 초대 메일의 링크로 처음 들어옴. 데스크톱 또는 휴대폰 | "이게 뭐지, 나한테 뭘 시킨 거지" — 경계 + 할 일 확인 의도 | 누가 무엇에 초대했나? (보드 상단 안내) / 나한테 배정된 일은? (보드에서 내 카드) / 여기서 뭘 바꿀 수 있나? (권한차등 화면) |

핵심 사람을 `owner`로 정한 이유: 성공 기준이 "가입 후 24시간 안에 첫 프로젝트를 만드는 계정 비율"이고, 프로젝트를 만들고 초대를 시작하는 주체가 owner다. member 경험은 owner가 초대를 끝까지 하게 만드는 신뢰 근거(초대 메일이 무엇을 말하는지)로도 쓰인다.

## 3. 최우선 과업과 완료 조건

- 최우선 과업(owner): 가입 당일 첫 프로젝트를 만들고, 팀원을 초대하고, 첫 할 일을 배정한다 (spec 공유 전제).
- 완료 조건: 보드에 owner가 만든 첫 할 일 카드가 담당자와 함께 보이고, 초대 상태(수락 대기)가 보드에서 확인된다.
- 최소 완료(지표 기준): 1단계 "프로젝트 만들기"를 누른 시점에 프로젝트가 생성된다. 이후 단계를 건너뛰거나 이탈해도 프로젝트는 남고 홈에서 이어할 수 있다. (interview 차별화 "가입 5분 안에 첫 보드 완성")

## 4. 망설임·불신 지점

| 지점 | 근거 | 디자인 대응 방향 |
|---|---|---|
| 빈 홈에서 무엇을 할지 모름 | spec P1 (가입자 70%가 첫 프로젝트 전 이탈) | 빈 홈 자체를 1단계 입력으로 만든다. 별도 클릭 없이 바로 이름 입력 |
| 초대 경로를 못 찾음 | spec P2 (설정 메뉴 깊숙이) | 마법사 2단계 + 사이드바 상시 "팀원 초대"(owner) + 보드 헤더 "수락 대기 N명" 링크(팀원 화면) |
| 동료에게 이상한 메일이 갈까 걱정 | 추론 (hypothesis) | 보내기 전 초대 메일 미리보기, 보낸 뒤 주소별 결과 |
| 마법사가 길어 보임 | 추론 (hypothesis) | 3단계 표시 + 2·3단계 "나중에" 허용 |
| (member) 무엇에 초대됐는지 모름 | 추론 (hypothesis) | 첫 진입 보드 상단에 초대한 사람·프로젝트 안내 + 내 카드 표시 |

## 5. 제약

- 기술: React 18 + Vite SPA, REST API, 이메일 링크 인증(비밀번호 없음). 이메일 발송은 외부 API(spec 에코시스템 맵) → 발송 실패 상태 필요.
- 브랜드: `DESIGN.md` — "차분하고 실무적인 업무 도구. 장식보다 할 일과 다음 행동이 먼저 보인다", 좌측 내비 + 본문 1열, 밀도 중간, primary 1개만 강조, accent는 마감 임박 경고에만. (시각 값은 Phase 3에서 다루며 이번 와이어프레임은 그레이스케일)
- 콘텐츠: 사용자에게 보여줄 고객 수치·후기·배지 없음. spec의 60%/30%/70%는 내부 지표이며 화면 카피로 쓰지 않는다.
- 접근성: 한국어 UI. 키보드만으로 마법사 완주, 오류는 필드에 연결, 상태 변화는 라이브 영역으로 알림.
- 역할: `owner`, `member` 두 역할. 화면은 둘 다 `공용 권한차등` → 같은 화면 위의 요소별 노출 차이.

## 6. 관찰 가능한 성공 기준

- 첫 5초: 홈 첫 화면만 보고 "프로젝트 이름을 넣고 만들기를 누르면 된다"와 "3단계"를 말할 수 있다.
- owner가 마우스·키보드만으로 1→2→3단계를 마치고 보드 결과 화면에 도달한다(목표 5분 이내 — interview 차별화).
- 2·3단계를 건너뛰어도 프로젝트가 남고, 홈에 "이어서 하기"가 보인다.
- member가 초대 링크로 들어와 첫 화면에서 초대한 사람·프로젝트·내 할 일을 찾는다.
- member 화면에 팀 설정·팀원 내보내기 조작이 보이지 않는다.
- 생성 실패·초대 발송 실패·권한 없음에서 다음 행동이 화면에 있다.

## 7. 레퍼런스

벤치마크 없음 → 제품 세계에서 유도. 이 제품 세계의 실물: 프로젝트 이름 하나, 사람(이메일), 할 일 카드, 상태 열(할 일·진행 중·완료). 첫 실행 화면의 근거는 카테고리 관례("온보딩 체크리스트 위젯", "샘플 프로젝트 템플릿 갤러리")가 아니라 이 세 실물을 순서대로 하나씩 만드는 것이다. 템플릿 갤러리·샘플 데이터 프로젝트는 MVP 포함 기능에 없으므로 추가하지 않는다.
