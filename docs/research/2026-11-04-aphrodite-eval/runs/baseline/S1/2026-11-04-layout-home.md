| 위계 (Hierarchy) | 통과 | owner 0개 1280: 색 없이도 읽는 순서가 상황 문장 → "첫 보드까지 3단계" 상자 → 화면 유일의 솔리드 버튼 "첫 프로젝트 만들기"(1단계 왼쪽 굵은 선·채운 원). 2단계 이메일 칸·외곽선 버튼이 두 번째로 무거움 — 2단계라 순서와 맞음. 사용 중 1280: "새 프로젝트" 솔리드 1개, 현황 띠에서 굵은 테두리 "! 마감 지남 1"이 먼저 읽힘. member: 솔리드 없음, 상황 문장 다음 프로젝트 행이 가장 진한 덩어리 | Phase 3에서 이메일 칸 테두리를 보조 잉크로 유지해 1단계 버튼보다 가볍게 |
| 구조 (Structure) | 통과 | 0개: 무엇부터(진행판) → 결과가 될 자리(내 할 일·프로젝트) → 함께할 사람(팀) 순서가 spec 목표 문장 순서와 같음. 사용 중: 위험·지금·계획 숫자 → 처리 목록 → 맥락(프로젝트·팀). 모든 구역이 본문 1열 | — |
| 흐름 (Flow) | 통과 (화면 밖 구간 미작도) | 진입→행동→완료: 1단계 버튼 → 마법사 → 새 보드(After) → 홈 "1 / 3"(사이트맵 4-1). 실패→복구: 초대 형식 오류·발송 실패는 입력 유지 + 문장 + 다시 보내기, 구역 오류는 그 구역만 다시 시도, 연결 끊김은 띠 + 다시 연결, 3단계는 비활성 이유 문장. member가 프로젝트 없는 팀에 들어온 상태도 문장으로 처리 | 마법사·보드 화면은 이번 범위 밖이라 그리지 않음. "할 일 배정하기"의 목적지 = 1단계에서 만든 프로젝트 보드로 정함 |

### 공통 문법 점검

- 잉크 3단계: 핵심(제목·숫자·주 행동) / 보조(설명·프로젝트명·날짜) / 배경(점선 칸·구분선·비활성)만 사용 ✓
- 강조는 블록당 1개: 내비 `홈`, 진행판 1단계, 현황 "마감 지남", 내 할 일의 마감 지남 행 ✓
- CTA 문법: 화면당 솔리드 1개 + 외곽선 0~1개 (0개: "첫 프로젝트 만들기" + "초대 보내기" / 사용 중: "새 프로젝트" + "팀원 초대" / member: 솔리드 0) ✓
- 상태 하나 보여 주기: 완료된 할 일 1행, 초대 대기 1명 ✓
- 지속 비대칭: 기능형 1열 화면이라 적용하지 않음(DESIGN.md "본문 1열")

## 역할별 화면 (2-5에서 그린 범위)

spec 시스템 역할 표의 `화면` 열이 둘 다 `공용 권한차등`이므로 별도 역할 화면 대신 같은 블록 순서에서 요소 노출만 다르게 그렸습니다(owner 0개·사용 중, member 첫 진입). 요소별 표시/숨김/비활성/읽기전용 초안은 `2026-11-04-experience-home.md`의 `## Role Variants`에 있으며 Phase 4-1-1에서 확정합니다.

- 역할 제거 점검: member에게서 진행판·생성·초대를 빼면 솔리드 CTA가 사라짐 → member 첫 화면은 상황 문장 + 프로젝트 목록(→ 보드)을 다음 행동으로 둠. 빈 화면이 되지 않음을 캡처로 확인.
- 미확정: member의 프로젝트 생성·초대 권한(현재 `숨김` 가설), member가 보는 프로젝트 범위.

## 게이트 결론

다섯 기준 모두 통과(1라운드 수정 4건 반영 후). 주 행동과 정보 순서는 와이어프레임에서 확정됐으며, Phase 3 시각 방향 후보는 이 구조(블록 순서·주 행동·문구)를 입력으로 써야 합니다. 후보가 주 행동이나 블록 순서를 바꾸면 이 게이트를 다시 실행합니다.
