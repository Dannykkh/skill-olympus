## Page Goal

- 사용자가 이 화면에서 달성할 결과: 프로젝트 0개 owner는 첫 프로젝트 만들기를 시작하고 팀원을 부를 수 있다. 사용 중인 owner·member는 마감이 지난 일과 오늘 마감인 일을 찾아 처리하거나 해당 보드로 간다.
- 제품이 얻어야 하는 결과: 가입 당일 첫 프로젝트 생성 → 팀원 초대 → 첫 할 일 배정(spec 목표). 빈 화면 이탈(P1)과 초대 경로 매몰(P2) 해소.
- 관찰 가능한 성공 조건: 1280×800·390×844 첫 뷰포트에 솔리드 주 행동이 하나만 보이고 한 번에 마법사로 이동. 초대는 홈에서 이동 없이 시작. 홈의 숫자는 모두 본인 데이터에서 센 값이고 누르면 해당 할 일만 남음. member 첫 진입에도 다음에 갈 곳이 있음.

## Audience and Tasks

- 주요 사용자와 사용 상황: spec 역할 `owner`(팀 소유자 — 가입 직후 프로젝트 0개, 또는 매일 아침 현황 확인)와 `member`(팀원 — 초대 메일 링크로 처음 들어오거나 배정된 일을 처리). 5~20명 소규모 팀, 데스크톱 업무 도구 중심.
- 최우선 과업: 새 owner의 첫 프로젝트 만들기(핵심 사람). 사용 중에는 마감 순 내 할 일 처리.
- 시작 조건과 완료 조건: 새 owner — 시작: 로그인 직후 홈, 프로젝트 0개 / 완료: 새 프로젝트 보드가 열리고 홈 진행판이 "1 / 3 완료". 사용 중 — 시작: 홈 진입 / 완료: 할 일 완료 표시 또는 할 일 상세 도착.
- 주요 불안·마찰·실패 가능성: 무엇부터 할지 모름(P1), 초대 경로를 못 찾음(P2), 초대가 팀원에게 가입 부담을 줄까 걱정, 숫자를 믿어도 되는지, member가 빈 화면을 만남, 초대 발송 실패, 연결 끊김으로 오래된 목록을 봄.

## Core Message

- 핵심 약속: 할 일과 다음 행동이 먼저 보인다 (DESIGN.md Overview).
- 설명: 프로젝트 0개면 "첫 프로젝트를 만들면 팀의 할 일이 이 화면에 모입니다." + 첫 보드까지 3단계. 사용 중이면 내 할 일 현황 3칸과 마감 순 목록.
- 증거: 사용자 자신의 데이터 — 진행판 "0 / 3 완료", 팀 인원 "1명", 할 일 현황 수, 각 할 일의 프로젝트·마감일. 외부 수치·후기 없음.
- 사용자가 다음에 이해해야 할 것: 1단계를 마치면 2·3단계가 이어지고, 완료하면 이 자리가 내 할 일 대시보드로 바뀐다(아래 점선 빈 칸("아직 없음")로 미리 보여 줌).

## Section Order

프로젝트 0개 owner:

1. 머리(`h1 홈` + 날짜 + 상황 한 문장): 지금 어디이고 무슨 상태인가.
2. 시작하기 진행판 "첫 보드까지 3단계": 무엇부터 하나 — 화면에서 가장 큰 덩어리이자 주 행동이 있는 곳.
3. 내 할 일(점선 빈 칸("아직 없음")): 다 하면 이 화면이 무엇이 되나 — 진행판 다음에 와야 약속이 구체화됨.
4. 프로젝트(점선 빈 칸("아직 없음") 한 줄): 만든 프로젝트가 어디 보이나.
5. 팀(실제 명단 1명): 지금 혼자라는 사실 — 2단계 초대의 동기.

사용 중 owner:

1. 머리 + "새 프로젝트": 위치와 생성 행동.
2. (시작하기 미완료 시) 한 줄 띠 "시작하기 2 / 3": 남은 단계 하나만.
3. 내 할 일 현황 3칸: 위험·지금·계획을 숫자로.
4. 내 할 일 목록(마감 순, 가장 큰 덩어리): 바로 처리.
5. 프로젝트 목록: 할 일 밖의 맥락·보드 이동.
6. 팀: 인원·초대 대기·팀원 초대.

member: 머리 → 내 할 일(목록 또는 빈 상태) → 프로젝트 목록 → 팀(읽기전용).

## CTA Strategy

- Primary: 프로젝트 0개 — "첫 프로젝트 만들기" → 프로젝트 생성 마법사, 첫 뷰포트 진행판 1단계 행에 1회. 사용 중 owner — "새 프로젝트" → 마법사, 페이지 머리 오른쪽에 1회. member — 솔리드 버튼 없음.
- Secondary: "초대 보내기"(외곽선, 진행판 2단계 이메일 칸 옆). 사용 중에는 팀 구역의 "팀원 초대"(외곽선) → 같은 이메일 입력 폼을 그 자리에서 펼침. "할 일 배정하기"(텍스트 버튼, 프로젝트 0개면 비활성).
- 반복 규칙: 솔리드 주 행동은 화면당 1개. 진행판이 끝나기 전 사용 중 홈에서는 한 줄 띠로 남은 단계 하나만 텍스트 버튼으로 다시 보여 줌. 3/3이면 띠를 없앰.
- 완료·실패 피드백: 프로젝트 생성 완료 → 마법사가 새 보드로 보냄(After), 홈 복귀 시 1단계 체크. 초대 완료 → 같은 자리 "boram.kim@onkyeol.kr 님에게 초대 메일을 보냈습니다" + 2단계 체크 + 팀 구역 "초대 대기 1명". 초대 실패 → 입력값 유지 + 원인과 "다시 보내기". 할 일 완료 → "완료로 표시했습니다 · 되돌리기"(5초).

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 팀원을 초대할 때(팀원에게 가입 부담을 줄까), 홈의 숫자를 볼 때(맞는 숫자인가), 연결이 끊겼을 때(지금 보는 게 최신인가).
- 그 직전에 제시할 근거: 2단계 설명에 이메일 링크 로그인 사실(Product Facts). 현황 칸 라벨에 "나에게 배정된 미완료"를 명시하고, 누르면 그 할 일만 남게 해 바로 검증. 연결 끊김 시 마지막 동기화 시각을 띠로 표시.
- 출처·날짜·검증 가능성: Product Facts의 spec 출처. 숫자는 사용자 자신의 데이터라 목록과 대조 가능.
- 근거가 없을 때 생략할 요소: 소요 시간 약속("5분이면 끝"), 다른 팀의 사용 수치, 후기, 배지, 팀 성과 지표.

## Desktop Structure

- 기준 뷰포트: 1280×800
- 첫 뷰포트: 프로젝트 0개 — 머리, 상황 문장, 시작하기 진행판 3단계 전체, 내 할 일 점선 빈 칸("아직 없음") 상단. 사용 중 — 머리, 현황 3칸, 내 할 일 목록 5행 이상.
- 그리드·pane·콘텐츠 위계: 좌측 사이드바 232px + 본문 1열(최대 폭 약 880px, 왼쪽 정렬). 구역은 1px 선 테두리 상자로 세로 배치, 구역 안 2단 분할 없음(DESIGN.md "본문 1열"). 잉크 위계: 진행판 1단계 제목·현황 숫자·할 일 제목 = 핵심, 설명·프로젝트명·날짜 = 보조, 점선 빈 칸("아직 없음")·구분선 = 배경.
- 스크롤 흐름과 밀도 변화: 위는 행동(진행판·현황), 아래로 갈수록 맥락(프로젝트·팀). 밀도 중간, 할 일 행 높이 44px 이상.

## Accessibility Contract

- 문서·랜드마크·헤딩 읽기 순서: `nav`(사이드바) → `main` → `h1 홈` → `h2` 시작하기 / 내 할 일 / 프로젝트 / 팀. 진행판은 `ol`, 현재 단계에 `aria-current="step"`, 진행 텍스트 "3단계 중 0단계 완료".
- 키보드·포커스·Escape 동작: 사이드바 → 주 행동 → 초대 입력 순 탭 이동. 현황 칸은 토글 버튼(`aria-pressed`). 모바일 내비 시트는 포커스 가둠 + Escape로 닫고 `메뉴` 버튼으로 포커스 복귀.
- 레이블·오류 연결·상태 알림: 이메일 칸에 보이는 라벨 "팀원 이메일", 오류는 `aria-describedby`로 연결. 초대 결과·완료 알림은 `role="status"`(polite), 구역 오류는 구역 안 텍스트 + 다시 시도 버튼. 비활성 3단계 버튼은 `aria-disabled` + 이유 문장.
- 대비·색 외 신호·터치 타깃: 마감 지남은 색(Accent)만이 아니라 "!" 기호와 "지남" 글자를 함께. 완료는 체크 + 취소선. 모바일 터치 타깃 44px 이상. 대비 실측은 Phase 3.
- reduced-motion과 대체 경험: `prefers-reduced-motion`이면 알림·행 흐려짐 전환 없이 즉시 상태 변경.
