# Design Brief — 플로우보드 첫 실행 경험

- 작성: 2026-11-04 · Aphrodite Phase 1-1 · `--plan-only` (이번 실행은 Phase 2-5 게이트까지)
- Source Mode: **product-derived** — 사용자가 지정한 벤치마크 URL·스크린샷 없음
- Planning dir: `docs/plan/projectflow/` (spec.md, interview.md) + `docs/athena/projectflow.md` + 루트 `DESIGN.md`
- Product Design Gate: `NOT APPLICABLE` — `--plan-only`이고 런타임이 Claude Code(0-0은 Codex 전용)
- 시장 관례: `NOT APPLICABLE` — 데스크톱 우선 React SPA 업무 도구이며 모바일 앱·모바일 우선 웹앱이 아님(korean-mobile-app.md 4~8절 대상 아님)
- 상류 제외 충돌: 없음 — 요청이 팀 성과 KPI 대시보드·시간 추적·리포트 내보내기를 요구하지 않음. 대신 이 제외가 홈 설계를 구속한다(아래 6절).
- PRODUCT.md: 루트에 없어 상류에서 옮겨 `docs/design-refs/2026-11-04-product-projectflow.md`에 작성(이 실행의 쓰기 범위 때문에 루트가 아님 — 루트 `PRODUCT.md`로 옮길 것)

## 1. 무엇을 만드는가

5~20명 소규모 팀의 프로젝트 관리 웹앱 "플로우보드"의 **첫 실행 경험**: 가입 직후 0건 홈 → 프로젝트 만들기 마법사(3단계) → 첫 보드(결과 화면) → 할 일 맡기기, 그리고 초대받은 팀원이 메일 링크로 들어와 자기 할 일을 찾는 경로.

## 2. 누가 어떤 상황에서 쓰는가 — 사람 카드

이름은 spec 이해관계자 표의 구분(`팀 리더`·`팀원`)과 역할 ID(`owner`·`member`)를 그대로 쓴다. 더미 이름·날짜는 Experience Contract `Scenario Facts`가 정본이다.

### 팀 리더 (`owner`) — 핵심 사람

- 누구인가: 김서연(34), 8명 규모 브랜드 디자인 스튜디오 "온결 스튜디오" 실장. 지금은 단톡방과 스프레드시트로 일을 나눈다.
- 처음 오는 이유와 마음: 단톡방에서 할 일이 묻혀 마감을 놓쳤다. 기대 반, "또 설정만 하다 끝나는 거 아닐까" 하는 막막함 반.
- 알고 싶은 것
  1. 지금 뭘 먼저 하면 되지? → 홈 첫 화면
  2. 팀원들을 어떻게 데려오지? → 홈·보드의 "팀원 초대", 마법사 3단계
  3. 초대한 사람이 들어왔나? → 보드 헤더의 팀원 상태
  4. 누구에게 무엇을 언제까지 맡겼나? → 보드 카드의 담당자·마감
- 성공한 순간: 첫 보드에 할 일 3개가 생기고 첫 카드에 박민지님 이름이 붙었을 때
- 주로 쓰는 화면: 홈, 할 일 보드

### 팀원 (`member`)

- 누구인가: 박민지(27), 같은 스튜디오 에디터. 초대 메일을 휴대폰에서 처음 연다.
- 처음 오는 이유와 마음: 실장이 보낸 초대라서 연다. "또 새 툴이야?" 하는 귀찮음과 "내가 뭘 해야 하지?" 하는 궁금함.
- 알고 싶은 것
  1. 누가 어디로 나를 불렀지? 믿어도 되는 링크인가? → 초대 수락 화면
  2. 내가 맡은 일은 뭐고 언제까지지? → 참여 직후 보드 첫 화면
  3. 여기서 뭘 누르면 되지? → 내 할 일 카드의 상태 옮기기
  4. 질문은 어디에 남기지? → 할 일 상세 댓글
- 성공한 순간: 맡은 할 일을 "진행 중"으로 옮겼을 때
- 주로 쓰는 화면: 할 일 보드, 할 일 상세

### 핵심 사람: 팀 리더

P1(가입자 70%가 첫 프로젝트 전에 이탈)과 성공 기준(24시간 안 첫 프로젝트 생성 60%)이 모두 팀 리더의 행동이다. 팀원 경험은 팀 리더의 "성공한 순간"(초대가 실제로 이어짐)을 완성하는 두 번째 고리다.

## 3. 최우선 과업과 완료 조건

| 사람 | 과업 | 시작 조건 | 완료 조건 |
|---|---|---|---|
| 팀 리더 | 첫 프로젝트 만들기 | 가입 직후, 프로젝트 0개 | 프로젝트가 저장되고 보드가 열림(마법사 1단계 "다음"에서 저장) |
| 팀 리더 | 팀원 초대 → 첫 할 일 맡기기 | 보드 1개, 팀원 0명 | 초대 1명 이상 발송 + 할 일 1개 이상에 담당자 지정 → 시작 단계 3/3 |
| 팀원 | 내 할 일 찾고 시작하기 | 초대 메일 링크 열기 | 참여 완료 + 맡은 할 일을 "진행 중"으로 옮김 |

## 4. 망설이거나 불신하는 지점

- 팀 리더: "설정만 하다 끝나지 않을까"(홈) / "초대 메일이 잘 갔나, 스팸처럼 보이진 않을까"(마법사 3단계) / "아직 수락 안 한 사람에게 맡겨도 되나"(담당자 정하기)
- 팀원: "이 링크 믿어도 되나, 가입부터 해야 하나"(초대 수락) / "내 일이 어디 있지"(첫 보드)

## 5. 제약

- 기술: React 18 + Vite SPA, REST API, 인증은 이메일 링크, 초대는 이메일 외부 API, Slack 연동 제외(spec 에코시스템 맵·기존 환경)
- 콘텐츠: 고객 수치·후기·배지 근거 없음 → 쓰지 않는다. "가입 5분 안에 첫 보드"는 차별화 목표(가설)이지 카피가 아니다.
- 브랜드: 루트 `DESIGN.md` — 차분하고 실무적, primary는 주 행동·현재 위치에만, accent는 마감 임박 경고에만, Pretendard Variable, 좌측 내비 + 본문 1열, 밀도 중간. (와이어프레임 단계에서는 색을 쓰지 않는다.)
- 역할: owner·member 둘 다 `공용 권한차등`(spec 시스템 역할 표) → 같은 화면 위의 역할별 변형
- 접근성: 키보드 완주, 상태를 색 외 텍스트로 표시, 한글 줄바꿈(keep-all)

## 6. 관찰 가능한 성공 기준

- 제품: 가입 후 24시간 안에 첫 프로젝트를 만드는 계정 비율 60% 이상(현재 30%) — spec 공유 전제
- 화면(와이어프레임·구현에서 확인)
  - 홈 첫 실행 첫 뷰포트의 solid 버튼은 "첫 프로젝트 만들기" 하나
  - 0으로 채운 KPI·빈 차트·팀 성과 지표 0개(athena 삭제 권고, interview 제외)
  - 마법사 3단계 이내에 보드 도달, 2·3단계는 건너뛸 수 있음
  - "팀원 초대" 진입점이 홈·보드 첫 뷰포트(데스크톱 사이드바, 모바일 상단 바)에 항상 보임 — P2
  - 팀원은 참여 직후 첫 화면에서 자기 할 일·마감·맡긴 사람을 읽음

## 7. 제품 세계에서 유도한 근거 (레퍼런스 없음, 1-2)

- 실물: 회의실 화이트보드의 포스트잇 3칸(할 일·진행 중·완료), 포스트잇에 붙이는 이름표, 단톡방의 "이거 누가 해요?"
- 어휘: 맡기다·맡은 일·마감·진행 중·초대 대기. "배정(assign)"보다 "맡기기"가 팀 리더의 말투에 가깝다.
- 구조로 옮긴 것: 보드 3열(포스트잇 칸), 카드의 담당자 칸(이름표), 할 일을 "맡기면" 끝나는 시작 단계
- 피할 카테고리 클리셰: 0값 KPI 카드 행, 빈 차트 자리, "생산성 N% 향상" 카피, 일러스트 히어로, 고객 로고 띠 — 제품 근거가 아니라 협업 SaaS의 습관이다.

## 8. 넣을지 판정 — 여섯 질문 (korean-mobile-app.md 7절)

질문: ①핵심 갈등을 푸나 ②이미 쓰는 통로가 하나 ③누구에게 새 할 일·알림이 생기나 ④없으면 무슨 일(빈도×피해) ⑤더 가벼운 형태 ⑥누구의 처음 오는 이유·성공한 순간에 닿나

| 후보 | 출처 | 판정 | 이유 한 줄 |
|---|---|---|---|
| 프로젝트 생성 마법사 | PRD(athena 1, Soft Gate 3) | keep | ①P1 그 자체 ⑥팀 리더 처음 오는 이유. 3단계·필드 1~3개로 가볍게 |
| 팀원 초대(이메일) | PRD(athena 2, spec P2) | keep | ①P2 ④혼자 쓰다 그만둠. 설정 깊숙이 대신 홈·보드 첫 뷰포트에 상시 |
| 할 일 보드 | PRD(athena 3) | keep | 핵심 가치 ⑥팀 리더·팀원 성공한 순간 모두 이 화면 |
| 댓글 | spec 역할 표(member 주요 업무) | keep | ⑥팀원 "질문은 어디에" — 할 일 상세 안에만, 첫 실행 화면에는 넣지 않음 |
| 팀 성과 KPI 대시보드 | 상류 제외(athena 삭제 권고, Soft Gate 3) | cut | ④데이터 0건이라 보여줄 것이 없음 ⑥누구에게도 닿지 않음. 복구 시점: 활성 팀 100개 이후 |
| 시간 추적 | 상류 제외 | cut | ①과 무관, 차별화 아님. 복구: 유료 전환 검증 이후 |
| 리포트 내보내기 | 상류 제외(Soft Gate 3) | cut | 관리자 분석 기능 — 첫 경험 우선 트레이드오프 |
| Slack 알림 | 상류 제외(spec 에코시스템) | cut | ②③ 새 알림 통로. MVP 밖 |
| 시작 단계 진행(0/3 → 3/3) | 설계 중 | keep | ①"뭘 먼저 하지"에 답 ⑤별도 투어 대신 홈 블록 하나. 3/3이면 사라짐 |
| 초대 대기 팀원에게 맡기기 | 설계 중 | keep | ④막으면 첫 세션에 3단계를 못 끝냄. 담당자 칸에 "초대 대기" 표시로 신뢰 보완 |

PRD·사용자 요구를 빼거나 가볍게 한 판정: 없음(PRD 기능 3개 모두 keep, 제외 4개는 상류 결정 그대로). 다만 "마법사 2·3단계 건너뛰기 허용"은 spec 목표(당일 초대·배정)를 선택 단계로 만드는 해석이므로 사용자 확인이 필요하다(아래).

## 9. 사용자 확인이 필요한 것 (이 실행은 질문할 수 없어 AI 권장으로 진행)

1. 마법사 2단계(첫 할 일)·3단계(팀원 초대)를 건너뛸 수 있게 해도 되는가 — 권장: 허용. 성공 기준이 "첫 프로젝트 생성"이므로 1단계 통과 시 저장하고, 남은 단계는 홈·보드의 시작 단계로 이어 간다.
2. 팀원(`member`)의 프로젝트 만들기·팀원 초대·담당자 지정 권한 — spec 금지 행동에 없음. 권장: 셋 다 표시, 팀 설정·팀원 내보내기만 숨김.
3. 아직 초대를 수락하지 않은 팀원에게 할 일을 맡길 수 있는가 — 권장: 허용("초대 대기" 표시).
