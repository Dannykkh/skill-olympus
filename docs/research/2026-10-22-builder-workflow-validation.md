기존 계약의 모호한 판단과 반복 절차를 수정했다. 사전에 정한 7개 합성 사례는 수정 전후 모두

## 변경 범위

- 미노스: 현재 요구사항·AC·명세로 기대 동작을 정한 뒤 구현/테스트 중 수정 대상을 선택한다.
  계약 근거 없는 기대값 완화, 거부 테스트에 허용 토큰 추가, `--fix-test-only`에서 구현 결함을
  테스트 변경으로 숨기는 행동을 금지한다. 마지막 수정 뒤 영향받는 회귀를 확인한다.
- 젭마인: 헤르메스의 수요 검증 상태를 보존한다. AI의 처리 경계와 평가 재현성은 기존
  `tripwire-guide.md`에 두고 plan·섹션 AC로 전달한다. 사용자의 설계 가설을 보존하고 후보 점수를
  실측 성능으로 표현하지 않는다.
- 포세이돈: 기존 섹션 입력 경로를 사용한다. AI 섹션의 Module Contract에 코드/모델 경계와
  실패 시 행동을, AC에 같은 평가를 실행할 데이터·기준·명령·지표 ID를 전달한다.
- 다이달로스: 이미 허용된 범위는 단일 실행안으로 진행하고 의미 있는 선택이 남을 때만 비교한다.
  흐름·분기·모듈 경계가 그대로인 국소 수정은 새 도면·제안서·사전을 만들지 않는다.
  네이티브·순차·MCP가 같은 판단을 사용하며 외부 변경 권한과 트립와이어 판정은 유지한다.
- 아르고스: UI/API 통과와 AI 품질 증거를 분리하고, 재현할 수 없는 품질 주장은 `weak`로 판정한다.

새 스킬·평가 엔진·전역 AGENTS 규칙은 추가하지 않았다. 상세 사용 계약은
[워크플로우 가이드](../workflow-guide.md#phase-2-구현--agent-team-vs-workpm-vs-orchestrator-mcp)에 연결했다.

## 방법과 한계

- 기준점: Git `0ee7598cc48342b07fd035f21e77eaef89bb3903`. 수정 전에 대상 파일을 별도 디렉터리에
  복사하고 SHA-256을 저장했다. 변경 전 추적 파일의 사용자 수정은 없었으며 기존 ZIP 8개는 보존했다.
- 사례·판정 기준을 수정 전에 고정했다. 같은 입력과 지침 경로만 변경 전/후 에이전트에 전달했다.
  변경 의도·기대 정답·이전 응답은 전달하지 않았다.
- 실행: 동일 호스트의 기본 모델·추론 설정을 상속하는 새 subagent 컨텍스트를 사용했다.
  Minos / WorkPM / 계획 각각 한 컨텍스트에서 해당 사례를 실행했고 전후 컨텍스트는 분리했다.
  모델 버전·토큰·호출 비용은 도구 결과에 제공되지 않아 미측정이다.
- 각 조건 1회 실행이다. 실행 간 편차와 통계적 유의성은 측정하지 않았다. 의미 판정은 변경을
  작성한 메인이 아래 사전 기준으로 수행했으므로 독립 채점은 아니다.
- 작성자가 사례를 알고 수정했으므로 7개는 개발·회귀 사례다. 설치 후 추가한 2개 사례도
  소규모 확인이며 일반화 성능을 입증하는 별도 평가셋으로 주장하지 않는다.
- Minos 2개는 실제 파일 수정과 Node 테스트를 실행했다. 나머지 5개는 제한된 판단 응답이며
  제품 구현·브라우저·전체 파이프라인 실행이 아니다.
