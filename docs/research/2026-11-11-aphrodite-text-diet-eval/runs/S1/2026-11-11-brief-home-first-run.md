### 상류 제외 결정과의 대조 (SKILL 0-1 규칙 4)

요청은 제외 항목을 직접 지목하지 않았습니다. 다만 "대시보드답게"는 해석에 따라 제외된 **팀 성과 KPI 대시보드**일 수 있습니다.
제외하지 않는 해석(작업 홈: 다음 한 단계 + 내 할 일·프로젝트 칸)으로 진행하고, 그 해석을 Experience Contract `Open Decisions`에 `scope`로 올렸습니다.

## 사람 카드

spec 이해관계자 구분과 이름을 그대로 씁니다. 이름·팀은 `Scenario Facts`의 시안 데이터입니다.

### 팀 리더 — 핵심 사람

- 누구인가: 한지원, 30대 후반 한국인, 12명 브랜드 디자인 스튜디오의 팀장. 가입 당일, 프로젝트 0개.
- 처음 오는 이유와 마음: 메신저와 엑셀로 흩어진 일을 한곳에 모으려 함. 막막함 — 빈 화면에서 무엇부터 할지 모름.
- 알고 싶은 것
  1. 지금 무엇부터 하면 되나 → `home` 시작 단계 1
  2. 얼마나 더 해야 쓸 수 있나 → `home` 시작 단계 진행(0/3)
  3. 팀원은 어디서 부르나 → `home` 시작 단계 2, 내비 `팀원`
  4. 만든 것은 어디에 생기나 → `home` 프로젝트 칸, `project-created`
- 성공한 순간: 첫 프로젝트에 팀원 한 명이 들어와 첫 할 일이 배정된 보드를 본다.
- 주로 쓰는 화면: `home`, `project-wizard`, `project-board`, `members`

### 팀원

- 누구인가: 오민재, 20대 후반 한국인, 같은 스튜디오 디자이너. 초대 메일의 링크로 처음 들어옴.
- 처음 오는 이유와 마음: 팀장이 불러서. 호기심 반, 도구가 하나 더 늘었다는 부담 반.
- 알고 싶은 것
  1. 내가 할 일이 무엇인가 → `home` 내 할 일 칸
  2. 언제까지인가 → `home` 내 할 일 행의 마감
  3. 어느 프로젝트의 일인가 → `home` 프로젝트 칸, `project-board`
- 성공한 순간: 내게 배정된 할 일을 열어 처리한다.
- 주로 쓰는 화면: `home`, `project-board`, `task-detail`

**핵심 사람: 팀 리더(가입 당일, 프로젝트 0개).** 성공 기준(24시간 안 첫 프로젝트 생성)과 P1이 이 사람의 이탈을 말하고, 팀원은 이 사람이 프로젝트를 만들고 초대해야 생깁니다.

## 넣을지 판정 — 여섯 질문

"채워줘"에 답할 후보를 모두 올려 판정했습니다. PRD 요구를 빼거나 가볍게 한 판정은 없습니다(모두 설계 중 떠올린 후보이거나 상류가 이미 제외한 항목).

| 후보 | 판정 | 이유 |
|---|---|---|
| 시작 단계(다음 한 단계 + 남은 단계) | keep | P1의 핵심 갈등 "무엇부터"를 직접 풂. 팀 리더의 처음 오는 이유에 닿음 |
| 홈 안의 프로젝트 이름 입력 | keep | 주 행동을 버튼이 아니라 행동 자체로 놓음. 없으면 빈 화면 → 다른 화면 이동이 한 번 더 생김 |
| 내 할 일 칸(0건이면 빈 상태 한 줄) | keep | 팀원의 성공한 순간 그 자체. 데이터가 생기면 홈의 주인공 |
| 프로젝트 칸(0건이면 빈 상태 한 줄) | keep | 만든 결과가 놓이는 자리. 팀 리더의 "어디에 생기나"에 답함 |
| 홈의 별도 `초대하기` 보조 버튼(0/3 단계에서) | cut | 단계 2가 차례가 되면 주 행동이 되고, 그 전에는 내비 `팀원` 한 번으로 감. 첫 화면의 행동을 하나로 유지 |
| KPI 카드 행(프로젝트 수·완료율·팀원 수) | cut | 상류 제외(Soft Gate 3, 아테나 삭제 권고). 0건 계정에서는 0만 보임 |
| 최근 활동 피드 | later | 활동이 0건. 핵심 사람 누구의 질문에도 닿지 않음. 팀 활동이 쌓인 뒤 재검토 |
| 환영 문단·일러스트·제품 소개 카드 | cut | 과업 단계에 기여하지 않음. 텍스트 예산 초과 |
| 사용법 가이드·튜토리얼 카드 | cut | 시작 단계가 같은 일을 더 가볍게 함 |
| 샘플 프로젝트·템플릿 갤러리 | later | 상류에 없음. 마법사(`01-onboarding`) 범위에서 정할 일 |
| 진행률 링·퍼센트 | lighten | `시작 단계 0/3` 글자 하나로 대신 |
| Slack 연결 안내 | cut | 에코시스템 맵에서 제외 |

## 제품 세계에서 가져올 근거 (1-2, 레퍼런스 없음)

- 실물·도구: 벽에 붙인 칸반 보드(열과 카드), 프로젝트 착수 체크리스트, 초대 메일.
- 어휘: 프로젝트 · 보드 · 할 일 · 담당 · 마감 · 초대. "워크스페이스", "태스크" 같은 번역투는 쓰지 않음.
- 구조 근거: 착수 체크리스트 → 시작 단계 목록. 보드의 빈 열 → 채워질 칸의 빈 상태.
- 색·재질·모션 근거는 Phase 3에서 `DESIGN.md`와 함께 다룸(이번 범위 밖).
- 시장 관례: NOT APPLICABLE — 한국 사용자 대상 모바일 앱이 아니라 데스크톱 중심 업무 웹앱.
