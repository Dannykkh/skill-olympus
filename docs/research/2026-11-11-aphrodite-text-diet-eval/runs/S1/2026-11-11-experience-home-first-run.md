## Page Goal

- 사용자가 이 화면에서 달성할 결과: 프로젝트 0개인 팀 소유자가 첫 프로젝트 만들기를 시작한다. 데이터가 생긴 뒤에는 자기 할 일과 프로젝트로 바로 간다.
- 제품이 얻어야 하는 결과: 가입 후 24시간 안에 첫 프로젝트를 만드는 계정 비율 60% 이상(현재 30%, spec 공유 전제).
- 관찰 가능한 성공 조건:
  1. 프로젝트 0개인 `owner`의 첫 뷰포트(1280×800, 390×844)에 스크롤 없이 `프로젝트 이름` 입력란과 `프로젝트 만들기` 버튼이 보인다.
  2. 화면의 solid primary 버튼은 정확히 1개다.
  3. 이름을 넣고 `프로젝트 만들기`를 누르면 그 이름이 채워진 `project-wizard`로 이동한다.
  4. 0으로 채운 수치 카드, 빈 차트, 출처 없는 수치가 0개다.
  5. 이름을 비우고 누르면 입력란 아래에 오류 문구가 나오고 포커스가 입력란에 있다.
  6. 홈 조회가 실패하면 `다시 시도`가 보이고, 누르면 다시 조회한다.
  7. `member`로 들어오면 `프로젝트 이름` 입력란과 `프로젝트 만들기`가 보이지 않고, 빈 상태 문구와 팀 소유자 이름이 보인다.
  8. 프로젝트를 만든 뒤 홈에 돌아오면 `시작 단계 1/3`이고 프로젝트 칸에 그 프로젝트가 있다.
  9. (출시 후 계측) 24시간 안 첫 프로젝트 생성 계정 비율. 화면 검증으로는 `NOT RUN`.

## Audience and Tasks

- 주요 사용자와 사용 상황: 5~20명 팀의 팀 리더가 가입 당일 데스크톱 브라우저로 처음 들어옴(핵심 사람). 팀원은 초대 메일 링크로 들어옴.
- 최우선 과업: 첫 프로젝트 만들기 시작.
- 시작 조건과 완료 조건: 시작 — 로그인 직후, 프로젝트 0개. 완료 — `project-created` 도달, 홈 복귀 시 `시작 단계 1/3`.
- 주요 불안·마찰·실패 가능성: 무엇부터 할지 모름(P1) / 초대 경로를 못 찾음(P2) / 실패하면 입력이 사라질까 / 팀원은 할 수 있는 일이 없어 보임.

## Header and Navigation

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 팀 이름 → 전역 내비(`홈` 활성) → 페이지 제목 `홈` → 보조 `시작 단계 0/3` → 주 행동(시작 단계 1의 `프로젝트 만들기`).
- 머리에서 내린 것: 환영 문구·제품 소개는 두지 않음. 초대는 시작 단계 2와 내비 `팀원`으로. 계정 메뉴는 사이드바 하단으로.
- 데스크톱 내비게이션: 좌측 고정 사이드바 240px. 팀 이름 → `홈`·`프로젝트`·`팀원`·`설정` → 하단 사용자.
- 모바일 대체 구조: 상단 바(메뉴 버튼 + 팀 이름), 내비는 드로어.

## Core Message

- 핵심 약속: 화면 문구는 시작 단계 1의 제목 `첫 프로젝트`. 별도 헤드라인을 두지 않음.
- 설명: 없음 — 제목으로 충분
- 증거: `시작 단계 0/3` — 그 계정의 실제 진행 상태.
- 사용자가 다음에 이해해야 할 것: 프로젝트 다음에 초대, 그다음에 첫 할 일이 온다는 것. 문장 없이 2·3번 행의 번호와 라벨로 전달.

## Section Order

`owner`, 프로젝트 0개 기준. 블록 순서는 역할과 상태가 달라도 같고, 노출만 달라집니다.

1. 화면 머리(`홈` + `시작 단계 0/3`): 여기가 어디이고 얼마나 남았나.
2. 시작 단계(1 첫 프로젝트 — 입력과 주 행동 / 2 팀원 초대 / 3 첫 할 일 배정): 지금 무엇을 하고 그다음은 무엇인가. 머리 바로 아래인 이유 — 핵심 사람의 첫 질문.
3. 내 할 일 칸: 배정된 일은 어디서 보나. 단계가 끝나면 이 칸이 주인공(`DESIGN.md` "할 일과 다음 행동이 먼저").
4. 프로젝트 칸: 만든 것은 어디에 생기나.

## CTA Strategy

- Primary: `프로젝트 만들기` — 목적지 `project-wizard`(입력한 이름 전달). 시작 단계 1행에 1회.
- Secondary: 없음.
- 반복 규칙: 빈 칸(내 할 일·프로젝트)에서 CTA를 반복하지 않음. 단계가 넘어가면 primary가 그 단계로 옮겨 감 — 1/3: `초대 보내기`(같은 자리에서 `invite-sent`), 2/3: `할 일 추가`(`project-board`의 `task-form`). 3/3이면 시작 단계 블록이 사라짐.
- 완료·실패 피드백: 완료 — `project-created`, 홈 복귀 시 단계 1에 체크와 프로젝트 이름. 실패 — 입력란 아래 오류 문구, 입력값 유지.

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 실패하면 입력이 사라질까 / 초대가 누구에게 갔나 / (팀원) 내가 뭘 해야 하나.
- 그 직전에 제시할 근거: 오류 때 입력값을 그대로 둠 / `invite-sent`에 보낸 주소와 상태를 보여 줌 / 팀원 빈 상태에 팀 소유자 이름을 보여 줌.
- 출처·날짜·검증 가능성: 모두 그 계정의 실제 데이터. 외부 주장 없음.
- 근거가 없을 때 생략할 요소: 고객 수·후기·배지·"5분" 문구·"나중에 바꿀 수 있어요" 같은 확인되지 않은 약속.

## Desktop Structure

- 기준 뷰포트: 1280×800
- 첫 뷰포트: 사이드바 + 화면 머리 + 시작 단계 전체 + 내 할 일·프로젝트 칸. 0건이면 스크롤 없음.
- 그리드·pane·콘텐츠 위계: 사이드바 240px 고정 + 본문 1열(최대 880px). 시작 단계 1행이 가장 큼. 아래 칸은 내 할 일 2/3 : 프로젝트 1/3.
- 스크롤 흐름과 밀도 변화: 데이터가 생기면 같은 칸이 행으로 채워져 아래로 늘어남. 3/3 이후 시작 단계가 사라지고 두 칸이 머리 바로 아래로 올라옴.

## Performance Budget

- 첫 화면 필수 자산: 앱 번들, 계정 상태 조회 1회, 폰트 1개.
- 지연 가능한 자산: 없음(이미지·영상·차트 없음).
- 폰트 weight·이미지·영상·모션 예산: 가변 폰트 1파일. 이미지 0, 영상 0. 모션은 상태 전환뿐이고 장식 모션 0.
- 저성능 기기와 느린 네트워크 폴백: 뼈대 → 내용. 폰트는 swap으로 시스템 sans 먼저.

## Accessibility Contract

- 문서·랜드마크·헤딩 읽기 순서: 건너뛰기 링크 → `nav`(전역) → `main`. h1 `홈` → h2 `시작 단계`(진행은 "3단계 중 0단계 완료"로 읽힘) → h2 `내 할 일` → h2 `프로젝트`. 단계는 순서 목록, 현재 단계에 `aria-current="step"`.
- 키보드·포커스·Escape 동작: Tab 순서 내비 → 프로젝트 이름 → 프로젝트 만들기 → 칸. 입력란에서 Enter는 제출. 모바일 드로어는 Escape로 닫히고 포커스가 메뉴 버튼으로 돌아옴.
- 레이블·오류 연결·상태 알림: 입력란에 보이는 라벨 `프로젝트 이름`. 오류 문구는 `aria-describedby`로 연결하고 즉시 알림. 조회 실패·갱신은 live region.
- 대비·색 외 신호·터치 타깃: 현재 단계는 채운 번호 원 + 굵은 제목, 완료는 체크 + 흐린 글자, 남은 단계는 빈 번호 원 — 색 없이 구분. 타깃 44px 이상. 본문 대비 4.5:1 이상.
- reduced-motion과 대체 경험: 전환 없이 즉시 바뀜. 뼈대 깜빡임 정지.

## Prompt Contract

GOAL — 프로젝트 0개인 팀 소유자가 홈 첫 뷰포트에서 첫 프로젝트 만들기를 시작하게 한다. 데이터가 생기면 같은 자리를 내 할 일·프로젝트로 채운다.
AUDIENCE — 핵심: 가입 당일의 팀 리더(`owner`). 보조: 초대로 들어온 팀원(`member`).
TASK — 프로젝트 이름 입력 → `프로젝트 만들기` → `project-wizard`.
FLOW — home(0/3) → project-wizard → project-created(1/3) → invite-sent(2/3) → task-form → task-assigned(3/3). 실패: 입력 오류·조회 실패에서 같은 자리 복구.
HEADER — 사이드바(팀 이름, 홈·프로젝트·팀원·설정, 사용자) + 본문 머리 `홈` + `시작 단계 0/3`. 머리에 설명·배지·버튼을 더하지 않는다.
MESSAGE — 헤드라인 없음. 단계 제목 `첫 프로젝트`, 라벨 `프로젝트 이름`, 번호와 라벨만으로 순서를 전달. 설명 문장 0.
FACTS — 이 문서 `Scenario Facts`만 인용. 표에 없는 날짜·숫자·상태를 지어내지 않는다.
CONTENT_INTEGRITY — 시안 데이터는 prototype. "5분", 생성률 수치는 화면에 쓰지 않는다. 0으로 채운 수치·빈 차트 금지.
SECTION_ORDER — 머리 → 시작 단계 → 내 할 일 칸(2/3) + 프로젝트 칸(1/3).
CTA — solid primary 1개: `프로젝트 만들기`. secondary 없음. 단계가 넘어가면 primary가 `초대 보내기`, `할 일 추가`로 옮겨 간다.
TRUST — 오류 때 입력 유지, 보낸 초대 주소 표시, 팀원 빈 상태에 팀 소유자 이름. 후기·배지·확인 안 된 약속 금지.
ASSETS — 이미지·일러스트 없음. 폰트는 `DESIGN.md`, 로드 경로 확인 전 시스템 sans.
LAYOUT — `docs/design-refs/2026-11-11-layout-home-first-run.md`와 와이어프레임 SVG. 시각 값은 `DESIGN.md`.
RESPONSIVE — 이 문서 `Mobile Transformations`. 사이드바는 드로어, 입력과 버튼은 풀폭 두 줄, 칸은 내 할 일 → 프로젝트.
STATES — loading(뼈대), empty(owner·member), error(입력·조회), success, permission, stale. 이 문서 `States`.
PERFORMANCE — 첫 화면 요청은 앱 번들 + 계정 상태 1회 + 폰트 1개. 장식 모션 0.
ACCESSIBILITY — 이 문서 `Accessibility Contract`. 단계 상태는 색 없이 구분.
PRESERVE — 좌측 내비 + 본문 1열(`DESIGN.md` Layout), primary 1개 규칙, 기존 빈 상태 문구 `아직 프로젝트가 없습니다`.
EXCLUDE — KPI 카드, 차트, 최근 활동 피드, 환영 문단, 튜토리얼 카드, 템플릿 갤러리, Slack 안내, 시간 추적, 리포트.
SUCCESS — 이 문서 `Page Goal`의 성공 조건 1~8.
