## 기능형 컴파일러 블록

```text
INTERFACE MODE
- 없음

PRIMARY ACTION
- 프로젝트 만들기

INFORMATION ARCHITECTURE
- 계속 남는 문맥: 사이드바(팀 이름, 홈·팀원·팀 설정, 사용자), 시작 단계 진행(n/3)
- 비교해야 하는 필드: 없음
- 상세로 숨겨도 되는 필드: 없음 (프로젝트가 생기기 전에는 숨길 것이 없다)

DENSITY
- low
- 시작 단계 3행(지금 단계 112px, 남은 단계 56px), 패널 1(본문 1열), 기본 노출: 주 행동 1 + 단계 이름 2 + 빈 칸 1

STATE MODEL
- loading / empty / error / permission / success(home-step-done)

EFFECT BUDGET
- 장식 효과 0
- 상태 모션만(단계 완료 표시, 상태 알림)
- 구현 단계 A
```

## 블록 순서

| # | 블록 | anatomy 체크 | 변주 |
|---|---|---|---|
| 1 | Sidebar | 팀 이름 / 내비 3(홈 활성 1·팀원·팀 설정) / 하단 사용자 | 항목은 3개. 5~7을 채우려고 늘리지 않음. 프로젝트 묶음은 1개 이상일 때만 |
| 2 | 화면 머리 | 제목 `홈` / 보조 1(`시작 단계 0/3` 진행) | 주 행동은 머리가 아니라 3번 블록에 둠. 설명 문장 없음 |
| 3 | 다음 한 단계 + 남은 단계 | 지금 단계 카드(번호 + primary 1) / 남은 단계 2행(번호 + 이름) | 지금 단계만 2px 테두리와 채워진 버튼. 카드 제목 없음 — 버튼 문구가 단계 이름을 겸함 |

마법사(`project-new`)는 사이드바 없는 중앙 단일 카드다: 제목 → 필드 1~2 → 풀폭 CTA → `건너뛰기` → 스텝 도트.
3/3만 필드가 2개(할 일 제목, 담당자)다.

## 덜어내기

성공 조건 번호는 Experience Contract `Page Goal`의 것이다.

| 블록·문구 | 기여 | 판정 |
|---|---|---|
| 사이드바 홈·팀원·팀 설정 | 현재 위치. 팀원 초대 경로를 한 번에 닿게 함(P2) | 남김 |
| 사이드바 하단 사용자 | 어느 계정으로 들어왔는지 확인 (anatomy Sidebar 구조) | 남김 |
| 제목 `홈` | 현재 위치, h1 | 남김 |
| `시작 단계 0/3` 진행 | 성공 조건 3 — 남은 단계가 보임 | 남김 (머리의 보조 한 가지) |
| 1단계 `프로젝트 만들기` | 성공 조건 1, 주 과업의 첫 단계 | 남김 |
| 남은 단계 이름 2행 | 성공 조건 3, 리더의 "그다음은" | 남김 (조작 없음, 이름만) |
| `프로젝트` 칸과 한 줄 | 결과가 놓일 자리 (anatomy 첫 실행 변형이 구조로 지정) | 남김 |

뺀 것:

- 환영 문단 — 어느 성공 조건에도 닿지 않는다.
- "5분 안에 첫 보드" 문구 — 측정되지 않은 가정(Content Integrity `hypothesis`).
- 단계마다 붙는 설명 문장 — 단계 이름만으로 뜻이 통한다.
- 1단계 카드의 제목 줄 — 버튼 문구와 같은 말이라 버튼만 남겼다.
- 기능 소개 카드 3장(보드·초대·할 일) — 과업 단계가 아니다.
- 0으로 채운 KPI·빈 차트 — anatomy 금지이자 상류 제외 항목.
- "내 할 일" 구역 — 상류 범위에 없는 기능 묶음.
- 사이드바의 빈 `프로젝트` 묶음 — 본문 프로젝트 칸과 겹친다. 프로젝트가 생기면 나타난다.
- 머리의 검색·알림 벨 — 범위 밖.
- 홈의 `팀원 초대` 보조 버튼 — 2단계 차례가 되면 주 행동으로 나타난다. 그 전에는 사이드바 `팀원`으로 닿는다.
- `Home.tsx`의 "아직 프로젝트가 없습니다." — owner에게는 다음 행동을 말하지 않아 뺐고, 할 수 있는 행동이 없는 member 빈 상태에만 쓴다.

남긴 설명 문구와 이유:

- `만든 프로젝트가 여기에 표시됩니다` (홈 프로젝트 칸) — 빈 상태임을 말한다. 글자 없는 점선 칸은 로딩이나 오류처럼 보인다.
- `한지원 님이 프로젝트를 만들면 여기에 표시됩니다` (member 빈 상태 ⑫) — member는 직접 풀 수 없으므로 누가 풀 수 있는지 알린다.
- 오류 문구 3종(⑩ ⑪, 1/3 입력 오류) — 회복 안내.

과하게 뺐는지: 데스크톱은 800px 중 596px, 모바일은 844px 중 568px까지 내용이 있다. 빈 부분이 절반에 못 미쳐 되돌린 것은 없다.
⑫(member, 프로젝트 0개)는 절반 넘게 빈다. 설명이나 장식으로 채우지 않았다. member에게 프로젝트 만들기를 숨긴다는 미결 권장안의 결과이며,
그 결정이 `표시`로 바뀌면 이 자리에 주 행동이 생긴다.

## 다섯 기준 판단

| 기준 | 화면에서 관찰한 근거 | 수정한 결정 |
|---|---|---|
| 위계 | 데스크톱·모바일 모두 가장 진한 면은 `프로젝트 만들기` 버튼 하나이고 다음이 제목이다. 프로젝트 빈 칸은 면적이 비슷해도 점선·회색이라 뒤로 물러난다 | 지금 단계 카드를 남은 단계(56px)의 두 배(112px)로 키우고 빈 칸을 128px로 줄여 주 행동이 가장 큰 채움이 되게 했다 |
| 구조 | 번호 순서가 spec 목표 문장의 순서(프로젝트 → 초대 → 첫 할 일)와 같다. 행동 블록 다음에 결과가 놓일 칸이 온다 | 없음 |
| 흐름 | ①→②→③→④→⑤로 진입에서 완료까지 이어진다. 실패는 ⑩ `다시 시도`, ⑪ `다시 보내기`·`건너뛰기`로 풀리고, 건너뛴 뒤에는 ⑥에서 이어 간다 | 마법사 1/3의 버튼을 `다음`에서 `프로젝트 만들기`로 바꿨다. 이 버튼에서 프로젝트가 실제로 만들어지므로 뒤 단계에서 닫거나 건너뛰어도 남는다는 것을 문구가 말해야 한다 |
| 일관성 | 채워진 버튼은 화면마다 하나, `건너뛰기`는 밑줄 글자, 완료 알림은 하단 한 줄로 같다. 초대 상태는 ④와 ⑦에서 같은 이름(`초대 보냄`)이다 | 마법사 3/3의 제목을 `첫 할 일`에서 홈의 단계 이름과 같은 `첫 할 일 배정`으로 맞췄다 |
| 명료성 | 홈의 설명 문장은 프로젝트 칸의 한 줄뿐이다. 그 줄을 지워도 번호·버튼·`시작 단계 0/3`으로 다음 행동을 알 수 있다 | 없음. 설명을 더해서 통과시킨 곳 없음 |

## 역할과 상태

- 역할: spec 역할 표에서 owner·member 모두 `공용 권한차등`. 같은 홈 위에서 member는 시작 단계 블록과 `팀 설정`이 숨겨진다(⑫).
  변형표 초안은 Experience Contract `Role Variants`에 있고 Phase 4-1-1에서 확정한다.
- 상태: loading ⑨, empty ①, error ⑩ ⑪, success ⑤ ⑥ ⑦ ⑧, permission ⑫. 이름은 Experience Contract `States`와 같다.

## 아직 그리지 않은 것

- `invite-accept`와 그 만료 상태(`stale`), `task` 패널, 프로젝트 메뉴 다이얼로그, members의 초대 입력 다이얼로그와 초대 취소.
- 세 단계를 모두 마친 뒤의 홈(프로젝트 목록만 남는 상태).
- 대표 화면 밖 화면의 Mode와 블록 순서는 Phase 4-1에서 정한다. 보드는 `Mode: 없음 — 칸반 보드`가 될 것으로 본다.
