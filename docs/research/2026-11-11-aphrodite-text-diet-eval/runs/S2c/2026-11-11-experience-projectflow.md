## Page Goal

- 사용자가 이 화면에서 달성할 결과: 프로젝트가 0개인 홈에서 첫 프로젝트를 만들기 시작하고, 마법사를 거쳐 그 프로젝트의 보드에 도착한다.
- 제품이 얻어야 하는 결과: 가입 후 24시간 안에 첫 프로젝트를 만드는 계정 비율 60% 이상(spec 공유 전제, 현재 30%).
- 관찰 가능한 성공 조건:
  1. owner가 프로젝트 0개인 홈을 열면 1280×800과 390×844에서 스크롤 없이 `프로젝트 만들기` 버튼이 보이고, 채워진 버튼은 그것 하나다.
  2. `프로젝트 만들기` → project-new 1/3 → 2/3 → 3/3 → `board-created`까지 키보드만으로 갈 수 있다. 2/3·3/3을 건너뛰어도 `board-created`에 도착한다.
  3. 건너뛴 단계는 홈에 남은 단계로 보이고, 그 단계의 행동이 홈의 유일한 채워진 버튼이 된다(`home-step-done`).
  4. member의 홈에는 프로젝트 만들기·팀원 초대 조작이 없고, 프로젝트가 0개면 빈 상태 문안이 보인다.
  5. 홈에 KPI 수치·차트·시간 추적·리포트 요소가 없다.

## Audience and Tasks

- 주요 사용자와 사용 상황: 팀 리더(owner)가 가입 직후 데스크톱에서 처음 연다. 이어서 초대받은 팀원(member)이 초대 메일로 들어온다.
- 최우선 과업: 첫 프로젝트를 만든다 → 팀원을 초대한다 → 첫 할 일을 배정한다.
- 시작 조건과 완료 조건: 시작 — 로그인됨, owner, 프로젝트 0개. 완료 — 만든 프로젝트의 보드가 열림(`board-created`).
  초대와 첫 할 일은 건너뛸 수 있고 홈의 남은 단계로 돌아온다.
- 주요 불안·마찰·실패 가능성: 무엇부터 할지 모름(P1), 초대 위치를 모름(P2), 초대 주소를 지금 모름, 초대 전송 실패, 이름을 잘못 지음.

### 사람 카드

**팀 리더 (owner) — 핵심 사람**

- 누구인가: 한지원, 34세, 8명 규모 디자인 스튜디오 "스튜디오 온"의 PM. 엑셀과 메신저로 일을 나눠 왔다.
- 처음 오는 이유와 마음: 팀 일을 한곳에 모으려고 가입. 막막함 — 빈 도구를 채우는 일이 자기 몫.
- 알고 싶은 것: ① 지금 뭘 먼저 하면 되나(home) ② 몇 단계 남았나(home) ③ 팀원은 어떻게 부르나(home 남은 단계, project-new 2/3, members)
  ④ 만들면 어떤 모습이 되나(board) ⑤ 잘못 만들면 고칠 수 있나(board 프로젝트 메뉴)
- 성공한 순간: 팀원 이름이 붙은 첫 할 일이 보드에 놓인 것을 본 때.
- 주로 쓰는 화면: home, project-new, board.

**팀원 (member)**

- 누구인가: 김도윤, 29세, 같은 스튜디오 디자이너. 초대 메일로 처음 들어온다.
- 처음 오는 이유와 마음: 리더가 불러서. 호기심 반, 도구가 또 늘었다는 피로 반.
- 알고 싶은 것: ① 내가 할 일이 뭔가(board) ② 누가 불렀고 어떤 팀인가(invite-accept) ③ 처리했다고 어떻게 알리나(board)
- 성공한 순간: 자기 이름이 붙은 할 일을 `완료`로 옮긴 때.
- 주로 쓰는 화면: board.

핵심 사람은 팀 리더다. 리더가 첫 프로젝트를 만들지 않으면 팀원이 들어올 곳이 없다.

## Header and Navigation

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 사이드바(팀 이름 → 홈·팀원·팀 설정 → 프로젝트 목록 → 사용자) → 본문 머리(제목 `홈` + 시작 단계 진행) → 지금 단계의 주 행동.
- 머리에서 내린 것: 환영 문구·제품 설명은 싣지 않음. 팀원 초대 버튼은 머리가 아니라 2단계 차례에 주 행동으로 나타남. 검색·알림은 범위 밖.
- 데스크톱 내비게이션: 좌측 고정 사이드바 240px. 활성 항목 1개. 프로젝트 목록은 1개 이상일 때만.
- 모바일 대체 구조: 상단 바(메뉴 버튼 · 팀 이름 · 사용자) + 드로어.

## Core Message

- 핵심 약속: 지금 할 일은 하나, `프로젝트 만들기`다.
- 설명: 없음 — 제목으로 충분. 버튼 문구와 번호 붙은 남은 단계가 대신한다.
- 증거: 남은 단계 수(`시작 단계 0/3`)와 단계 이름. 사용자 자신의 진행 상태뿐이다.
- 사용자가 다음에 이해해야 할 것: 프로젝트를 만든 뒤 팀원 초대와 첫 할 일 배정이 이어지고, 건너뛰어도 홈에 남는다는 것.
  번호 순서, 단계 완료 표시, 프로젝트 칸의 위치로 전달한다.

## Section Order

1. 화면 머리(`홈` + `시작 단계 0/3`): "지금 어디고 얼마나 남았나"에 답한다.
2. 시작 단계(지금 단계의 주 행동 + 남은 단계 이름): "지금 무엇을 하나, 그다음은"에 답한다. 머리 바로 아래에 와야 스크롤 없이 주 행동이 보인다.
3. 프로젝트 칸(빈 상태): "만들면 어디에 생기나"에 답한다. 행동 다음에 결과 자리가 온다.

## CTA Strategy

- Primary: `프로젝트 만들기` → project-new 1/3. owner, 프로젝트 0개인 홈에 진입하자마자 1회.
- Secondary: 홈에는 없음. 마법사 2/3·3/3의 `건너뛰기`(밑줄 글자)만.
- 반복 규칙: 홈의 주 행동은 남은 단계에 따라 하나만 바뀐다 — `프로젝트 만들기` → `팀원 초대`(members의 초대 입력) → `첫 할 일 배정`(board의 `+ 할 일 추가`).
  세 단계를 모두 마치면 시작 단계 블록이 사라지고 사이드바와 프로젝트 목록이 이동을 맡는다.
  마법사의 주 행동: 1/3 `프로젝트 만들기`, 2/3 `{n}명에게 초대 보내기`, 3/3 `추가하고 보드 열기`.
- 완료·실패 피드백: 완료는 도착 화면 하단의 상태 알림 한 줄(`프로젝트를 만들었습니다 · 2명에게 초대 보냄`).
  실패는 실패한 입력 바로 아래 한 줄 + 같은 자리의 다시 시도 버튼. 입력값은 지우지 않는다.

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 초대를 보내기 직전(누구에게 무엇이 가나), 단계를 건너뛸 때(다시 할 수 있나), 초대 메일을 연 팀원(진짜 초대인가).
- 그 직전에 제시할 근거: 입력한 주소가 칩으로 그대로 보이고 버튼이 인원 수를 말한다. 건너뛴 단계는 홈에 남은 단계로 남는다. 초대 수락 화면은 초대한 사람과 팀 이름을 보여 준다.
- 출처·날짜·검증 가능성: 모두 사용자 입력과 계정 데이터. 외부 주장 없음.
- 근거가 없을 때 생략할 요소: 고객 수, 후기, 보안 배지, 소요 시간 약속.

## Desktop Structure

- 기준 뷰포트: 1280×800
- 첫 뷰포트: 사이드바 + 제목 `홈` + `시작 단계 0/3` + 1단계 카드(`프로젝트 만들기`) + 남은 단계 2줄 + 프로젝트 빈 칸. 스크롤 없음.
- 그리드·pane·콘텐츠 위계: 사이드바 240px 고정 + 본문 1열(최대 720px, 왼쪽 정렬). 위계는 주 행동 버튼 > 제목 > 남은 단계 이름 > 빈 칸.
- 스크롤 흐름과 밀도 변화: 첫 실행은 한 뷰포트에 끝난다. 프로젝트가 생기면 프로젝트 칸이 행 목록으로 자라며 아래로 늘어난다.

| error: project-new 1/3 | 이름이 비었거나 저장 실패 | 입력 아래 `프로젝트 이름을 입력하세요` 또는 `프로젝트를 만들지 못했습니다` | 고쳐서 다시 제출 | 입력값 유지 |
| error: project-new 2/3 | 초대 메일 전송 실패 | 주소 칩 유지 + `초대를 보내지 못했습니다` + `다시 보내기` | 다시 보내기, 건너뛰기 | 프로젝트는 이미 만들어져 있고 홈 2단계가 남음 |
| permission | member, 프로젝트 0개인 home | 시작 단계 블록 없음. `아직 프로젝트가 없습니다` + `한지원 님이 프로젝트를 만들면 여기에 표시됩니다` | 팀원 보기 | owner가 만들면 목록에 나타남 |
| stale | 만료된 초대 링크로 invite-accept 진입 | `초대가 만료되었습니다` + 초대한 사람 이름 | 로그인으로 이동 | 초대한 사람이 members에서 다시 보냄 |

프로젝트 만들기·팀원 초대·프로젝트 고치기의 member 값도 상류에 없다. 모두 `Open Decisions`에 올렸다.
member에게 시작 단계 블록과 프로젝트 만들기를 숨기면 프로젝트 0개인 홈이 비므로 `permission` 상태의 빈 상태 문안을 둔다.

## Performance Budget

- 첫 화면 필수 자산: 앱 셸, 홈 화면 코드, 프로젝트 목록 응답 1건, 폰트 1종.
- 지연 가능한 자산: 보드·할 일 상세·팀원 화면 코드(홈에서 지연 로드).
- 폰트 weight·이미지·영상·모션 예산: Pretendard Variable 1파일, 이미지·영상 0, 장식 효과 0, 상태 모션만(단계 완료 표시, 상태 알림).
- 저성능 기기와 느린 네트워크 폴백: 뼈대 화면을 먼저 그리고, 폰트가 늦으면 시스템 sans-serif로 먼저 보여 준다.

## Accessibility Contract

- 문서·랜드마크·헤딩 읽기 순서: nav(사이드바) → main. h1 `홈` → 시작 단계(순서 있는 목록, 지금 단계에 `aria-current="step"`) → h2 `프로젝트`.
- 키보드·포커스·Escape 동작: Tab 순서는 사이드바 → 주 행동 → 프로젝트 칸. 마법사는 단계가 바뀌면 그 단계 제목으로 포커스를 옮긴다.
  Escape는 다이얼로그(프로젝트 메뉴·초대 입력)만 닫고 마법사는 `닫기` 버튼으로 나간다.
- 레이블·오류 연결·상태 알림: 입력마다 보이는 레이블 또는 제목 연결. 오류 문구는 입력과 `aria-describedby`로 연결하고 `role="alert"`. 완료 알림은 `role="status"`.
- 대비·색 외 신호·터치 타깃: 본문 4.5:1 이상. 단계의 완료·지금·남음은 색이 아니라 체크·채움·번호로 구분. 조작 요소는 44×44px 이상.
- reduced-motion과 대체 경험: 상태 모션을 끄고 즉시 바뀐 상태를 보여 준다. 정보는 모션에 싣지 않는다.

## Prompt Contract

GOAL — 프로젝트 0개인 owner가 홈에서 첫 프로젝트를 만들기 시작해 마법사 3단계를 거쳐 보드에 도착하게 한다.
AUDIENCE — 팀 리더(owner, 가입 직후, 데스크톱, 막막함). 보조로 초대받은 팀원(member).
TASK — 프로젝트 만들기 → 팀원 초대(건너뛸 수 있음) → 첫 할 일 배정(건너뛸 수 있음).
FLOW — home(empty) → project-new 1/3 → 2/3 → 3/3 → board-created. 건너뛰면 home-step-done으로 돌아와 이어서 한다.
HEADER — 사이드바(팀 이름, 홈·팀원·팀 설정, 프로젝트 목록, 사용자). 본문 머리는 `홈` + `시작 단계 n/3`까지.
MESSAGE — 설명 문단 없음. 주 행동 문구와 번호 붙은 단계 이름으로 전달한다.
FACTS — 사실 주장 없음. 화면 데이터는 `Scenario Facts`만 인용하고 표에 없는 날짜·숫자·상태를 지어내지 않는다.
CONTENT_INTEGRITY — "5분" 약속과 생성률 수치는 싣지 않는다. 시안 데이터는 prototype.
SECTION_ORDER — 화면 머리 → 시작 단계(지금 단계 주 행동 + 남은 단계) → 프로젝트 칸.
CTA — 홈 `프로젝트 만들기` 1개. 마법사 1/3 `프로젝트 만들기`, 2/3 `{n}명에게 초대 보내기`, 3/3 `추가하고 보드 열기`, 2/3·3/3 `건너뛰기`.
TRUST — 초대 주소 칩과 인원 수가 들어간 버튼, 홈에 남는 건너뛴 단계, 초대 수락 화면의 초대한 사람·팀 이름.
ASSETS — 이미지 없음. 폰트·아이콘은 `Asset Provenance`의 상태를 따른다.
LAYOUT — [Layout Blueprint](2026-11-11-layout-projectflow.md)와 와이어프레임 3개. 사이드바 240px + 본문 1열 최대 720px.
RESPONSIVE — `Mobile Transformations` 표대로. 사이드바는 드로어, 마법사는 전체 화면 폼.
STATES — `States` 표의 loading·empty·error·success·permission·stale 전부.
PERFORMANCE — 장식 효과 0, 상태 모션만, 이미지 0.
ACCESSIBILITY — `Accessibility Contract`대로. 단계는 순서 있는 목록, 알림은 status·alert.
PRESERVE — 루트 `DESIGN.md` 토큰, 좌측 내비 + 본문 1열, primary 1개 원칙.
EXCLUDE — KPI·차트·시간 추적·리포트·Slack·알림 벨·환영 문단·기능 소개 카드·샘플 데이터.
SUCCESS — `Page Goal`의 성공 조건 1~5.

## Success Checks

- 첫 5초 안에 핵심 약속과 주 행동을 설명할 수 있는가?
- 화면의 사실·수치·후기·브랜드 자산이 출처와 상태를 가지며, unverified 항목을 사실처럼 보이지 않는가?
- 주요 과업을 막는 상태·정보·행동 누락이 없는가?
- 모바일이 데스크톱 축소판이 아니라 우선순위에 맞게 재구성됐는가?
- 아름다움, 접근성, 성능 중 하나를 다른 하나의 희생으로 얻지 않았는가?
- 홈에 설명 문단을 더하지 않고도 owner가 다음 행동을 말할 수 있는가?
