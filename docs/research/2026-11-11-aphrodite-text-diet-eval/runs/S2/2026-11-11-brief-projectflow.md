# Design Brief — 플로우보드 첫 실행 흐름

- 작성일: 2026-11-11
- Source Mode: product-derived (벤치마크 없음)
- 상류 정본: `docs/plan/projectflow/spec.md`, `docs/plan/projectflow/interview.md`, `docs/athena/projectflow.md`
- 기존 표현 정본: 루트 `DESIGN.md` (차분하고 실무적, 좌측 내비 + 본문 1열)
- 현재 구현: `src/pages/Home.tsx` — `<h1>홈</h1>` + "아직 프로젝트가 없습니다." (다음 행동 없음)
- `PRODUCT.md`: 루트에 없음. 이번 실행의 쓰기 범위가 `docs/design-refs/`뿐이라 초안을
  [2026-11-11-product-draft-projectflow.md](2026-11-11-product-draft-projectflow.md)에 두었다. 확인 후 루트 `PRODUCT.md`로 옮긴다.

## 무엇을 만드는가

가입 직후 프로젝트가 0개인 계정이 홈에서 바로 첫 프로젝트를 만들고, 팀원을 초대하고, 첫 할 일을 배정해
보드에 도착하는 첫 실행 흐름. 대표 화면은 **프로젝트 0개인 홈**이다.

## 누가 어떤 상황에서 쓰는가 — 사람 카드

spec `이해관계자` 표의 구분과 이름을 그대로 쓴다.

### 팀 리더 (역할 ID `owner`) — 핵심 사람

- 누구인가: 7명 디자인 스튜디오의 팀장 한지우(30대). 방금 이메일 링크로 가입했고 계정에 아무것도 없다.
- 처음 오는 이유와 마음: 메신저와 엑셀에 흩어진 일을 한곳에 모으려 한다. 써 보고 아니면 바로 닫을 생각이라 조급하다.
- 알고 싶은 것 → 답이 보일 화면
  1. 지금 뭘 하면 시작되나 → home(프로젝트 0개)
  2. 몇 단계나 남았나 → home·setup-invite·setup-task의 단계 표시
  3. 팀원을 어디서 부르나 → setup-invite, board 머리
  4. 초대한 사람이 들어왔나 → board 머리의 팀원 줄, members
  5. 누가 무엇을 맡았나 → board 카드
- 성공한 순간: 보드에 담당자가 붙은 할 일 카드가 하나 생긴 것을 본 순간
- 주로 쓰는 화면: home, board, members

### 팀원 (역할 ID `member`)

- 누구인가: 같은 스튜디오의 디자이너 박서준(20대). 초대 메일의 링크를 눌러 들어왔다.
- 처음 오는 이유와 마음: 리더가 불렀다. 새 도구가 하나 더 생긴 것이 번거롭다.
- 알고 싶은 것 → 답이 보일 화면
  1. 내가 맡은 일이 무엇인가 → board 카드
  2. 다른 사람은 무엇을 하고 있나 → board 열
  3. 끝냈다고 어떻게 알리나 → board 카드 이동, task-detail 상태
- 성공한 순간: 맡은 카드를 '완료'로 옮긴 순간
- 주로 쓰는 화면: board, task-detail

핵심 사람은 **팀 리더**다. 리더가 첫 프로젝트를 만들기 전에는 팀원이 올 곳이 없고, spec 성공 기준(첫 프로젝트 생성률)과
P1이 모두 이 사람의 첫 화면을 가리킨다.

## 최우선 과업과 완료 조건

- 과업: 프로젝트 이름 입력 → 팀원 초대 → 첫 할 일 배정
- 완료 조건: 보드에 담당자가 붙은 카드 1건이 보인다
- 성공 지표에 잡히는 시점: 1단계(프로젝트 만들기) 완료. 2·3단계는 건너뛸 수 있다

## 망설이거나 불신하는 지점

| 지점 | 사람 | 대응 (문장이 아니라 구조로) |
|---|---|---|
| 빈 화면에서 무엇을 할지 모름 (P1) | 팀 리더 | 홈이 곧 1단계 입력 칸이다. 따로 누를 시작 버튼이 없다 |
| 얼마나 걸릴지 모름 | 팀 리더 | 단계 이름 3개를 처음부터 보여 준다 |
| 남의 이메일을 넣는 순간 | 팀 리더 | 보내기 전에 받을 주소를 행으로 보여 주고 지울 수 있다. 버튼에 인원 수를 쓴다 |
| 초대가 갔는지 모름 | 팀 리더 | 보낸 뒤 사람마다 `초대 보냄` 상태가 붙는다 |
| 초대 경로가 설정 깊숙이 있음 (P2) | 팀 리더 | 마법사 2단계 + 보드 머리 팀원 줄 끝 + 사이드바 `팀원` |

## 제약

- 기술: React 18 + Vite SPA, REST API, 인증은 이메일 링크 (spec `기존 환경`)
- 콘텐츠: 고객 수·후기·배지 같은 사실 주장을 싣지 않는다. 화면에 낼 검증된 제품 사실이 없다
- 브랜드: `DESIGN.md` — primary는 주 행동과 현재 위치에만, accent는 경고에만
- 접근성: 키보드만으로 3단계 완료, 오류는 입력 칸에 연결, 끌어 옮기기에는 대체 조작
- 제외(상류): 팀 성과 KPI 대시보드, 시간 추적, 리포트 내보내기, Slack 알림

## 관찰 가능한 성공 기준

Experience Contract `Page Goal`의 성공 조건 7개가 정본이다. 제품 지표는 spec의 "가입 후 24시간 안에 첫
프로젝트를 만드는 계정 비율 60% 이상(현재 30%)"이다.

## 넣을지 판정 — 여섯 질문

| 후보 | 출처 | 판정 | 이유 |
|---|---|---|---|
| 프로젝트 생성 마법사 | 상류 include | keep | 핵심 갈등(P1)을 푼다. 1단계를 홈에 그대로 두어 시작 클릭을 없앤다 |
| 팀원 초대 | 상류 include | keep | 리더의 성공한 순간에 필요하다. 없으면 혼자 쓰다 그만둔다(P2) |
| 할 일 보드 | 상류 include | keep | 두 사람 모두의 성공한 순간이 보드에서 일어난다 |
| 팀 성과 KPI 대시보드 | 상류 exclude | cut | 아테나 삭제 권고, Soft Gate 3 제외. 0건 계정에 보여 줄 숫자가 없다 |
| 시간 추적 · 리포트 내보내기 · Slack 알림 | 상류 exclude | cut | 상류 제외 그대로 |
| 홈의 진행 체크리스트 카드 | 설계 중 | lighten | 따로 카드를 두지 않고 마법사의 단계 표시가 겸한다 |
| 샘플 프로젝트 자동 생성 | 설계 중 | cut | 직접 만든 것이 아니어서 성공 지표를 흐리고, 지워야 할 일이 생긴다 |
| 환영 문구·도움말 카드·제품 투어 | 설계 중 | cut | 설명으로 이해시키는 화면이 된다. 누구의 질문에도 답하지 않는다 |
| 앞으로 채워질 보드의 빈 미리보기 | anatomy 첫 실행 변형 | cut | 성공 조건 어디에도 기여하지 않는다. 단계 이름이 같은 일을 한다 |
| 완료 축하 화면 | 설계 중 | lighten | 화면을 더 만들지 않고 보드 도착 모습(카드 1건 + 상태 알림)이 끝이다 |
| 댓글 | spec 역할 표(member 주요 업무) | 미결 | MVP 포함 목록에도 제외 목록에도 없다. Experience Contract `Open Decisions`(scope) |

상류 요구를 빼거나 가볍게 한 판정은 없다. 설계 중 떠올렸다가 뺀 것만 기록했다.

## 제품 세계에서 가져온 구조 근거 (레퍼런스 없음)

- 화이트보드에 세로 줄을 긋고 포스트잇을 옮기는 방식 → 보드의 열과 카드
- 포스트잇에 적는 것은 "무엇을, 누가" 두 가지 → 카드의 필수 요소는 제목과 담당자
- 팀장이 회의 끝에 일을 나눠 주는 순서(일감 정하기 → 사람 부르기 → 맡기기) → 마법사 3단계 순서

색·타입·재질은 Phase 3에서 `DESIGN.md`를 기준으로 정한다. 이 브리프는 정하지 않는다.

## 시장 관례

`NOT APPLICABLE` — 데스크톱 우선 업무용 웹앱이다. 한국 사용자 대상 모바일 앱·모바일 우선 웹앱이 아니어서
