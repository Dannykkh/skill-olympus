## Page Goal

- 사용자가 이 화면에서 달성할 결과: 프로젝트가 0개인 홈에서 이름을 적어 첫 프로젝트를 만들고, 이어서 팀원을 초대하고 첫 할 일을 배정해 보드에 도달한다
- 제품이 얻어야 하는 결과: 가입 후 24시간 안에 첫 프로젝트를 만드는 계정 비율 60% 이상 (spec, 현재 30%)
- 관찰 가능한 성공 조건:
  1. 프로젝트 0개인 계정의 홈 첫 뷰포트(1280×800, 390×844)에 "프로젝트 이름" 입력과 "프로젝트 만들기" 버튼이 스크롤 없이 보인다
  2. 이름을 적고 버튼을 한 번 누르면(또는 Enter) 프로젝트가 저장되고 `setup-invite`가 열린다
  3. 빈 이름으로 누르면 같은 화면에 오류 글이 뜨고 포커스가 입력으로 간다. 저장 실패 뒤에도 적은 이름이 남아 있다
  4. `setup-invite`와 `setup-task`를 모두 넘겨도 `setup-done`을 거쳐 `board`에 도달한다
  5. 홈 어디에도 KPI 카드·차트·0으로 채운 숫자가 없다
  6. `member`로 들어오면 "팀 설정"·"내보내기"·"초대 취소"가 보이지 않는다

## Audience and Tasks

- 주요 사용자와 사용 상황: 가입 당일의 팀 리더(`owner`). 5~20명 팀, 프로젝트 0개, 쓸 만한지 몇 분 안에 판단하려 한다
- 최우선 과업: 첫 프로젝트 만들기 → 팀원 초대 → 첫 할 일 배정
- 시작 조건과 완료 조건: 이메일 링크로 로그인했고 프로젝트가 0개 → 보드에 담당자가 있는 할 일 1건. 최소 완료는 프로젝트 생성
- 주요 불안·마찰·실패 가능성: 빈 화면에서 무엇을 할지 모름(P1), 초대 메일에 무엇이 가는지 모름, 아직 들어오지 않은 사람에게 맡겨도 되는지 모름, 건너뛴 초대를 나중에 어디서 하는지 모름(P2)

사람 카드 (상세는 브리프):

| 사람 | 역할 ID | 처음 오는 마음 | 알고 싶은 것 → 답이 보이는 곳 | 성공한 순간 |
|---|---|---|---|---|
| 팀 리더 한서윤 (핵심 사람) | `owner` | 막막함, 빨리 판단하고 싶음 | 무엇부터 하지 → `home` 첫 실행의 입력과 주 행동 / 몇 단계지 → 단계 표시 / 만들면 뭐가 생기지 → 보드 미리보기 / 팀원은 어떻게 → `setup-invite`, 보드 머리 | 보드에 첫 할 일이 담당자와 함께 놓임 |
| 팀원 오준호 | `member` | 귀찮음, 내 일만 알고 싶음 | 내가 맡은 일 → `home`의 내 할 일 / 어느 프로젝트·누가 맡겼나 → 그 행의 보조 정보 / 남들은 뭘 하나 → `board` | 맡은 할 일을 "진행 중"으로 옮김 |

## Header and Navigation

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 플로우보드 → 홈(활성) → 프로젝트 목록 → 팀원 → 사용자 영역. 주 행동은 내비가 아니라 본문에 둔다
- 머리에서 내린 것: 환영 문구와 제목 아래 설명 문장은 쓰지 않는다(단계 표시가 같은 정보를 준다). 2·3단계에서 프로젝트 이름은 제목 옆이 아니라 내비의 활성 항목과 보드 미리보기 머리에 둔다. 보드 머리의 화면 설명·필터·정렬은 두지 않는다
- 데스크톱 내비게이션: 좌측 고정 내비. 활성 항목 하나만 강조. 프로젝트가 0개면 "프로젝트" 구역 자체를 그리지 않는다
- 모바일 대체 구조: 상단 바(현재 위치 이름 + "메뉴" 버튼). 프로젝트 안에서는 상단 바가 프로젝트 이름을 보여 준다

## Section Order

`home` 첫 실행:

1. 제목 "첫 프로젝트 만들기": 지금 무엇을 하는 화면인지 답한다
2. 단계 표시: 몇 단계가 남았는지 답한다. 제목 바로 아래에 있어야 입력 전에 부담을 가늠한다
3. "프로젝트 이름" 입력과 "프로젝트 만들기": 무엇부터 하면 되는지 답한다. 첫 뷰포트의 주인공
4. 보드 미리보기: 만들면 무엇이 생기는지 답한다. 입력한 이름이 미리보기 머리에 그대로 비친다

`setup-invite`·`setup-task`는 같은 순서(제목 → 단계 표시 → 입력 → 행동 → 보드 미리보기)를 지키고, 미리보기에 앞 단계의 결과가 쌓인다. `setup-done`은 제목 → 결과 3행 → "보드 열기". `home`(프로젝트 있음)은 내 할 일 → 프로젝트 목록으로, 첫 실행의 입력 자리를 내 할 일이, 미리보기 자리를 프로젝트 목록이 채운다.

## CTA Strategy

- Primary: 화면마다 하나
  - `home` 첫 실행: "프로젝트 만들기" → 프로젝트 저장 뒤 `setup-invite`. 입력 오른쪽(모바일은 바로 아래 전체 폭)에 처음부터 보인다
  - `setup-invite`: "N명에게 초대 메일 보내기" → `setup-task`. N은 적은 주소 수
  - `setup-task`: "할 일 배정" → `setup-done`
  - `setup-done`: "보드 열기" → `board`
  - `board`: "할 일 추가". `team`: "팀원 초대" (`owner`)
- Secondary: `setup-invite`의 "나중에 초대", `setup-task`의 "나중에 하기" (둘 다 다음 단계로), `board` 머리의 "팀원 초대" (`owner`)
- 반복 규칙: 한 화면에 같은 주 행동을 두 번 두지 않는다. 팀원 초대는 건너뛴 사람을 위해 `board` 머리와 `team`에서 다시 나온다
- 완료·실패 피드백: 성공은 다음 화면으로의 이동과 단계 표시의 체크로 알린다. 실패는 같은 화면의 오류 글로 알리고 입력을 지우지 않는다. 제출 중에는 버튼 글이 "만드는 중"으로 바뀌고 다시 누를 수 없다

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 초대 메일 발송 직전, 초대 대기 중인 사람에게 배정하는 순간, 단계를 건너뛰는 순간
- 그 직전에 제시할 근거: 발송 버튼에 받는 사람 수, 입력 아래 한 줄 "프로젝트 이름과 참여 링크가 담긴 메일이 발송됩니다.", 담당자 선택지의 "초대 대기" 표시, `setup-done`의 결과 3행
- 출처·날짜·검증 가능성: 모두 사용자가 방금 입력한 값이라 화면에서 바로 대조된다. 초대 상태는 `team`에서 다시 확인하고 취소할 수 있다
- 근거가 없을 때 생략할 요소: 소요 시간 약속, 사용 팀 수, 후기, 보안 배지, 초대 링크 만료 기간(정책이 상류에 없음), "이름은 나중에 바꿀 수 있습니다"(프로젝트 이름 고치기가 미결)

## Desktop Structure

- 기준 뷰포트: 1280×800
- 첫 뷰포트: 좌측 내비 232px + 본문 1열(최대 860px). 본문 위에서부터 제목, 단계 표시, 입력과 주 행동, 보드 미리보기. 주 행동의 아래 끝이 y=239에 있다(와이어프레임 실측)
- 그리드·pane·콘텐츠 위계: pane은 내비와 본문 둘. 가장 진한 것은 제목·현재 단계·입력 테두리·주 행동이고, 보드 미리보기는 점선과 옅은 글로 한 단계 물러나 있다
- 스크롤 흐름과 밀도 변화: 1단계는 스크롤 없음. 2·3단계는 입력이 늘어 보드 미리보기가 접힌 선 아래로 내려가지만 주 행동은 첫 뷰포트에 남는다
- Interface Mode: 없음 — 첫 실행 (anatomy `Dashboard`의 첫 실행 변형). `board`의 Mode는 그 화면을 설계할 때 정한다
- 효과 예산: 장식 효과 0. 상태 전환(오류 표시·단계 전환)만

## Role Variants

## Accessibility Contract

- 문서·랜드마크·헤딩 읽기 순서: 상단 바 또는 내비(nav) → main의 h1 → 단계 표시(순서 목록, 현재 단계는 `aria-current="step"`) → 폼 → 보드 미리보기(h2 "보드 미리보기")
- 키보드·포커스·Escape 동작: Tab 순서는 입력 → 주 행동 → 보조 행동. 입력에서 Enter로 제출. 단계가 바뀌면 포커스를 새 h1로 옮긴다. `invite-dialog`와 `task-detail`은 Escape로 닫고 연 버튼으로 포커스를 돌려준다
- 레이블·오류 연결·상태 알림: 모든 입력에 보이는 label. 오류 글은 `aria-describedby`로 입력에 연결하고 `aria-invalid`를 켠다. 저장 실패와 참여 알림은 `role="alert"`·`role="status"`
- 대비·색 외 신호·터치 타깃: 현재 단계는 채운 번호와 굵은 글로, 완료 단계는 체크로, 초대 대기는 점선 테두리와 글자 "초대 대기"로 알린다. 색만으로 구분하지 않는다. 버튼과 칩 지우기 버튼은 좁은 화면에서 44px 이상
- reduced-motion과 대체 경험: 장식 모션이 없다. 단계 전환은 움직임 없이 내용만 바뀐다
