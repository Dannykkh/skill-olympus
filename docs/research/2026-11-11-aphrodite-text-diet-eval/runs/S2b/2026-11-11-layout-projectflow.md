## 덜어내기

블록과 문구마다 `Page Goal`의 성공 조건이나 과업 단계에 기여하는지 댔다. 기여는 위 표의 "기여하는 과업 단계" 열에 있다.

뺀 것:

| 뺀 것 | 이유 |
|---|---|
| 환영 문단, 제목 아래 설명 문장 | 과업 단계에 기여하지 않는다. 남은 단계는 단계 표시가 전달한다 |
| KPI 카드 행, 차트, 0으로 채운 숫자 | anatomy 첫 실행 변형이 금지하고, 상류가 KPI 대시보드를 제외했다 |
| 기능 소개 카드, 도움말·가이드 링크 | 첫 프로젝트 만들기의 어느 단계도 아니다 |
| 프로젝트 템플릿 고르기 | 첫 단계를 선택지로 늘린다. 상류에 없다 |
| 내비의 빈 "프로젝트" 구역 | 0건일 때 라벨만 남는다. 프로젝트가 생기면 나타난다 |
| 보드 미리보기의 설명 문장("프로젝트를 만들면 이런 보드가 열립니다") | h2 라벨 "보드 미리보기"와 점선 표현으로 충분하다 |
| `setup-task`의 마감일 입력 | 첫 배정에는 제목과 담당자면 된다. 보드와 할 일 상세에서 정한다 |
| `setup-done`의 단계 표시 | 결과 3행이 같은 세 라벨을 값과 함께 보여 준다. 처음 그렸다가 스크린샷을 보고 뺐다 |
| `home`(프로젝트 있음)의 h1 "홈" | 내비와 상단 바가 이미 위치를 말한다. 가장 큰 글자를 "내 할 일 1"에 줬다 |
| 보드 열 끝의 "+ 할 일 추가" 행 | 머리의 "할 일 추가"와 같은 행동이 두 번 나온다 |

남긴 설명 문구:

| 문구 | 위치 | 남긴 이유 |
|---|---|---|
| "프로젝트 이름과 참여 링크가 담긴 메일이 발송됩니다." | `setup-invite` 입력 아래 | 신뢰 근거. 내 이름으로 남에게 무엇이 가는지는 라벨과 버튼만으로 알 수 없다 |
| "프로젝트를 만들지 못했습니다. 입력한 이름은 그대로 있습니다. 다시 눌러 주세요." | `home` 저장 실패 | 오류 상태의 회복 안내 |
| "프로젝트 이름을 입력하세요." | `home` 입력 오류 | 오류 상태의 회복 안내 |
| "봄 시즌 브랜드 리뉴얼에 참여했습니다." | `home` (`member` 참여 직후) | 상태 알림. 초대 링크를 누른 결과를 알린다 |

빼지 않은 구조 요소: 단계 표시(남은 단계 진행), 보드 미리보기(앞으로 채워질 구역), 입력 label, 초대 대기 표시.

빈 자리 점검: 처음 그린 대표 화면은 데스크톱에서 뷰포트 아래 32%, 모바일에서 35%가 비어 있었다. 설명이나 장식으로 채우지 않고, 결과가 놓일 자리인 보드 미리보기의 열을 키워 데스크톱 691/800, 모바일 706/844까지 채웠다. 2·3단계는 처음에 아래 절반이 비어 있었고, 같은 원칙으로 보드 미리보기를 단계 내내 유지해 앞 단계의 결과(프로젝트 이름, 초대한 사람, 첫 카드)가 쌓이게 했다. `setup-done`·`home`(프로젝트 있음)·`team`은 데이터가 1~3건인 시점이라 아래가 비지만 대표 화면이 아니며, 더할 과업 요소가 없어 그대로 뒀다.

| 기준 | 화면에서 관찰한 근거 | 판정 | 고친 결정 |
|---|---|---|---|
| 위계 | `home-desktop.png`: 가장 진한 것은 h1, 채운 번호 "1", 입력 테두리, 검은 버튼 네 가지이고 모두 한 과업을 가리킨다. 보드 미리보기는 점선·옅은 글이라 두 번째로 읽힌다. 주 행동 아래 끝이 데스크톱 y=239, 모바일 y=314로 첫 뷰포트 안이다 | 통과 | 모바일에서 입력이 가는 선으로 찌그러져 버튼만 보였다. 입력 높이를 48px로 고정했다 |
| 구조 | 제목 → 단계 표시 → 입력·행동 → 미리보기가 팀 리더의 질문 순서(무엇부터, 몇 단계, 무엇이 생기나)와 같다. 내비는 프로젝트 0개에서 홈·팀원 둘뿐이다 | 통과 | 홈(프로젝트 있음)의 가장 큰 글자가 "홈"이었다. 팀원의 첫 질문에 맞춰 "내 할 일 1"로 바꿨다 |
| 흐름 | HTML에서 실행: 빈 이름 제출 → 오류 글 표시·입력에 포커스·`aria-invalid` → 이름 입력(미리보기 머리에 같은 이름, 오류 글 사라짐) → Enter → "팀원 초대" → "첫 할 일 배정" → "보드가 준비됐습니다" → 보드. 저장 실패 화면(`home-fail-*.png`)은 입력값이 남아 있다 | 통과 | 모바일에서 오류 글이 버튼 아래에 떴다. 입력 바로 아래로 옮겼다. 모바일 `team`에서 `owner`의 "팀원 초대"가 사라졌다. 보드 전용 규칙이 새던 것을 고쳤다 |
| 일관성 | 세 단계가 같은 자리에 같은 순서(제목, 단계 표시, 입력, primary 왼쪽·secondary 오른쪽, 미리보기)를 쓴다. "초대 대기"는 담당자 선택·미리보기 카드·보드 카드·팀원 화면에서 같은 말과 같은 점선 아바타다. 화면마다 solid 버튼은 하나다 | 통과 | 1단계 미리보기 라벨만 "만들면 열리는 보드"였다. 세 단계 모두 "보드 미리보기"로 맞췄다 |
| 명료성 | 화면에 남은 설명 문장은 초대 메일 한 줄뿐이다. 그 줄을 지워도 label "초대할 사람의 이메일"과 버튼 "2명에게 초대 메일 보내기"로 다음 행동을 안다. 1·3단계와 보드에는 설명 문장이 없다 | 통과 | 미리보기 설명 문장과 완료 화면의 단계 표시를 뺐다 |

시각 시안 전에 정해진 주 행동: "프로젝트 만들기", "N명에게 초대 메일 보내기", "할 일 배정", "보드 열기", "할 일 추가", "팀원 초대". Phase 3 후보가 이 밖의 주 행동을 만들면 이 게이트로 돌아온다.

## 역할별 화면

spec 시스템 역할 표의 `화면` 열이 두 역할 모두 `공용 권한차등`이므로 같은 블록 순서 위에서 요소 노출만 다르게 그렸다. 초안 변형표는 계약의 `## Role Variants`에 있다.

| 화면 | `owner` | `member` | 근거 스크린샷 |
|---|---|---|---|
| `team` | "팀원 초대", "내보내기", "다시 보내기", "초대 취소" 표시 | 넷 모두 숨김. 목록은 남는다 | `team-*.png`, `team-member-*.png` |
| 내비 사용자 영역 | "팀 설정" 표시 | 숨김 | `home-desktop.png`, `home-member-desktop.png` |
| `board` 머리 | "팀원 초대" 표시 | 숨김 (권장안, 구조 미결) | `board-*.png` (`owner`만 그림) |

역할을 지웠을 때 화면이 비는 곳은 없다. `member`의 `team`은 주 행동이 사라지지만 목록이 남고, `board`는 "할 일 추가"가 남는다.
