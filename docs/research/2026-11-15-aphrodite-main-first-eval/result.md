# 아프로디테 메인 우선 배치 검증

2026-11-15 · codex · Phase 2 와이어프레임의 실제 렌더 평가

**기본 배치는 개선됐다. 확대 회귀도 발견했으며, 지침 보강과 예제의 렌더 후 수정을 구분해 검증했다.**
지침만으로 모든 첫 생성 결과가 통과한 것은 아니다. 완료 전에 실제 렌더를 확인하는 게이트가 필요하다.

## 방법

- 별도 컨텍스트 5개가 각각 지침을 처음 읽고 실행했다. 작업자에게 기대 결과·실측 기준·기존 실패는 제공하지 않았다.
- A: HEAD의 변경 전 지침으로 발주 목록. B: 처음 수정한 지침으로 같은 발주 목록.
- C: 처음 수정한 지침으로 매뉴얼 편집기와 빈 문서.
- D: 확대 대응을 보강한 지침으로 같은 편집기·빈 문서를 새로 실행.
- E: 보강한 지침으로 같은 발주 목록을 새로 실행. 최초 결과를 보존한 뒤, 메인이 발견한 렌더 문제만 같은 작업자가 최소 수정했다.
- A/B/E의 PRODUCT.md·DESIGN.md와 사용자 요청은 동일하다. C/D도 입력과 요청을 유지했다.
- 작업자는 HTML/CSS/JS와 Phase 2 문서를 만들었고 브라우저는 사용하지 않았다. 메인이 원본을 별도 보존한 후 Chromium 156 / Windows에서 렌더링·관찰·실측했다.
- 기본 폭은 1280×800, 390×844, 360×800. 글자 확대는 모든 요소의 계산된 font-size·고정 line-height를 2배로 바꾸었다.
- 200% 전체 확대는 390×844를 195×422 CSS 배치 폭으로 환산했다. 실제 브라우저 UI 줌·실기기 인증은 아니다.
- 목록 비교는 모두 지연 발주 3건 선택 상태로 맞췄고, 실제 표 셀 글자는 16px임을 확인했다. 제목이나 빈 테두리를 데이터 항목으로 세지 않았다.
- HTML 좌표와 스크린샷을 함께 봤다. 확대 뒤에는 포커스를 해제하고 scrollY=0을 확인하여 첫 화면을 측정했다.

공통 문법 #9에 다음을 보강했다.

- 기본 한 행은 출발점이며 높이는 내용에 따라 늘어날 수 있어야 한다.
- 고정 높이·overflow:hidden으로 한 행을 강제하지 않는다.
- 문서 가로 스크롤 수치에 더해 핵심 조작의 실제 위치·잘림·클릭 가능 여부를 확인한다.

D의 편집기·빈 문서는 기본 세 폭과 확대 두 조건에서 저장 등 확인 대상 조작의 화면 밖 위치·클릭 중심 가림이 재현되지 않았다. 확대에서는 헤더와 도구 모음이 늘어나며 세로 스크롤을 허용한다. 확대 상태에 기본 크기의 한 행·상단 절반 기준을 강제하지 않았다.

## 목록 E에서 추가로 발견한 회귀와 수정

보강된 지침의 독립 생성 E도 첫 결과가 모두 통과하지는 않았다.

1. 195px 배치 폭에서 결과 도구가 x110px부터 162px를 차지해 right272px까지 넘쳤다. 정렬과 더보기가 화면 밖으로 갔다.
2. 모바일에서 시각적으로 숨긴 thead의 전체 선택 체크박스가 포커스 가능한 상태로 남았다.
3. 글자 200%에서 건너뛰기 링크는 top=-60px, 높이110px가 되어 bottom50px까지 나타나 제목을 덮었다. 실제 hit target으로도 확인했다.

최초 HTML/CSS/JS는 runs/candidate-list-r2에 보존했다. 이후 작업자에게 위 관찰만 전달했다. 수정본은 runs/candidate-list-repaired에 별도로 보존했다.

- 결과와 도구 줄을 flex-wrap으로 재배치하고 실제 가용 폭 안에서 정렬을 배치했다. 글자 크기는 줄이지 않았다.
- 숨긴 표 머리의 체크박스는 모바일 포커스에서 제거했다. 실제 행의 체크박스와 복수 선택·배정은 유지했다.
- 건너뛰기 링크는 자신의 높이를 기준으로 숨기고 포커스 시 나타나게 했다.

| 수정본 검사 | 기본 3폭 | 글자 200% / 390px | 확대 환산 / 195px |
|---|---|---|---|
| 문서 가로 넘침 | 없음 | 없음 | 없음 |
| 확인 대상 조작의 화면 밖 위치 | 없음 | 없음 | 없음 |
| 화면 내 확인 대상의 클릭 중심 가림 | 없음 | 없음 | 없음 |
| 미포커스 건너뛰기 링크 bottom | -16px | -16px | -16px |

확대 환산에서는 온전한 발주 행이 첫 화면 안에 다 들어오지 않으며 세로 스크롤이 필요하다. 이를 글자 축소로 해결하지 않았다. 위 PASS는 기본 배치와 검사한 조작 가시성에 한정한다.

## 한계와 미검증

- 시나리오별 독립 생성은 1회다. 같은 모델의 샘플링 차이가 있으므로 개선 폭 전체를 특정 지침 한 줄의 인과 효과로 단정하지 않는다.
- Phase 2 구조 검증이다. Phase 3의 미학·브랜드 방향과 실제 앱 구현에서 동일한 결과가 유지되는지는 NOT RUN.
- 실제 사용자 평가·백엔드·권한·데이터 저장·전체 접근성 인증·성능은 NOT RUN. 프로토타입 메뉴와 상태 시트를 완성된 제품 기능으로 세지 않았다.
- 제공한 PRODUCT.md는 승인된 내용을 한국어 제목으로 적은 평가 fixture다. 일부 실행의 정본 검사기는 strategy/scope 필수 제목 누락을 FAIL로 보고했다. 입력을 바꾸지 않았으며 전체 파이프라인 PASS라고 주장하지 않는다.
- 기존 wrapcheck의 raw 결과에는 닫힌 details의 텍스트와 sr-only 라벨이 포함됐다. 해당 집계를 화면의 실제 결함 개수로 쓰지 않았다. 브라우저 checkVisibility·좌표·hit target과 스크린샷으로 확인했다. 한국어 줄바꿈 전체 PASS를 주장하지 않는다.
- E의 최초 독립 출력에는 확대 회귀가 있었다. 최종 목록의 확대 통과는 렌더 후 수정 결과이며 독립 첫 생성 통과로 바꾸어 기록하지 않았다.
