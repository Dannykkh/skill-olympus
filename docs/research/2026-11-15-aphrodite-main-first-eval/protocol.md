# 평가 계획 — 작성자와 분리한 와이어프레임 실행

작성: 2026-11-15, codex. 사전 지표이며 작업자에게 전달하지 않는다.

- A/B는 PRODUCT.md·DESIGN.md·자연어 요청·출력 제약이 동일하다. 차이는 지침 스냅샷(HEAD / 현재 작업 트리)이다. C는 현재 지침의 편집기·빈 문서 일반화 확인이다.
- 모든 실행은 Phase 2까지다. 독립 실행의 HTML을 메인이 변경 없이 렌더링한다.
- 뷰포트: 1280×800, 390×844, 360×800. 후보는 폰 폭 390에서 CSS 글자 200%와 browser-equivalent layout zoom 200%를 별도로 확인한다. 두 확대는 별도 검사이며 실제 브라우저 UI 줌과 동일하다고 주장하지 않는다.
- 관찰 지표: 전역 내비·페이지 헤더·탭·주 작업 도구 모음까지의 상단 누적 높이, 첫 실제 행·문서 본문·입력 영역의 y, 첫 화면에 완전히 보이는 실제 항목 수, 작업 표면의 가시 높이.
- 구조 판정: 실제 내용이 위쪽 절반 안에서 시작하는가, 상단보다 작업 영역이 충분히 큰가, 페이지/지역/선택 조작이 범위에 맞게 배치됐는가. 제목과 빈 테두리만 보이는 것은 실제 콘텐츠로 세지 않는다.
- 회귀 판정: 자주 쓰는 핵심 조작과 현재 조건·필드 라벨·복구 경로가 남는가, 본문·컨트롤이 겹치거나 페이지 전체가 수평으로 넘치지 않는가, 0건·빈 문서에도 첫 작업을 시작할 수 있는가.
- HTML 버튼의 기능성은 프로토타입 범위만 확인한다. 백엔드·권한·제품 전체 QA 통과로 해석하지 않는다.
- baseline이 이미 좋으면 차이를 과장하지 않는다. 1회씩 실행한 결과는 반복 안정성이나 일반적 인과 효과의 증거가 아니다.
- 실패가 나오면 최초 산출물·실측을 보존한 뒤 실제 원인만 수정하고 영향 범위를 재검증한다. 작업자가 읽지 않은 규칙과 규칙 자체의 결함을 구분한다.
