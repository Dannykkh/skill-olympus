# 디자인 브리프 — 발주 목록

- Source Mode: product-derived
- 정본: 프로젝트 루트 PRODUCT.md, DESIGN.md. 두 파일은 수정하지 않았다.
- 요청: “아프로디테 --plan-only로 구매 담당자의 발주 목록 화면을 설계해줘. 데스크톱 1280×800과 모바일 390×844의 저충실도 와이어프레임까지 만들어줘.”
- 실행 경계: 명시된 별도 지시를 따라 Phase 0~2까지만 실행한다. 기본 --plan-only의 Phase 0~4보다 이 경계가 우선한다.
- Product Design Gate: NOT APPLICABLE — --plan-only이며 Phase 3·5에 진입하지 않음.
- 제작 방식: 외부 API·패키지·브라우저·전역 설정 없이 로컬 회색조 HTML/CSS. 작은 JS는 와이어프레임의 상태 전환만 담당한다.

## 무엇을 만드는가

발주 목록 한 화면과 그 화면의 상태 시트다. 앱 내 발주·거래처·입고·보고서·설정, 워크스페이스·계정 진입점을 보존한다. 다른 업무 화면이나 신규 KPI·통계를 설계하지 않는다.

## 누가 언제 쓰는가

구매 담당자가 데스크톱에서 지연 발주의 납기·금액·담당자를 비교하고, 미배정 건을 골라 담당자를 배정한다. 외근 중에는 폰으로 같은 정보를 확인하고 필요한 발주를 선택한다. PRODUCT.md의 역할은 하나이며 새 역할 ID나 인물 설정을 만들지 않았다.

## 최우선 과업과 완료

1. “지연 3건 보기” 또는 상태 필터로 지연 발주를 찾는다.
2. 금액·납기와 현재 담당자를 확인하고 하나 이상 선택한다.
3. “담당자 배정”에서 김민수 또는 이서연을 선택한다.
4. 완료 알림과 바뀐 담당자 값을 확인한다. 지연 상태 자체는 배정으로 바뀌지 않는다.

## 망설임과 회복

- 선택 범위와 기존 담당자 덮어쓰기가 불안할 수 있다. 배정 직전 선택 건수·발주번호·현재 담당자를 다시 보여준다.
- 검색 결과가 없으면 조건을 유지하고 “검색·필터 초기화”를 제공한다.
- 배정 실패 시 선택·담당자를 유지한 재시도를 설계한다.
- 재조회 실패 시 이전 결과임을 알리고 새로 불러오게 한다. 확인되지 않은 갱신 시각을 만들지 않는다.

## 제약과 제품 근거

- 12건 샘플·지연 3건과 모든 행 값은 PRODUCT.md를 그대로 사용한다. 운영 사실이 아니므로 헤더에 “프로토타입 · 샘플 데이터”를 표시한다.
- 발주번호·거래처·품목·금액·납기·상태·담당자는 모두 남긴다. 비교가 목적이므로 데스크톱은 표, 폰은 같은 행을 발주별 정보 묶음으로 변환한다.
- 기능의 추가·삭제 없이 필터·목록 도구·행 메뉴로 노출 위계를 정한다.
- DESIGN.md에 따라 회색조·시스템 한글 폰트·본문 16px·단순 선을 사용한다. 사진·브랜드 자산·효과·외부 폰트는 사용하지 않는다.
- 데스크톱 우선 반응형 웹앱이다. 한국 모바일 앱 유형 분류·시장 앱 조사는 적용하지 않는다.

## 관찰 가능한 성공 조건

- 1280×800에서 발주 목록·검색·지연 진입·필수 비교 열과 행 선택을 볼 수 있다.
- 390×844에서 가로 표를 밀지 않고 발주 식별·상태·납기·금액·담당자를 확인할 수 있다.
- 필터 조건·결과 수가 함께 바뀌고 초기화할 수 있다.
- 복수 선택 → 배정 → 완료 값 확인과 검색 결과 없음 → 초기화를 따라갈 수 있다.
- 모든 필수 기능에 직접 노출 또는 이름 있는 메뉴 진입점이 있다.

## 벤치마크와 미결

벤치마크가 주어지지 않았다. 구매 장부의 행 비교와 PRODUCT.md의 실제 필드·과업을 구조 근거로 삼았다. 기간의 기준, 부분 실패·충돌 처리, 후속 화면의 경계는 Experience Contract의 Open Decisions에 모았다. 대상·범위를 바꾸는 미결은 없다.

## 실행 제약과 규칙 해석

| 원문 | 적용 |
|---|---|
| “--plan-only / Phase 0~4 실행.” | 이번 실행의 “Phase 2까지 진행하고 멈춤”이 더 구체적이므로 Phase 3·4를 수행하지 않는다. |
| “HTML이면 각 뷰포트의 스크린샷을 남기고” | 메인 평가자가 스크린샷·브라우저 검증을 맡는다는 명시 지시가 우선한다. 본 에이전트의 실제 렌더·다섯 기준 최종 통과는 NOT RUN이다. |
| “데이터 행 6~10”, “헤더 행 … 4~6열” | anatomy의 기본값이다. 필수 7개 정보와 12건 샘플을 삭제하지 않고 행 선택·메뉴를 더한 표를 사용한다. |
| “반복 요소는 … 개수는 3~6” | 주문 데이터 건수를 장식 반복의 기본값에 맞춰 줄이지 않는다. 결과 12건을 같은 anatomy로 표시한다. |
