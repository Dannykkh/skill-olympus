## Page Goal

- 사용자가 이 화면에서 달성할 결과: 열려 있는 매뉴얼의 제목·본문을 수정하고 저장 결과를 확인한다. 문서가 없으면 제목과 첫 문장을 작성한다.
- 제품이 얻어야 하는 결과: 업무 문서 작성과 짧은 수정이 같은 작업 공간에서 이어진다.
- 관찰 가능한 성공 조건:
  1. 두 기준 뷰포트에서 본문 또는 첫 입력이 위쪽 절반 안에서 시작하며 읽거나 쓸 수 있는 내용이 보인다.
  2. 제목·저장 상태·저장 동작이 구별되고 본문 도구가 작업면 가까이에 있다.
  3. 승인된 모든 기능이 기본 영역 또는 라벨 있는 메뉴에서 발견된다.
  4. 새 문서는 “문서 제목”, “본문”, “작성 시작”으로 첫 행동을 제시한다.
  5. 저장 실패 시 작성 내용과 “다시 저장”이 함께 보이며 완료 시 “모든 변경사항 저장됨”으로 바뀐다.
  6. 폰에서 앱 탐색·서식·문서 메뉴를 열고 편집 문맥으로 돌아올 수 있다.

## Header and Navigation

## CTA Strategy

- Primary: 기존 문서는 “저장” → 같은 화면의 editor-saved 상태. 새 문서에서는 “작성 시작” → 본문 포커스, 입력 후 저장 활성화.
- Secondary: “미리보기” → 대화상자에서 내용 확인 후 닫기.

## States

| State | Trigger | User sees | Available action | Recovery |
|---|---|---|---|---|
| loading | 문서 열기 | 문서를 불러오는 중입니다 | 불러오기 취소 | 빈 작업면으로 복귀; 본문 입력은 로드 후 |
| empty | 새 문서 | 문서 제목·본문 입력과 작성 시작 | 직접 입력·작성 시작 | 첫 문장 입력 |
| dirty | 제목·본문 수정 | 저장하지 않은 변경사항 | 저장·계속 편집 | 저장 |
| saving | 저장 실행 | 저장 중… | 진행 확인 | 실패 시 error |
| success / editor-saved | 저장 완료 | 모든 변경사항 저장됨 + 작성 본문 | 미리보기·계속 편집 | 같은 화면에서 후속 작업 |
| validation-error | 제목 없이 저장 | 문서 제목을 입력하세요. 작성한 본문은 그대로 있습니다 | 제목 입력 | 제목 채운 후 저장 |
| error | 저장 실패 | 본문 유지 + 저장 실패 안내 | 다시 저장 | 성공 시 editor-saved |
| permission | 편집 권한 변경 | 읽기 전용·본문 유지 | 문서 정보 | 권한 회복 방식은 Open Decisions |
| stale | 다른 버전 존재 | 본문 유지·버전 확인 필요 | 버전 기록 | 비교·충돌 처리 정책은 Open Decisions |

## Prompt Contract

GOAL — 제목·본문을 직접 수정하고 보존 여부 확인; 빈 상태에서 첫 문장 시작.
AUDIENCE — 편집 권한을 가진 운영 담당자 한 역할.
TASK — 입력→수정→저장→미리보기; 실패→내용 유지→재시도.
FLOW — 새 제품 화면 없이 같은 편집기 상태 전환.
HEADER — 제목·저장 상태·저장. 나머지 조작은 영향 범위 가까이.
MESSAGE — 매뉴얼 실제 내용·명시적 상태. 설계 의도를 안내 카드로 옮기지 않음.
FACTS — PRODUCT.md 샘플과 Scenario Facts만 사용.
CONTENT_INTEGRITY — prototype 표시; 운영 데이터·실제 저장 사실 주장 금지.
SECTION_ORDER — 앱 탐색 + 문서 머리→본문 도구→작업면→하단 정보.
CTA — 저장 한 곳, 빈 상태 작성 시작, 미리보기는 보조.
TRUST — 제목 아래 상태와 본문 인접 오류 복구.
ASSETS — 외부 자산 없음.
LAYOUT — Layout Blueprint의 메인 우선 영역·상단 두 줄 유지.
RESPONSIVE — 탐색 replace, 드문 서식 collapse, 종이 외부 여백 remove.
STATES — loading·empty·dirty·saving·success·validation-error·error·permission·stale.
PERFORMANCE — 패키지 설치·외부 요청 없음.
ACCESSIBILITY — 의미 있는 HTML·레이블·키보드·상태 알림; 실제 검증 미실행을 명시.
PRESERVE — 모든 PRODUCT.md 승인 기능과 전체 샘플 본문.
EXCLUDE — 마케팅·성과 KPI·AI 요약·협업 서버·인증·결제.
SUCCESS — Page Goal의 6개 조건을 메인이 실제 렌더로 확인.

## Success Checks

- 구조 판독 후보: 본문이 가장 큰 작업 대상이며 저장이 단일 주 행동.
- 정적 확인: 두 HTML의 한국어 lang·viewport·단일 main·로컬 스타일 연결 확인, JS 구문 검사 통과.
- NOT RUN: 실제 뷰포트 관찰, 입력·저장 경로 런타임, 접근성·성능·한글 줄바꿈 실측. 메인이 스크린샷과 완료 판정을 담당한다.
- Phase 2에서 중단. 구조 게이트의 실제 관찰 승인은 pending이며 계획 전체 완료나 미학 통과를 선언하지 않는다.
