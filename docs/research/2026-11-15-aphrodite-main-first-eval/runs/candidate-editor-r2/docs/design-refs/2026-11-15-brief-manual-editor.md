# 디자인 브리프 — 사내 매뉴얼 편집

- Source Mode: product-derived. 외부 벤치마크·조사·API를 사용하지 않았다.
- 범위: Phase 0~2만. 사용자가 명시한 중단 지점이 일반 `--plan-only`의 Phase 0~4보다 우선한다.
- 정본: [PRODUCT.md](../../PRODUCT.md), [DESIGN.md](../../DESIGN.md). 변경하지 않는다.
- 만드는 것: 문서 편집과 새 문서 빈 상태의 회색조 HTML/CSS 와이어프레임. 같은 반응형 구조를 1280×800, 390×844에서 본다.
- 사용자: 편집 권한을 가진 운영 담당자 한 역할. 데스크톱에서 본문을 고치고 저장·미리보기하며 폰에서는 짧게 수정한다.
- 최우선 과업: 현재 본문에서 수정할 곳을 찾고 고친 뒤, 저장 상태를 확인한다. 빈 상태에서는 제목과 첫 문장을 작성하기 시작한다.
- 완료 조건: 본문과 첫 행동이 첫 뷰포트 상반부에서 시작하고, 수정·저장·미리보기·실패 복구의 위치가 이어진다.
- 불안: 수정 내용 손실, 저장 여부 불명, 좁은 폰에서 도구가 본문을 밀어냄. 상태 문구와 복구 행동을 작업 영역에 인접하게 둔다.
- 제약: 회색조·시스템 한글 폰트·본문 16px. 외부 폰트·사진·패키지·브랜드 효과 없음. 모든 승인 기능의 접근 경로 유지, 추가 제품 화면 없음.
- 관찰 가능한 성공 기준: 본문/첫 입력이 위쪽 절반에서 시작; 저장과 상태가 식별됨; 모든 승인 기능에 라벨이 있는 경로 존재; 실패 시 본문이 유지되고 다시 저장 가능; 390px에서 탐색·서식을 펼칠 수 있음.

## 사람 카드 — 최초 가정

아래는 동일한 승인 역할의 두 사용 상황이다. 추가 역할이나 실제 사용자 조사 결과가 아니다. Phase 2 계약의 Audience and Tasks가 이후 정본이다.

## 근거·제외

문서라는 업무 실물에서 왼쪽 탐색 → 본문 가까운 서식 → 넓은 종이 작업면의 구조를 유도했다. KPI·빈 차트·환영 카드·AI 요약·마케팅 설명은 제품 과업에 기여하지 않으므로 넣지 않았다. 국내 모바일 앱 시장 관례 조사는 NOT RUN — 데스크톱 우선 업무용 웹이며 외부 조회는 이번 실행 범위 밖이다.
