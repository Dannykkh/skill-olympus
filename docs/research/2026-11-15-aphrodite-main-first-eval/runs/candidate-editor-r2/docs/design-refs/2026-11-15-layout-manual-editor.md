Mode: 없음 — 문서 편집기. 첫 행동은 본문 수정이며 여러 agent·터미널 작업 문맥을 유지하는 Agent Workbench가 아니다.

## 기능형 프롬프트 컴파일러

INTERFACE MODE: 없음 — 문서 편집.
PRIMARY ACTION: 본문에 커서를 놓고 수정; 빈 상태에서는 작성 시작.
INFORMATION ARCHITECTURE: 문서 제목·저장 상태·본문이 지속 문맥. 서식은 본문 인접, 드문 문서 기능은 메뉴.
DENSITY: medium — 208px 앱 탐색 하나와 편집면 하나. 기본 도구 한 줄, 제목/상태/저장 머리 한 줄.
STATE MODEL: loading / empty / dirty / saving / error / permission / stale / success.
EFFECT BUDGET: 장식 0, 상태 모션 0. 저장 중 문구만 변경. 가장 무거운 요소는 로컬 HTML 대화상자.

## 메인·조작 배치 — 공통 문법 #9

- 주 작업 대상: 실제 매뉴얼 본문. 데이터 0건일 때는 제목/본문 입력과 첫 행동.
- 확보 영역: 데스크톱에서 탐색 208px를 제외한 가로 영역 중 종이 최대 820px. 폰에서는 탐색을 접고 전체 작업 폭을 확보.
- 페이지 조작: 저장·미리보기는 문서 머리. 드문 공유·댓글·버전·내보내기·설정은 문서 메뉴.
- 본문 조작: 서식·검색을 본문 위 한 도구 모음에 배치.
- 앱 조작: 워크스페이스·최근 문서·폴더·템플릿·즐겨찾기·계정은 탐색.
- 조회: 문서 정보·확대는 아래쪽에 배치.

| 뷰포트 | 상단 전체 행 수·누적 높이 — 설계값 | 메인 시작 — 설계값 | 첫 화면에 보여야 할 실제 내용 | 판단 |
|---|---|---|---|---|

## 덜어내기 기록

| 뺀/접은 대상 | 과업 연결과 판단 | 보존한 기능 |
|---|---|---|
| 별도 환영 Hero·제품 설명·KPI·AI 요약 | 승인된 수정/첫 문장 성공 조건에 기여하지 않음, 일부는 범위 제외 | 넓은 본문 작업면 |
| 문서 위 별도 경로·탭·메타 행 | 현재 제목과 좌측 탐색으로 위치를 알 수 있음 | 문서 제목·저장 상태 |
| 상시 펼친 공유·댓글·버전·내보내기·설정 패널 | 내용 수정이 첫 과업이므로 주 작업면의 폭/높이를 회수 | 문서 메뉴의 모든 항목 |
| 모바일의 상시 앱 탐색 | 390px에서 본문 폭을 줄임 | 탐색 열기로 모든 앱 기능 접근 |
| 모바일 목록·링크·표의 직접 버튼 | 자주 쓰는 기본 서식과 본문 영역을 우선 | 서식 메뉴로 세 기능 유지 |
| 빈 상태의 큰 그림·다중 시작 카드 | 실제 제목/본문 자리에서 바로 시작하는 편이 명료 | 작성 시작과 입력면 |

남긴 설명은 빈 상태 “첫 문장을 쓰면 이 자리가 매뉴얼이 됩니다” 한 문장과 오류 회복 문구다. 전자는 입력 후 어떤 자리가 채워지는지, 후자는 내용 보존과 다음 행동을 알려준다. 정상 편집면에는 도구 설명 문장을 추가하지 않았다. 빈 화면의 넓은 여백은 실제 본문 입력면이며 장식이나 안내 카드로 채우지 않았다.

## 다섯 기준 판단 게이트

아래는 정적 구조 판단이다. 실제 스크린샷을 관찰하지 않았으므로 렌더 게이트 통과로 승격하지 않는다.

| 기준 | HTML에서 확인할 근거 | 결정·수정 | 상태 |
|---|---|---|---|
| Hierarchy | 가장 큰 면적은 본문. 저장만 솔리드, 빈 상태는 작성 시작만 솔리드 | 메인 먼저 확보; 머리/도구 두 줄로 제한하는 시작점 | 정적 후보 확보 / 렌더 PENDING |
| Structure | 앱/문서/본문/조회 조작이 범위별로 분리됨 | 드문 조작은 메뉴, 서식은 본문 인접 | 정적 후보 확보 / 렌더 PENDING |
| Flow | empty→입력→저장→success, error→다시 저장, preview→닫기 | 완료 모습과 회복 상태를 상태 시트로 추가 | 정적 후보 확보 / 런타임 PENDING |
| Consistency | 두 상태에서 같은 머리·도구·메뉴·하단 사용 | 같은 문서 기능 이름과 배치 유지 | 정적 후보 확보 / 렌더 PENDING |
| Clarity | 제목·본문·저장·찾기·문서 메뉴 등 실제 라벨 사용 | 정상 화면의 설명 카드 제거; 빈/오류 회복만 안내 | 정적 후보 확보 / 렌더 PENDING |

## 제한과 다음 판정

HTML의 입력·메뉴·저장 상태 변경·미리보기는 구조 확인을 위한 로컬 시연이다. 실제 서식 적용·템플릿·공유 링크·댓글 전송·내보내기·서버 저장·권한 검증은 구현하지 않았다. 도구 대화상자는 승인된 기능의 접근 위치를 보이는 개략이며 실제 기능 완료로 세지 않는다. 실제 렌더에서 첫 뷰포트·줄바꿈·가림이 발견되면 이 게이트에서 수정하며 Phase 3을 먼저 진행하지 않는다.
