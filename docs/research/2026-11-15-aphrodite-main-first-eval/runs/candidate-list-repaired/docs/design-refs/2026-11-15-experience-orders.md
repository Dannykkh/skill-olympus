## Page Goal

- 사용자가 이 화면에서 달성할 결과: 지연 발주의 금액·납기를 확인해 담당자를 배정한다.
- 제품이 얻어야 하는 결과: 선택과 변경 대상이 일치하고 사용자가 결과를 목록에서 확인한다. 가상 성과 수치는 제시하지 않는다.
- 관찰 가능한 성공 조건: (G1) 두 대표 폭의 첫 화면에서 지연 행과 선택 조작이 보인다. (G2) 상태 지연으로 3건을 찾는다. (G3) PO-261101·PO-261103을 선택하고 이서연에게 배정한 뒤 두 담당자와 완료 알림이 일치한다. (G4) 결과 없음에서 초기화해 12건을 복구한다. (G5) 승인된 모든 기능의 진입점을 찾는다.

## Audience and Tasks

- 주요 사용자와 사용 상황: 중소 제조사 구매 담당자 한 역할. 데스크톱에서 발주를 비교하며 외근 중 폰에서도 확인한다.
- 최우선 과업: 지연 건 찾기→금액·납기 비교→대상 선택→담당자 확정→목록에서 변경 확인.
- 시작 조건과 완료 조건: PRODUCT.md 초기 12건으로 시작하며 선택한 대상의 담당자 변경이 보이면 완료한다.
- 주요 불안·마찰·실패 가능성: 잘못된 복수 선택, 기존 담당자 덮어쓰기, 최신성 부족, 조회 실패, 빈 결과. 배정 모달에 대상 번호·거래처·현재 담당자를 다시 노출한다.

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 앱의 ‘구매 관리’와 워크스페이스는 사이드바, 현재 ‘발주’는 페이지 제목, 생성은 ‘새 발주’로 분리한다.

- 데스크톱 내비게이션: 발주·거래처·입고·보고서·설정. 발주만 현재 위치로 표시. 하단 계정과 도움말, 상단 워크스페이스.

## Section Order

1. 앱 탐색: 어느 업무·워크스페이스인지 확인한다. 데스크톱은 왼쪽 공간을 사용한다.
2. 페이지 제목·새 발주: 현재 위치와 페이지 수준 생성 진입점. 한 행에서 시작한다.
3. 검색·필터: 대상을 좁힌다. 조건을 바꾼 경우에만 제거 가능한 요약을 표시한다.
4. 결과 수·정렬·목록 더보기: 현재 조건의 대상과 결과 작업을 확인한다.
5. 선택 도구: 대상 선택 시에만 ‘N건 선택·담당자 배정·선택 해제’가 나타난다.
6. 발주 본문: 필수 7개 필드, 체크박스, 행 조작. 화면의 가장 큰 영역이다.
7. 하단 샘플 출처와 상태 시트 링크: 검토 산출물의 보조 탐색. 운영 앱 기능으로 승격하지 않는다.

## CTA Strategy

- Primary: 초기 페이지 수준은 ‘새 발주’→작성 화면 진입점. 주 과업은 행 선택 후 나타나는 ‘담당자 배정’→배정 모달, 모달의 ‘배정하기’→orders-assigned 상태다.
- Secondary: ‘취소’는 변경 없이 선택 목록으로 돌아온다. ‘선택 해제’는 선택만 지운다. 발주번호 또는 ‘상세 열기’는 같은 행의 상세 모달.
- 반복 규칙: 페이지 생성 1개, 선택 영역 배정 1개, 확정 모달 배정 1개. 동일 범위에서 같은 강조 버튼을 반복하지 않는다.
- 완료·실패 피드백: 성공은 ‘2건의 담당자를 이서연님으로 배정했습니다.’와 실제 담당자 셀 변경. 조회·최신성·권한 실패는 인접 상태 알림과 복구 행동. 실제 배정 실패는 입력·선택을 유지하고 재시도하는 계약이며 서버 미연결로 실행하지 않았다.

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 복수 변경 확정 직전, 최신성을 확인하지 못한 상태, 보관 직후.
- 그 직전에 제시할 근거: 모달의 정확한 대상 목록·현재 담당자, 명시적인 최신성 상태와 새로고침, 보관 완료의 발주번호·실행 취소.
- 출처·날짜·검증 가능성: 샘플 출처 PRODUCT.md, 확인일 2026-11-15. 실제 서버 확인 시각은 없으므로 ‘방금 동기화’나 가상 시각을 표시하지 않는다.
- 근거가 없을 때 생략할 요소: 회사 고객 수·처리 성과·보안 배지·인증 상태·응답 속도·실제 동기화 시각.

- 기준 뷰포트: 1280×800.
- 첫 뷰포트: 지연 3건을 포함한 실제 데이터 행과 선택 조작. CSS 기반 예상은 테이블 y=184px, 데이터 시작 약 y=227px이다. 실제 위치와 보이는 행 수는 메인 브라우저 관찰 대기.
