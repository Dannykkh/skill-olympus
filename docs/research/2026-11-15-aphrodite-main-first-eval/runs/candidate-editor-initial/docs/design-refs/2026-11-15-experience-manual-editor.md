## Page Goal

- 사용자가 이 화면에서 달성할 결과: 문서의 제목·본문을 편집하고 저장 여부를 확인한다. 새 문서에서는 바로 첫 문장을 시작한다.
- 제품이 얻어야 하는 결과: 내용 입력 → 저장 → 확인이 작업면을 잃지 않고 이어진다.
- 관찰 가능한 성공 조건:
  - G1: 두 뷰포트 모두 본문 작업면이 위쪽 절반 안에서 시작한다.
  - G2: 내용 있는 문서의 실제 검사 절차와 빈 문서의 입력 필드가 첫 화면에 보인다.
  - G3: 저장·저장 상태·미리보기를 찾을 수 있다.
  - G4: 모든 승인 기능의 접근 위치가 있고 모바일에서 같은 기능이 사라지지 않는다.
  - G5: 저장 실패 안내에서 내용을 보존하고 다시 저장할 다음 행동이 있다.
  - G6: 빈 상태가 별도 온보딩이나 설명 화면을 거치지 않고 입력으로 이어진다.

## Audience and Tasks

- 주요 사용자와 사용 상황: 편집 권한을 가진 운영 담당자 한 역할. 사무실 데스크톱에서 매뉴얼을 고치고 폰에서 짧은 문구를 수정한다.
- 최우선 과업: 제목·본문 수정 → 저장 → 저장됨 확인 → 미리보기.
- 시작 조건과 완료 조건: 문서가 열림 또는 새 문서가 비어 있음 → 변경 내용이 입력되고 저장 결과가 확인됨.
- 주요 불안·마찰·실패 가능성: 저장 여부·편집 맥락 상실, 좁은 폭의 다중 도구, 저장 실패 후 내용 손실.

## Header and Navigation

- 브랜드·현재 위치·전역 이동·주 행동의 순서: 앱 탐색은 좌측, 문서 제목·저장 상태·저장은 한 헤더. 별도 홍보 문구 없음.

## Section Order

1. 앱 탐색: 다른 문서·폴더의 문맥을 현재 편집과 분리한다.
2. 문서 헤더: 편집 대상 제목과 저장 상태·저장을 확인한다.
3. 본문 도구 모음: 영향을 주는 본문 바로 앞에 서식·검색·미리보기를 둔다.
4. 본문 작업면: 가장 큰 면적에 실제 매뉴얼 또는 첫 입력을 둔다.
5. 하단 문서 정보·확대: 읽기에 필요할 때 펼친다.

## CTA Strategy

- Primary: “저장” — 문서 헤더에 한 번, 입력 내용을 저장하는 상태로 전환.
- Secondary: “미리보기” — 본문 도구 모음에 한 번, 같은 작업면의 미리보기 상태. 돌아오는 행동은 “편집으로 돌아가기”.
- 빈 상태: 별도 생성 CTA를 더하지 않고 제목·본문 입력과 같은 “저장” 사용.
- 반복 규칙: 복구 시 저장 실패 상태에 “다시 저장”을 사용하고 헤더 저장과 의미가 중복되지 않게 동일한 저장 처리로 연결.
- 완료·실패 피드백: 저장 중은 상태 문구, 완료는 “모든 변경사항 저장됨”, 실패는 내용 보존 안내와 다시 저장.

## Trust Strategy

- 사용자가 불안을 느끼는 지점: 입력 후 저장과 이동 직전.
- 그 직전에 제시할 근거: 헤더의 명시적인 저장 상태. 실패 시 “입력 내용은 이 화면에 남아 있습니다.”
- 출처·날짜·검증 가능성: 상태 문구는 PRODUCT.md와 상태 설계 초안, 2026-11-15. 실제 서버 검증 NOT RUN.
- 근거가 없을 때 생략할 요소: 협업 인원·저장 시각·버전 수·성공률·보안 배지.

- 기준 뷰포트: 1280×800.
- 첫 뷰포트: 208px 탐색 옆 문서 영역 1072px. 헤더 72px + 도구 52px = 상단 124px. 캔버스는 y=124에서 시작, 종이는 y=148에서 시작한다.

- 치수는 CSS 설계값이며 스크린샷 관찰은 메인 확인 대기.

## Prompt Contract

GOAL — 문서 편집과 새 문서 첫 입력을 방해 없이 시작한다.
AUDIENCE — 데스크톱 우선 운영 담당자, 폰 짧은 수정.
TASK — 제목·본문 수정, 저장 상태 확인, 저장, 미리보기.
FLOW — 내용 있음 또는 빈 문서 → 입력 → 저장 중 → 저장 완료; 실패 → 입력 유지 → 다시 저장.
HEADER — 제목·저장 상태·저장만 기본, 앱 탐색 분리.
MESSAGE — 제목과 실제 매뉴얼 본문, 설명 문단 없음.
FACTS — Scenario Facts와 PRODUCT.md 샘플만 사용.
CONTENT_INTEGRITY — 모든 문서 내용·저장 상태는 prototype.
SECTION_ORDER — 앱 탐색 / 문서 헤더 / 본문 도구 / 본문 / 하단 정보·확대.
CTA — 저장 한 개, 보조 미리보기, 실패 시 다시 저장.
TRUST — 내용 보존 안내와 저장 상태, 근거 없는 시각·협업 수 없음.
ASSETS — 로컬 HTML/CSS와 시스템 폰트만 사용.
LAYOUT — 문서 작업면을 먼저 확보, 208px 탐색과 나머지 본문.
RESPONSIVE — 탐색·서식·검색을 접고 본문 폭 보존, 390×844.
STATES — loading/empty/editing/saving/error/success/permission/stale/preview.
PERFORMANCE — 외부 요청·장식 효과·패키지 0.
ACCESSIBILITY — 실제 label·button·details·input·textarea·main, 44px 터치.
PRESERVE — PRODUCT.md의 모든 승인 기능과 DESIGN.md.
EXCLUDE — 마케팅·KPI·AI·실제 협업 서버·인증·결제.
SUCCESS — G1~G6을 메인의 실제 렌더에서 확인. 본 실행은 구조 초안과 정적 확인까지만.

## Interface Compiler

- INTERFACE MODE: 없음 — 단일 문서를 직접 수정하는 편집기. agent 관찰·다중 terminal·데이터 비교가 핵심이 아니다.
- PRIMARY ACTION: 문서 제목·본문 수정, 페이지 행동은 저장.
- INFORMATION ARCHITECTURE: 현재 문서·저장 상태를 유지, 앱 탐색·보조 행동은 접을 수 있다.
- DENSITY: medium, 헤더72/76px, 도구52px, 문서 한 pane.
- STATE MODEL: 위 States와 같다.
- EFFECT BUDGET: 장식 효과0, 상태 모션0, HTML/CSS 기본 단계 A.
