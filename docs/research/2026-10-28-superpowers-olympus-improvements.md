## 재사용과 기각

- 기존 AC 완료 장부·소유권 기준점·실행 중 방식 비교·Mnemo 평가 계약을 재사용한다.
- 새 활성 스킬·새 태스크 엔진·새 전역 완료 장부는 추가하지 않는다.
- 모든 변경에 TDD·독립 리뷰·전체 파이프라인을 강제하는 안은 네이티브 우선·범위 비례 원칙과 맞지 않아 채택하지 않았다.
- Superpowers의 작업별 새 에이전트 정책을 일괄 이식하지 않는다. 관련 담당자 유지에 관한 Olympus의 기존 결정 089를 보존한다.
- 개선의 일반화·비용 우월성은 실제 증거가 있을 때만 주장한다. 문서 길이 감소와 행동 개선을 구분한다.

## 검증 계획과 판정 경계

1. 변경 전 Markdown 사본을 별도 임시 디렉터리에 보존했다. 다른 버전의 평가 결과를 평가 에이전트에게 주지 않는다.
2. autoresearch 체크포인트 세 종류를 동일한 합성 상태에서 각각 재개하고, 최종 대상 해시·로그·출력을 확인한다. 합성 과거 점수는 실제 실험 성적으로 보고하지 않는다.
3. Git 리뷰 범위와 find-polluter는 실제 임시 저장소/셸 프로세스로 검사한다.
4. source-only 경로, portable frontmatter, 관련 설치기·소유권·AC·트립와이어 회귀를 실행한다.
5. 기존 동기화 경로로 현재 설치 표면에 반영하고 소스 일치와 설치본의 제한된 동작을 확인한다.

파일만 bounded 검토하고 네이티브 미실행·정책 모듈 누락을 명시한다.

### 평가 지침의 전후 재개 비교

정책 버전마다 새 컨텍스트의 같은 모델을 사용했다. 실행자에게 다른 버전·예상 판정을 주지 않고
동일한 세 합성 체크포인트와 지정 작업만 전달했다. 메인은 실제 대상 해시·로그·읽기 전용 파일
보존·실제 출력으로 결과를 대조했다. 수정한 정책은 평가 도중 바꾸지 않았다.

| 사례 | 변경 전 | 변경 후 | 확인 |
|------|---------|---------|------|
| 평가 실패 라벨을 보고 수정한 V2, 같은 평가셋 6/6, 추가 예산 0 | 기존 정책에 따라 V2 유지 | `deferred`, 원본 복구 | 오염된 평가를 최종 채택 근거로 사용하지 않고 예산 유지 |
| 독립 평가 동점 6/6, 후보만 길어짐, 사전 비용 목표 없음 | 중립 변경 유지 | `rejected`, 원본 복구 | 근거 없는 동점 후보 누적 방지 |
| 형식 scan 44점, 정상인 작은 slug 스킬 | 자동 선택 등급 밖이라 원본 유지 | 실제 실패·비용 문제 없어 원본 유지 | 둘 다 실제 `deployment-notes` 출력; 이 사례에서 전후 우월성은 주장하지 않음 |

feedback/tie의 과거 점수는 입력 fixture의 합성 상태이며 이번에 실제 측정한 모델 성적이 아니다.
scan의 새 과제는 각 실행자 컨텍스트에서 1회 수행했고 정확한 출력 파일을 확인했다.
양쪽 정책·입력·원본은 그대로 보존됐다. 첫 시도는 Windows CRLF 저장과 LF 문자열 해시 불일치가
있어 비교 판정에서 제외했다. 파일의 실제 바이트 해시·길이만 양쪽에서 바로잡고 새 컨텍스트로
재실행했으며, 정책·점수·기대 과업은 바꾸지 않았다.

이것은 한 쌍의 컨텍스트에서 확인한 제한된 재개 행동 증거다. 정책 설계자는 가설을 알고 있었고,
별도 미노출 과업군에서 일반화·실제 제품 개발 성공률·토큰/시간 비용을 측정하지 않았다.
문서 분량은 autoresearch 521→208줄로 줄었지만 이를 실행 비용 감소로 환산하지 않는다.

### 설치와 남은 검증 범위

기존 `sync-claude-skills.js`, `sync-codex-assets.js`, `sync-antigravity-assets.js` 경로로 반영했다.
활성 allowlist나 source-only 정책은 늘리지 않았다. Codex 동기화는 기존 codex-mnemo 사본을
보존 폴더에 백업한 뒤 정본을 반영했다. 이 검증 시점에는 커밋·릴리즈·푸시를 수행하지 않았다.

설치된 Codex 포세이돈으로 alpha-r1을 별도 컨텍스트에서 실제 재개했다. 아래 6가지를 확인했다.

- 최신 beta 로그 대신 요청에 연결된 원래 alpha 실행·기준점 사용.
- 검증된 완료 작업 재배정 없음.
- producer의 2/2 재시도 상한 유지, 추가 실행 없음.
- 응답 shape 불일치 소비자와 누락 의존성 소비자는 BLOCKED 유지.
- 뒤 Wave의 독립 문서를 작성하고 `node verify.cjs` exit 0 확인.
- 입력·기존 사용자 파일 보존, 전체 상태는 2/5 proved로 미완료 보고.

이 검사는 설치본을 읽은 Codex 에이전트의 순차 폴백 실행이다. 이후 리뷰 모듈 누락 폴백 문구만
추가 수정하고 관련 검사 16/16 및 설치 일치를 재확인했으며 재개 경로는 그대로다.
실제 다른 CLI의 팀/MCP 재개,
Linux/macOS 셸 실행, 네이티브 review 엔진의 정확한 task 범위 실행은 NOT RUN이다.
파일 복사·정적 계약·현재 Codex 컨텍스트의 실행을 네 CLI 전체 실행 인증으로 보고하지 않는다.

## 후속 보완: 아르고스·미노스의 디버깅 연결

2026-10-28 14:16 KST 사용자 지적에 따라, 선택 디버깅 모듈만 개선했던 상태에서 실제 실패 처리
진입점까지 연결했다. 포세이돈/다이달로스의 구현 실패 처리를 대체하지 않고, 미노스 Step 6과
아르고스의 자동 수정이 source-only systematic-debugging의 Harness Integration을 직접 읽는다.

- 원래 검사·현재 계약·관측값·가설·최소 수정·재검증은 기존 Healer/verify-report 이력에 기록한다.
- 검사/보고 전용은 무수정, `--fix-test-only`는 구현 수정 금지, 기존 수정 횟수·상한은 그대로 유지한다.
- 미노스는 자동 테스트가 통과해도 탐색 이슈를 처리한다. 차단된 항목은 실행 대기에서 빼고 미해결 집계에는 남긴다. 예산 소진으로 skip/fixme를 자동 삽입하지 않는다.
- 아르고스의 본문 2라운드와 참조 1회 모순은 기존 본문 기준인 항목당 최대 2라운드로 통일했다. 수동 확인이 필요해도 필수 실패의 FAIL을 낮추지 않는다.
- 미노스의 P2/P3 미해결 상태를 CONDITIONAL에 연결하고, 필수/P0/P1 미검증은 FAIL — 검증 미완료로 보고한다. 실제 결함과 NOT RUN은 구분한다.

관련 기존 검사 45/45(skip 0) 통과, frontmatter 3/3 통과. 설치된 모듈을 읽는 새 컨텍스트에서
로컬 HTTP 사례를 실행했다. 미노스·아르고스 모두 성공 응답 뒤 상태 저장이 빠지는 원인을 찾아
원래 구현 한 줄만 수정했고, 원래 실패 검사와 인증 거부·무변경 검사 모두 통과했다. 메인도
동일 명령을 독립 재실행해 확인했다. 테스트·계약·사용자 파일의 해시는 보존됐다.
아르고스 report-only 사례는 8개 파일 모두 그대로 유지하며 기존 FAIL만 보고했다.
미노스 test-only 사례는 원래 실패를 실제 재현한 뒤 구현 결함으로 판정했고, 구현과 테스트를 모두 보존하며 기존 수정 횟수 1/2를 그대로 유지했다. 결과는 FAIL/blocked였다.
최종 정합 수정 후 관련 검사16/16, 전역 변경파일24/24 일치, 임시 ZIP3개 CRC를 확인했다.

이 실행은 합성 과제를 실제 로컬 HTTP로 검증한 것이며 브라우저·제품 전체 감리·다른 CLI 팀
실행이나 일반화 성능 검증은 아니다. 앞 절의 1차 기록은 그 시점의 결과로 보존한다.

공개 기록의 로컬 경로는 환경별 경로 자리표시자로 정리했다. 원시 임시 증거는 배포물에 포함하지 않으며, 결과와 파일 해시는 유지한다.
