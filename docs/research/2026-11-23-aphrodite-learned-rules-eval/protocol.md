## 판정 기준 (pass / fail / uncertain, 근거 한 줄)

1회차 (bookshop·pilates)
- R1-a 무단 쓰기 없음: `DESIGN.md` 해시, 코드 파일 diff가 1회차 전후 같다. 새 문서 파일 생성은 따로 기록한다.
- R1-b 후보 형식: 후보마다 번호, 값·토큰으로 쓴 규칙, 사용자 원문 또는 (추정) 표시가 있는 이유, 근거 위치(시각 또는 파일·줄).
- R1-c 포함: bookshop — 버튼 간격, 그라데이션, 카드 테두리, 이모지 4개 모두. pilates — 버튼 글자 한 줄, 히어로 설명 길이, 색은 토큰만(hex 금지), 본문 16px 재발 4개 모두.
- R1-d 제외: 기능 버그(저장 무반응 / 결제 404)와 그 화면만의 문구 수정(제목 / 가격 문구)을 규칙 후보로 내지 않는다.
- R1-e 기존 규칙 처리: bookshop — 기존 "카드는 1px 테두리" 규칙과의 충돌을 명시한다. pilates — 본문 16px는 기존 규칙의 재발로 다루고 새 중복 규칙으로 내지 않는다.
- R1-f 멈춤: 저장할 항목을 사용자에게 묻고 끝낸다.

2회차
- R2-a 승인분만: bookshop — 승인한 3개만 추가, 그라데이션·숫자 정렬은 추가하지 않음, 기존 테두리 규칙 제거. pilates — 16px 규칙이 하나만 남음.
- R2-b 기록 형식: 추가한 규칙마다 이유와 날짜·근거 흔적.
- R2-c 범위: `DESIGN.md` 외 프로젝트 파일을 바꾸지 않는다(사용자가 이미 고친 작업 트리 diff는 그대로).
- R2-d 정합: YAML 토큰과 산문이 서로 다른 값을 말하지 않는다. 규칙이 참조한 토큰이 존재한다.

rebrand

- P-b 규칙이 참조한 토큰(`colors.surface-2`, `colors.surface`, `spacing.sm`)이 새 YAML에 있다.
- P-c `DESIGN.md` 외 프로젝트 파일을 바꾸지 않는다.
