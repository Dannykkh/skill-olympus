# Q1 실험 프로토콜 초안 — 기억은 어느 계층에 놓여야 실제로 발동하는가

`version: 0.1 (draft)`
`date: 2026-07-31`
`status: 사전 등록 전 초안 — 확정 시 본 문서의 해시를 기록하여 사전 등록으로 사용`

---

## 1. 연구 질문과 배경

**RQ**: 문서화된 교훈(gotcha)이 라우팅 계층(raw 관찰 → 정제 파일 → 상시 가시 → 작업 현장 내장) 중 어디에 배치되어야, 그 교훈을 명시적으로 언급하지 않는 실제 작업(간접 적용 과제)에서 실제로 적용되는가?

**배경**: InMind(arXiv:2607.24368)는 메모리 시스템들이 직접 회상(84~100%)과 간접 적용(6~16%) 사이에서 붕괴함을 합성 벤치마크로 보였고, "어떤 기억이 상시 가시 상태에 머물 자격이 있는가"라는 라우팅 문제를 미해결로 남겼다. 본 실험은 실사용 18개월 시스템(mnemo/skill-olympus)의 실제 gotcha 코퍼스로 계층별 발동률을 측정하여 이 공백에 답한다. 본 시스템에서 라우팅 실패의 실재는 gotcha 036(기록됐으나 재발)으로 이미 확인되었다.

**결과의 쓸모(어느 쪽이 나와도)**:
- T3/T4에서만 발동 → "정제 파일은 무덤이다, 승격이 전부다" — 승격 기준 연구·컨텍스트 예산 설계로 연결
- T2에서도 충분히 발동 → 상시 가시 예산(100줄 제한 등)을 공격적으로 줄여도 된다는 근거
- 직접/간접 격차가 실환경에서 InMind보다 작다/크다 → 벤치마크 생태 타당성에 대한 증거

## 2. 설계 개요

| 요소 | 값 |
|------|-----|
| 설계 | 계층(5) × 프로브 유형(2) 요인 설계, gotcha를 반복 단위로 하는 혼합 설계 |
| 독립변수 1 | 배치 계층 T0~T4 (아래 3절) |
| 독립변수 2 | 프로브 유형: 직접(P-D) / 간접(P-I) |
| 종속변수(1차) | 함정 회피율 (간접 프로브에서 trap-hit 여부, 이진) |
| 종속변수(2차) | 실패 유형 분해(미조회 vs 조회-미적용), 과제 성공률, 총 토큰, 조회 이벤트 수 |
| 실행 단위 | 격리 샌드박스 프로젝트 + 신규 headless 세션 1회 = 1 run |
| 반복 | 셀당 3회 (파일럿) → 5회 (본실험, 인접 계층 판별용) |

## 3. 조건 (배치 계층)

각 조건은 **샌드박스 프로젝트의 파일 배치만 다르고 나머지는 동일**하다.

| 조건 | 배치 | 조작 방법 |
|------|------|-----------|
| **T0** 부재 | 해당 교훈이 어디에도 없음 | 대조군. 모델의 내재적 회피율 측정 (스크리닝 겸용, 6절) |
| **T1** raw 관찰 | `memory/gotchas/observations.jsonl`에 관찰 1줄만 존재 | 실제 훅이 남기는 형식의 jsonl 라인 삽입 |
| **T2** 정제 파일 | `memory/gotchas/NNN-{slug}.md` + `index.md` 등록 | 실제 gotcha 파일 형식 그대로. CLAUDE.md에는 "작업 시 gotchas/index.md 확인" 일반 지침만 (현행과 동일) |
| **T3** 상시 가시 | 교훈이 프로젝트 `CLAUDE.md`에 규칙 1~3줄로 존재 | 현행 "가드레일 승격"과 동일 형태. T2 파일도 함께 존재(현실 배치 재현) |
| **T4** 작업 현장 내장 | 과제를 처리하는 스킬의 `SKILL.md` 안에 규칙 존재 | 현행 "스킬 내장 승격"과 동일 형태. T2 파일도 함께 존재 |

**T4 설계 결정(미결)**: T4는 과제가 스킬을 경유할 때만 정의된다. 선택지:
- (a) 스킬이 자연 매개되는 gotcha 부분집합에만 T4 arm 적용 (예: 폰트 계열 → design 스킬) — 자연스러움 우선, 셀 불균형 감수
- (b) 과제마다 최소 스텁 스킬(예: `ps-script-writer`)을 만들어 전 gotcha에 T4 균일 적용 — 균일성 우선, 인공성 감수
- **권고**: 파일럿은 (a), 본실험에서 (b) 병행 후 두 결과 비교를 부록으로.

**누적 설계 주의**: T3/T4는 T2를 포함한다(현실의 승격은 파일을 지우지 않음). 따라서 T3-T2 차이는 "상시 가시가 더해진 효과"로 해석한다. 순수 단독 배치 비교가 필요하면 T3', T4' (T2 제거) arm을 부록 실험으로.

## 4. 프로브 설계

gotcha 1건당 프로브 2종을 작성한다. **간접 프로브가 본 실험의 핵심이다.**

### 4.1 직접 프로브 (P-D)
- 형식: "이 프로젝트에서 {키워드} 관련해 주의할 점 있어?"
- 목적: InMind의 저장/회상 성공 재현 확인 (천장 예상). 셀당 1회만 실행해 비용 절약.

### 4.2 간접 프로브 (P-I)
- 형식: **함정이 매복된 실제 작업 지시. 함정·교훈·키워드를 절대 언급하지 않는다.**
- 판정: 산출물에서 함정 발동 여부를 객관 신호로 검사 (자동 체커 우선).

### 4.3 프로브 스펙 시트 (gotcha당 1장, 템플릿)

```markdown
## PROBE-{NNN}
- gotcha: {NNN-slug}
- 매개 스킬(T4): {스킬명 | 스텁 | 해당없음}
- P-D 질문: "..."
- P-I 과제문: "..."   ← 함정 무언급 검증 체크 통과 필수
- trap 정의: {무엇을 하면 함정 발동인가}
- 자동 체커: {파일/바이트/문자열 수준의 객관 검사. 예: 출력 .ps1의 BOM 유무를 바이트로 검사}
- 성공 정의: {과제 자체의 완료 기준 — trap과 독립}
- T0 스크리닝 결과: {사전 실행 후 기입}
```

### 4.4 후보 gotcha 셔틀리스트 (재현 가능 + 객관 판정 가능 기준으로 1차 선별)

| # | gotcha | P-I 과제 예시 | 자동 체커 |
|---|--------|---------------|-----------|
| 012 | powershell-bom-utf8 | "설정 파일을 UTF-8로 저장하는 ps1 작성" | 산출 파일 선두 3바이트 EF BB BF 검사 |
| 013 | join-path-3arg | "PS 5.1 호환으로 세 경로를 조합하는 함수 작성" | `Join-Path`에 인수 3개 패턴 grep + PS5.1 파싱 |

## 5. 실행 절차

### 5.1 샌드박스 재료화
run마다 스크립트가 임시 디렉토리에 프로젝트를 생성한다:
- 공통: 최소 CLAUDE.md(공통 지침), memory/ 뼈대, (T4 시) 스킬 디렉토리
- 조건별: 3절의 배치 차이만 주입
- git init (실환경 재현), 이전 run 잔재 없음 보장

### 5.2 세션 실행
```
claude -p "{프로브 과제문}" --model {고정 모델 스냅샷 ID} [권한 플래그 고정]
```
- **모델 버전 전체 실험 기간 고정** (스냅샷 ID 기록). 중간 업그레이드 금지.
- 세션당 1 run, 재사용 금지 (오염 방지)
- transcript(jsonl)와 산출물 디렉토리 전체 보존
- run 순서는 (gotcha × 조건 × 반복) 전체를 셔플

### 5.3 판정
1. **자동 체커 우선** (4.3의 객관 신호) — 조건 맹검이 구조적으로 보장됨
2. 자동 판정 불가 항목만 LLM 판정자(조건 정보 미제공, 루브릭 고정) + 사람 표본 검증 20%
3. **실패 유형 분해**: transcript에서 조회 이벤트를 파싱하여
   - `NR` (Not Retrieved): gotcha 파일/규칙을 읽지 않고 함정 발동
   - `RNA` (Retrieved, Not Applied): 읽었으나 함정 발동
   - `A` (Applied): 함정 회피 + 근거 흔적
   - `A0` (Innate): 회피했으나 기억 흔적 없음 (내재 지식 회피 — T0 대비로 판별)

## 6. 스크리닝 (핵심 타당성 장치)

**문제**: 모델이 훈련 지식만으로 함정을 회피하면(T0에서 이미 높은 회피율) 해당 gotcha는 계층 효과를 측정할 수 없다.

**절차**: 본실험 전에 전 후보를 T0 × P-I × 5회 실행.
- **채택 기준: T0 함정 발동률 ≥ 60%** (5회 중 3회 이상 함정을 밟음)
- 미달 gotcha는 제외하고 사유와 함께 부록 기록 (선택 편향 방지 위해 제외 목록 공개)

---

## 7. 가설 (사전 등록 대상)

- **H1**: 간접 적용률은 T0 ≈ T1 < T2 < T3 ≤ T4 (단조 증가, T1은 T0과 무차이)
- **H2**: 직접 회상은 T2 이상에서 천장(≥90%) — InMind의 저장/회상 성공 재현
- **H3**: T2 실패는 주로 `NR`(미조회), T3/T4 실패는 주로 `RNA`(조회-미적용) — 실패 병목이 계층에 따라 검색→적용으로 이동
- **H4**: 토큰 비용 — T3는 과제 무관 상수 비용, T4는 스킬 발동 시에만 비용. 회피 1건당 토큰 효율은 T4 > T3
- 방향이 반대로 나오는 경우도 보고한다 (특히 T2가 T3와 무차이면 승격 무용론의 증거)

## 8. 표본 크기와 비용

| 단계 | 구성 | run 수 |
|------|------|--------|
| 스크리닝 | 후보 20 × T0 × 5회 (P-I) | 100 |
| 파일럿 | 채택 5 × 5계층 × 3회 (P-I) + 5 × 5 × 1회 (P-D) | 100 |
| 본실험 | 채택 12~15 × 5계층 × 5회 (P-I) + 동일 × 1회 (P-D) | 375~450 |

- run당 토큰 추정 20~60k (과제 복잡도별) → 본실험 총 10~25M 토큰. **파일럿 결과로 재추정 후 진행 판단.**
- 분석: 혼합효과 로지스틱 회귀 `회피 ~ 계층 + (1|gotcha)`, 인접 계층 쌍대비교(Holm 보정), Wilson 95% CI 보고. 셀당 5회 × 12 gotcha면 인접 계층 30%p 차이 판별이 현실적 목표 (정밀 검정력 계산은 파일럿 분산으로).

## 9. 타당성 위협과 대응

| 위협 | 대응 |
|------|------|
| 모델이 gotcha 내용을 훈련에서 학습 | T0 스크리닝으로 내재 회피 gotcha 제외 (6절) |
| N=1 시스템 | 주장 범위를 "이 설계 계열의 시스템"으로 한정. gotcha 12~15건이 시스템 내 반복 단위 |
| 자기 연구 편향 | 자동 체커 우선, 판정 맹검, 프로토콜 사전 등록(본 문서 해시), 제외 목록 공개 |
| 프로브 문구가 힌트 누설 | P-I 작성 후 독립 세션에 "이 과제문에서 연상되는 주의사항?"을 물어 키워드 누설 검사 |
| T3 컨텍스트 길이 자체의 효과 | T3 arm에 동일 길이의 무관 규칙을 넣은 placebo arm (T3-p) 을 파일럿에 포함해 길이 효과 분리 |
| 헤드리스와 대화형의 행동 차이 | 한계로 명시. 표본 일부(10%)를 대화형으로 반복해 방향 일치 확인 |

## 10. 산출물과 일정

| 산출물 | 내용 |
|--------|------|
| 프로브셋 공개 | 스펙 시트 + 샌드박스 재료 + 자동 체커 (아티팩트 기여 — 본 실험의 최대 인용 자산) |
| 데이터 | run별 transcript 해시, 판정, 토큰. 공개 전 secret 스크럽 |
| 보고 | 계층별 회피율 곡선 + 실패 유형 분해 + 비용 곡선 |

일정(제안): 1주 프로브셋 작성 → 1주 스크리닝+파일럿 → 진행 판단 게이트 → 2주 본실험+분석 → 프리프린트/워크숍 제출.

## 11. 미결 사항 (확정 전 결정 필요)

1. T4 설계: 자연 매개(a) vs 스텁 스킬(b) — 3절
2. 모델 스냅샷 선택과 고정 기간
3. 헤드리스 권한 플래그 표준 구성
4. placebo arm(T3-p) 파일럿 포함 여부
5. 사전 등록 방식: OSF vs 본 문서 커밋 해시
